# Jarvis AI 助手模组开发计划（纯客户端版）

## 1. 项目分析

通过对当前仓库的分析，我们可以看到这是一个基于 NeoForge 框架的 Minecraft 1.21.1 模组开发模板。仓库中已经存在一个基础的 `Jarvis` 类，位于 `com.rheinmetal.jarvis` 包中。

### 现有项目结构

```
├── src/
│   ├── main/
│   │   ├── java/
│   │   │   ├── com/example/examplemod/  # 示例模组代码
│   │   │   └── com/rheinmetal/jarvis/    # Jarvis 模组代码
│   │   ├── resources/                    # 资源文件
│   │   └── templates/                    # 模板文件
├── build.gradle                         # Gradle 构建脚本
├── gradle.properties                    # 项目配置参数
└── README.md                            # 项目说明
```

### 技术栈

- Java 21（Minecraft 1.21.1 要求）
- NeoForge 框架（版本 21.1.224）
- Gradle 构建系统
- 本地推理服务（whisper.cpp、llama.cpp、TTS 后端）

## 2. 核心功能需求

### 2.1 功能概述

创建一个纯客户端的 Jarvis AI 助手模组，包含以下核心功能：

1. **ASR（自动语音识别）**：使用 whisper.cpp 进行本地语音识别
2. **LLM（大语言模型）**：使用 llama.cpp 进行本地文本生成
3. **TTS（语音合成）**：使用本地 TTS 后端进行语音合成
4. **内存级微内核与进程守护架构**：管理本地推理服务
5. **AiOrchestrator 状态机**：管理数据流和状态
6. **显存分档预设系统**：根据玩家显卡显存动态分配模型
7. **流式接力管道**：实现低延迟的语音交互

### 2.2 技术要求

- **禁止云端依赖**：所有推理必须在本地完成
- **禁止 Python 运行时**：使用预编译的单文件二进制程序
- **禁止阻塞主线程**：所有 AI 相关操作必须在后台线程执行
- **流式处理**：实现基于短句边界的流式接力，确保低延迟
- **纯客户端**：模组仅在客户端运行，无需服务端支持

## 3. 项目架构设计

### 3.1 核心模块

1. **Jarvis 主类**：模组入口点，负责初始化和注册
2. **AiOrchestrator**：核心调度器，管理状态机和数据流
3. **ProcessManager**：进程管理器，负责启动和监控本地推理服务
4. **AudioManager**：音频管理器，处理录音和播放
5. **ModelManager**：模型管理器，根据显存分档选择合适的模型
6. **Config**：配置管理，包含显存分档预设系统
7. **NetworkClient**：网络客户端，与本地推理服务通信
8. **JarvisClient**：客户端特定逻辑处理

### 3.2 状态机设计

```
IDLE → LISTENING → PROCESSING → THINKING → SPEAKING → IDLE
                      ↑                ↑           |
                      |                |           |
                      +----------------+-----------+
                              (玩家打断)
```

- **IDLE**：空闲状态
- **LISTENING**：监听玩家语音
- **PROCESSING**：处理语音数据
- **THINKING**：LLM 生成回复
- **SPEAKING**：播放 TTS 语音

### 3.3 数据流设计

1. **语音输入**：玩家按住语音按键录音
2. **ASR 处理**：将录音发送给 whisper.cpp 进行识别
3. **LLM 生成**：将识别结果发送给 llama.cpp 生成回复
4. **TTS 合成**：将 LLM 生成的文本发送给 TTS 服务进行合成
5. **语音输出**：播放合成的语音

### 3.4 显存分档系统

| 档位 | 显存要求 | 推荐模型 |
|------|---------|----------|
| 轻量引擎 | 4GB 显存 / 核显 | 小尺寸模型 |
| 标准引擎 | 6GB - 8GB 显存 | 中等尺寸模型 |
| 豪华引擎 | 12GB+ 显存 | 大尺寸模型 |
| 自定义 | 自定义配置 | 用户指定模型 |

## 4. 实现步骤

### 4.1 项目准备

1. **更新项目配置**：
   - 修改 `gradle.properties` 中的模组信息
   - 配置构建脚本以支持额外的依赖

2. **创建核心目录结构**：
   - `com.rheinmetal.jarvis.core`：核心功能
   - `com.rheinmetal.jarvis.network`：网络通信
   - `com.rheinmetal.jarvis.audio`：音频处理
   - `com.rheinmetal.jarvis.config`：配置管理
   - `com.rheinmetal.jarvis.model`：模型管理

### 4.2 核心组件实现

1. **Config 类**：
   - 实现显存分档预设系统
   - 配置本地服务路径和端口

2. **ProcessManager 类**：
   - 使用 ProcessBuilder 启动本地推理服务
   - 实现服务健康检查和端口占用检测

3. **AiOrchestrator 类**：
   - 实现状态机逻辑
   - 管理数据流和任务调度
   - 实现防 OOM 互斥原则和玩家绝对优先原则

4. **AudioManager 类**：
   - 实现录音功能
   - 实现音频播放功能
   - 处理音频流的拼接和缓冲

5. **NetworkClient 类**：
   - 实现与 ASR 服务的 HTTP 通信
   - 实现与 LLM 服务的 HTTP + SSE 通信
   - 实现与 TTS 服务的 WebSocket 通信

6. **ModelManager 类**：
   - 根据显存分档选择合适的模型
   - 管理模型的下载和加载

### 4.3 客户端集成

1. **Jarvis 主类**：
   - 初始化核心组件
   - 注册事件监听器
   - 设置键位绑定

2. **JarvisClient 类**：
   - 使用 `@Mod(value = MODID, dist = Dist.CLIENT)` 注解标记
   - 实现客户端特定逻辑
   - 处理游戏内 UI 界面
   - 处理玩家输入
   - 显示状态信息

### 4.4 测试与优化

1. **功能测试**：
   - 测试语音识别功能
   - 测试 LLM 生成功能
   - 测试 TTS 合成功能
   - 测试流式处理性能

2. **性能优化**：
   - 优化线程管理
   - 优化内存使用
   - 优化网络通信

3. **兼容性测试**：
   - 测试不同显存配置
   - 测试不同操作系统
   - 测试与其他模组的兼容性

## 6. 风险与应对策略

### 6.1 技术风险

1. **本地服务启动失败**：
   - 应对策略：实现服务启动重试机制，提供详细的错误信息

2. **显存不足**：
   - 应对策略：实现显存检测，自动降级到合适的模型档位

3. **音频处理延迟**：
   - 应对策略：优化音频处理流程，使用缓冲区减少延迟

4. **线程安全问题**：
   - 应对策略：使用线程安全的数据结构，实现适当的同步机制

### 6.2 用户体验风险

1. **响应延迟**：
   - 应对策略：实现流式处理，减少等待时间

2. **语音识别准确率**：
   - 应对策略：选择合适的 ASR 模型，提供语音识别反馈

3. **模型下载大小**：
   - 应对策略：提供模型分档选择，允许用户根据网络情况选择合适的模型

1. **多线程架构**：使用线程池管理后台任务，避免阻塞主线程
2. **流式处理**：实现基于短句边界的流式接力，减少延迟
3. **进程管理**：通过 ProcessBuilder 启动和监控本地服务
4. **状态机设计**：实现灵活的状态管理，支持玩家打断
5. **显存管理**：根据显存分档选择合适的模型，避免 OOM
6. **网络通信**：实现与本地服务的高效通信，支持 HTTP、SSE 和 WebSocket
7. **客户端特定逻辑**：使用 `@Mod(value = MODID, dist = Dist.CLIENT)` 注解确保仅在客户端运行
