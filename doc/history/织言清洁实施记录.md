# 织言清洁实施记录

> 实施日期：2026-11-03。范围：`tianshu-weaving` 与它对辅星协议面的连带适配。
> 本文只记录"改了什么、为什么这么定"，接口语义以 [LLM 接口设计](../function/weaving/LLM接口设计.md) 为准。

## 1. 目标

把织言从"本地引擎时代的双通道推理模块"收敛成**云端推理传输 + 向量/RAG 数据面**：调用方给成品消息，织言发出去、收回来；提示词组装、上下文管理、工具编排归调用方（辅星）。

## 2. 删掉的东西

| 类别 | 删除内容 |
|---|---|
| 协议字段 | `lane`、`taskPriority`、`taskPreemptible`、`InferencePolicyPayload`、`toolsJson`、对话身份 4 字段、`rag` chunk、结果/分片里的 `ragHits` |
| 类型 | `ChunkPayload`、`LlmStatusPayload`、`LLM.STATUS` topic、`LlmTopics`、`LlmTaskAdmissionController`、`LLMRequest`、`Chunk`、`MessageItem`、`LlmRequestPreparer`、`LlmPromptPayloadMapper`、`LlmInferenceOptions`、`LlmRuntimeInspector`、`LlmRagService`、`LlmEmbeddingServiceAdapter`、4 个 `LlmMtp*`、`LlmEngineCapabilitySnapshot`、`LlmContextBudgetSnapshot`、`LlmRagPathResolver/Resolution` |
| 配置/UI | 全局 `contextTier` 键、准入队列配置、设置页“推理通道”行、4 条语言键 |
| 模型清单 | 采样 8 字段 → 4 字段；无读端的 `series` / `description*` / `thinkingCapability` / `estimatedVramBytes` / `promptTokenBudget` |

## 3. 保下来的东西及理由

- **tier**：100K/200K/500K 是云端模型的上下文容量，保留 `WeavingContextTiers` 作为定义与校验下限；预算来源改为模型条目声明的容量，不再有第二个全局档。
- **token 用量**：厂家返回的 usage 始终是权威数据（输入/输出/thinking/缓存命中拆分），照旧进账本与计价；`TOKEN_COUNT` 原语保留为发送前估算，并用真实 usage 校准。
- **`LLM.CACHE_MANAGE`**：RAG 库的注册、写入、检索、内联检索全部保留；删掉的只是 `LLM.REQUEST` 里的自动注入。
- **`LLM.PRIMITIVE_QUERY`**：`TOKEN_COUNT` / `EMBED` / `STATUS` 保留，快照瘦身为 9 个字段。

## 4. 两个真 bug

1. `EMBED` 原语原先包在远程客户端上，必然抛 `REMOTE_LLM_EMBEDDING_UNAVAILABLE`，而快照又报 embedding 可用。现在 RAG、EMBED、快照共用一个 `EmbeddingRuntime`。
2. 运行时把全局默认 100K 当预算、忽略模型声明的容量。现在预算 = 模型容量 − 输出保留 − headroom，公式在 `LlmContextBudget`。

## 5. 辅星侧的连带改动

- 请求种类不再是一个枚举：`AXLlmClient.submitInTurn(parent, …)` 的期限取回合信封，`submitDetached(payload, handler, timeout)` 由调用方给期限；`PendingRequest` 只记 `expireAt`。
- `RequestKind`、`lane`、`cancelChatRequests` 删除；重投诊断属性由 `lane` 改为 `turnOwned`。
- 压缩与委派各自传自己的期限（压缩 120s，委派用本步剩余预算）。
- 辅星 9 个测试文件同步重写/适配。

## 7. 有意留到以后

- 设置页把 tier 做成可见的容量选择（当前模型条目声明 + 常量定义，已可用，只是没有选择控件）。
- libs 接口文档保持原样：libs 是独立底层模组，其文档描述的是它自己的客观接口，不随织言用法改写。

## 8. 后续增量：推理档位

请求字段是 `reasoningTier`（序号）。每个模型有一条从 0 开始的有序档位表：`0` 是非思考档（模型支持时），其余是提供商官方的档位名；表长和名称是数据，织言不写死 `low/medium/high`，也不做名称间的别名折叠。

- `null` 表示“用该模型的默认档”，并把它显式编码出去——端点自己的默认通常是高档，不能靠“不发字段”来表达 low；
- `DEEPSEEK_THINKING`：tier 0 发 `thinking.type=disabled`；其余发 `thinking.type=enabled` + `reasoning_effort=<该档官方名称>`；
- `OPENAI_EFFORT`：直接发 `reasoning_effort=<该档官方名称>`，没有非思考槽时第一档就是最低档；
- `NONE`：不发送；
- `LLM.PRIMITIVE_QUERY`（`queryType=STATUS`）暴露 `reasoningTierCount` / `reasoningIncludesNoThinking` / `reasoningDefaultTier` / `reasoningLevels`，调用方只按序号选。

DeepSeek 梯子 `[非思考, low, high, max]`，默认 tier 1（low）。

辅星默认（开关就是现有的“允许以思考时间换取回复质量”）：

| 开关 | 对话 | 记忆压缩 |
|---|---|---|
| 关 | tier 0 | tier 1 |
| 开 | tier 1 | tier 2 |

委派固定 tier 2。越界档位夹到最近档，模型切换不会让旧序号直接报错。

织言**不做模型预设**：模型迭代快，预设表很快过期。内置提供商的梯子是 profile 数据；自定义提供商在设置页自己声明。

## 9. 设置页：容量与档位

自定义 API 模式的表单新增两组字段，均只在该模式出现（内置提供商由 profile 完整定义）：

- **上下文容量**：下拉选择 50K / 100K / 200K / 500K，写入“当前使用的模型”的声明容量；已有非档位数值（例如旧配置的 8192）会作为额外一项列出，不会在打开表单时被静默改写。容量下限仍统一在保存校验里检查。
- **推理档位**：三件事——线协议（不控制 / OpenAI 风格 / DeepSeek 思考模式）、第 0 档是否为非思考、档位名称（官方名称，逗号分隔，由低到高）。表单里填出的梯子与提供商 profile 一致时不写覆盖；不同才存成该条目的覆盖值，删除条目会一并清掉。

存储：梯子与凭据一样放在独立键 `reasoningProfiles`（`entryId=编码`），不进模型列表；编码形式为 `wire;noThinking;levels;defaultTier`，解析失败视为“无覆盖”，不抛错。读取顺序：条目覆盖 → 提供商 profile → 无控制。

未做：默认档位仍取 profile 的值（DeepSeek 为 1=low）；自定义梯子的默认档固定为 0（最低档），表单不暴露该字段。

## 10. 错误处理审查

复审时按“每条失败路径最后落到哪个状态”过了一遍 `catch`，改了 6 处、删了 2 处死代码：

- **取消按类型判定**：`LLMService` 之前把所有异常包成 `RuntimeException`，取消因此丢了类型，请求处理器只能靠“消息里是否含 cancel”猜。现在 `CancellationException` 原样上抛，`isCancellation` 只看类型；流的失败从 `ExecutionException` 里解包后再判定。
- **中断会真正中止请求**：`future.get()` 被中断时只抛 `InterruptedException`，底层 HTTP 读者线程会一直跑到超时。现在中断先 `cancel(true)`（传输层把取消接到响应体上），再恢复中断标志并抛 `CancellationException`。
- **校验失败带自己的码**：新增 `LlmRequestRejectedException`，空请求 `LLM_EMPTY_REQUEST`、空消息 `LLM_EMPTY_MESSAGES` 直接作为 `errorCode` 上报，不再统一变成 `LLM_REQUEST_FAILED`。
- **启动异常有终点**：`startRemoteRuntime` 抛出的异常现在会被接住，清掉加载提示、把生成能力标失败、保留存储能力、进入重试；创建出来但没交出去的客户端会先 `shutdown()`。
- **向量引擎失败不拖垮聊天**：`LlmEngineProvider.startEmbeddingOnly()` 不再向外抛，内部转成 `UNAVAILABLE` 报告，聊天照常可用。
- **后台清理不外溢**：模型下载的启动清理与可用性刷新各自兜底，一个失败不影响另一个。
- 删除：`LlmPresenceActivityBridge.Kind.PROCESSING_TASK`（重构后从未发布）、`LLMPromptResultPayload.SUCCESS_EMPTY`（全仓零引用）。
- 有意保留：RAG 查询取向量失败时静默退化为纯词法检索——这是检索的降级策略，不是吞异常；写入失败仍以 `RAG_WRITE_FAILED` / `EMBEDDING_NOT_READY` 返回调用方。

## 11. 资源与并发审查

按“谁分配、谁释放；异常时是否也释放”过了一遍持有资源的地方：

- **HTTP 客户端复用**：推理、余额、模型目录原来各建一个 `HttpClient`，推理客户端每次启动（含每次重试）还会再建一个，而中性模块按 Java 17 编译、`HttpClient` 没有 `close()`，于是每个会话都留下选择器线程与连接池。现在三者共用 `LlmHttpTransport` 的进程级客户端；超时仍按请求设置，行为不变。
- **卡住的流有截止时间**：`HttpRequest.timeout` 只覆盖响应头，不覆盖流内的字节。新增 `LlmTimeoutScheduler`，模块用协议的 scheduled lane 给每个请求挂一个截止任务，超时关闭响应体并按 `REMOTE_LLM_STREAM_TIMEOUT` 报失败；请求结束时撤销该任务，不额外占线程。
- **检索原语的两个开关独立**：`includeVector` 与 `includeEmbeddingDetails` 之前被 AND 在一起，只想要向量的一方拿不到向量；现在各自控制向量与模型/命名空间，`dimension` 总是返回。
- **RAG 文件名不再碰撞**：文件名只保留 `[a-zA-Z0-9._-]`，`mod:a` 与 `mod_a` 会落到同一个 `.bin`，后写的库覆盖前一个。现在文件名 = 可读部分 + uid 摘要；旧的短名文件读一次后迁移到新名并删除。
- **manifest 原子写**：先写 `manifest.txt.tmp` 再移动，避免崩溃时留下截断的清单——它是“哪些库存在”的唯一索引。
- **启动失败释放原生加载认领**：进世界时 `claimPrimary()` 认领一次，配置缺失导致云端起不来时没有任何路径结算它，听澜/回响的语音模型会永远排在检索后面。现在启动前失败会 `abandonQueuedLoad()`；若重试真的加载了向量引擎，`startEmbeddingOnly()` 会重新认领。
- **损坏文件先关闭再删除**：`loadStore` 原来在 try-with-resources 内删除文件，Windows 上删不掉，于是每个会话都重读同一个坏文件。现在读完/关闭后再清理。
- 未处理（记录在案）：`VectorStore.upsert` 用线性查找 entryId，导入大库是 O(n²)；`LlmProtocolAdapter` 派发请求的 broker 任务不可中断，取消一个进行中的请求不会中断处理器线程（有截止任务兜底后影响有限）。

## 12. 设置页：向量模型改为可选

向量模型从“页面的前提”变成“页面里的一块”，云端配置不再等它：

- **解绑**：删掉 `columns` 上的 `embeddingReady` 可见性门，以及 `validate()` 里“未下载向量模型就拒绝云端配置”的分支。向量模型没下载时，提供商卡片、添加、编辑器、用量都照常可用；只有检索、`EMBED` 与依赖检索的模组不可用。
- **布局**：页面顶层只剩开关与两栏；向量模型区块成为左栏第一项，下面是提供商卡片、添加按钮、编辑器，右栏仍是用量。
- **说明**：向量模型区块的提示行随状态切换——已下载时提示显卡风险，未下载时说明“可选：云端对话可用；向量检索与依赖它的模组（如辅星）需下载后才可用”，并删掉不再使用的 `validation.embedding_missing` 文案。
- **关闭联动**：之前只有向量模型区块跟随开关置灰，下面的云端面板仍可点击。现在提供商列表、添加按钮（自身还要求表单未打开）、编辑器与用量刷新都由 `enabled` 驱动，关掉模块后整页只剩开关可点。
- 测试：页面只剩两行、左栏顺序、未下载仍可配置并保存、关闭后各区块均禁用；旧的“未下载就隐藏两栏”用例删除。
