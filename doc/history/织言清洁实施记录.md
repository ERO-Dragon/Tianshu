# 织言清洁实施记录

> 实施日期：2026-11-03。范围：`tianshu-weaving` 与它对辅星协议面的连带适配。
> 本文只记录"改了什么、为什么这么定"，接口语义以 [LLM 接口设计](../function/weaving/LLM接口设计.md) 为准。

## 1. 目标

把织言从"本地引擎时代的双通道推理模块"收敛成**云端推理传输 + 向量/RAG 数据面**：调用方给成品消息，织言发出去、收回来；提示词组装、上下文管理、工具编排归调用方（辅星）。

## 2. 删掉的东西

| 类别 | 删除内容 |
|---|---|
| 协议字段 | `lane`、`taskPriority`、`taskPreemptible`、`InferencePolicyPayload`、`toolsJson`、对话身份 4 字段、`rag` chunk、结果/分片里的 `ragHits` |
| 类型 | `ChunkPayload`、`LlmStatusPayload`、`LLM.STATUS` topic、`LlmTopics`、`LlmTaskAdmissionController`、`LLMRequest`、`Chunk`、`MessageItem`、`LlmRequestPreparer`、`LlmPromptPayloadMapper`、`LlmInferenceOptions`、`LlmRuntimeInspector`、`LlmRagService`、`LlmEmbeddingServiceAdapter`、4 个 `LlmMtp*`、`LlmEngineCapabilitySnapshot`、`LlmContextBudgetSnapshot`、`LlmRagPathResolver/Resolution` |
| 配置/UI | 全局 `contextTier` 键、准入队列配置、设置页“推理通道”行、4 条语言键 |
| 模型清单 | 采样 8 字段 → 4 字段；无读端的 `series` / `description*` / `thinkingCapability` / `estimatedVramBytes` / `promptTokenBudget` |

## 3. 保下来的东西及理由

- **tier**：100K/200K/500K 是云端模型的上下文容量，保留 `WeavingContextTiers` 作为定义与校验下限；预算来源改为模型条目声明的容量，不再有第二个全局档。
- **token 用量**：厂家返回的 usage 始终是权威数据（输入/输出/thinking/缓存命中拆分），照旧进账本与计价；`TOKEN_COUNT` 原语保留为发送前估算，并用真实 usage 校准。
- **`LLM.CACHE_MANAGE`**：RAG 库的注册、写入、检索、内联检索全部保留；删掉的只是 `LLM.REQUEST` 里的自动注入。
- **`LLM.PRIMITIVE_QUERY`**：`TOKEN_COUNT` / `EMBED` / `STATUS` 保留，快照瘦身为 9 个字段。

## 4. 两个真 bug

1. `EMBED` 原语原先包在远程客户端上，必然抛 `REMOTE_LLM_EMBEDDING_UNAVAILABLE`，而快照又报 embedding 可用。现在 RAG、EMBED、快照共用一个 `EmbeddingRuntime`。
2. 运行时把全局默认 100K 当预算、忽略模型声明的容量。现在预算 = 模型容量 − 输出保留 − headroom，公式在 `LlmContextBudget`。

## 5. 辅星侧的连带改动

- 请求种类不再是一个枚举：`AXLlmClient.submitInTurn(parent, …)` 的期限取回合信封，`submitDetached(payload, handler, timeout)` 由调用方给期限；`PendingRequest` 只记 `expireAt`。
- `RequestKind`、`lane`、`cancelChatRequests` 删除；重投诊断属性由 `lane` 改为 `turnOwned`。
- 压缩与委派各自传自己的期限（压缩 120s，委派用本步剩余预算）。
- 辅星 9 个测试文件同步重写/适配。

## 7. 有意留到以后

- 设置页把 tier 做成可见的容量选择（当前模型条目声明 + 常量定义，已可用，只是没有选择控件）。
- libs 接口文档保持原样：libs 是独立底层模组，其文档描述的是它自己的客观接口，不随织言用法改写。

## 8. 后续增量：推理档位

请求字段是 `reasoningTier`（序号）。每个模型有一条从 0 开始的有序档位表：`0` 是非思考档（模型支持时），其余是提供商官方的档位名；表长和名称是数据，织言不写死 `low/medium/high`，也不做名称间的别名折叠。

- `null` 表示“用该模型的默认档”，并把它显式编码出去——端点自己的默认通常是高档，不能靠“不发字段”来表达 low；
- `DEEPSEEK_THINKING`：tier 0 发 `thinking.type=disabled`；其余发 `thinking.type=enabled` + `reasoning_effort=<该档官方名称>`；
- `OPENAI_EFFORT`：直接发 `reasoning_effort=<该档官方名称>`，没有非思考槽时第一档就是最低档；
- `NONE`：不发送；
- `LLM.STATUS` 暴露 `reasoningTierCount` / `reasoningIncludesNoThinking` / `reasoningDefaultTier` / `reasoningLevels`，调用方只按序号选。

DeepSeek 梯子 `[非思考, low, high, max]`，默认 tier 1（low）。

辅星默认（开关就是现有的“允许以思考时间换取回复质量”）：

| 开关 | 对话 | 记忆压缩 |
|---|---|---|
| 关 | tier 0 | tier 1 |
| 开 | tier 1 | tier 2 |

委派固定 tier 2。越界档位夹到最近档，模型切换不会让旧序号直接报错。

织言**不做模型预设**：模型迭代快，预设表很快过期。内置提供商的梯子是 profile 数据；没有档位数据的提供商（例如自定义 API）就是 `reasoningTierCount=0`，调用方据此退回默认行为。设置页目前还没有手填档位的控件，属于后续增量。
