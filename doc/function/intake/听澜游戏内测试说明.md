# 听澜游戏内测试说明

本文是听澜（ASR + IR + IA）在开发客户端里做黑盒测试的操作手册：怎么启动、在哪里看到聊天回显、怎样在新建世界后用测试台的三个参与者分别触发准星、手持物品和唤醒词三种仲裁申请。

## 1. 启动

在 VS Code 的 Gradle 面板里打开 `tianshu-intake`，运行 `runClient`；等价命令行：

```text
gradlew.bat :tianshu-intake:runClient
```

开发运行会自动安装：

- **天枢**（内核）
- **映迹**（presence，听澜的必需伙伴）
- **听澜**
- **lab**（测试台，dev-only，不参与产品打包）

四个模组全部来自开发源码集，构建档位是 Debug。进入主菜单后**新建世界**即可（不需要 quickPlay）。要退回到只装内核/其它组合时，用 `-PfeatureMods=...` 显式覆盖。

## 2. 调试开关与聊天回显

Debug 构建里调试开关默认打开（`config/tianshu-client.toml` 的 `debug.enabled`，可在天枢设置右下角切换）；Release 构建无论配置写什么都关闭，聊天栏不会出现调试行。

聊天回显按链路顺序出现（文案在 `tianshu-intake/src/main/lang/` 的 `tianshu.chat.progress.*` 下，中英各一份）：

| 聊天行 | 来源 | 说明 |
| --- | --- | --- |
| `参与者注册：module.lab/alpha（优先级 30）` | `PARTICIPANT_REGISTERED` | lab 启动时注册 alpha / beta / gamma 各一行 |
| `参与者被拒：module.lab/…（CODE）` | `PARTICIPANT_REGISTER_REJECTED` | 契约校验失败；常见是缺伙伴图标或 route capability 不匹配 |
| `ASR 识别完成：…` | `RECOGNITION_COMPLETE` / `STREAM_RESULT` | 识别原文；注入通路也会发一行 |
| `IR：原文 → 修复文（匹配视图：…）` | `ANALYSIS_PUBLISHED` | 修复后的正文与去填充词的匹配视图 |
| `IR 命中：对象 …；触发 …` | `IR_MATCHES` | 对象 `spoken=registryId`，触发 `module:spoken=registered(kind)`；无命中时不发 |
| `IA 接收：文本；owner=…；claims=…；原因` | `ARBITRATION_ACCEPTED` | claims 是 `module:participant(source,priority)` 列表，能看到谁申请了 |
| `IA 拒绝：文本；claims=…；原因` | `ARBITRATION_REJECTED` | 无参与者时为 `NO_PARTICIPANT`，有参与者但无人中标为 `NO_OWNER` |
| `会话 EVENT（STATE）；owner=…；原因` | `DIALOGUE_SESSION_EVENT` | 开始、认领、owner 变更、释放、拒绝、过期 |
| `投递 → owner；会话 …；轮 …` | `DIALOGUE_DELIVERED` | 投递成功才有 |
| `LAB 投递 → alpha：正文（会话 …）` | 测试台 | 测试台确实收到正文 |

聊天行可能包含正文，这是调试构建的预期；诊断日志仍按原有隐私级别落盘。

## 3. 测试台的三个参与者

设置页“【听澜】仲裁测试台”可以改条件、注册/注销、观察会话。三个参与者各有一个独立的 delivery capability，因此投递与 session control 都能明确到人：

| 参与者 | 申请条件 | 源档 | 默认优先级 | 默认条件 |
| --- | --- | --- | --- | --- |
| `alpha` | 准星命中的实体类型在列表里 | CONTEXT | 30 | 列表留空 = 任意实体（瞄动物即可） |
| `beta` | 手持物品 ID 命中 | CONTEXT | 20 | `minecraft:diamond` |
| `gamma` | 说出的唤醒词命中 | UTTERANCE | 10 | `伽马` / `gamma` |

规则：

- 仲裁先比源档：**CONTEXT > UTTERANCE**。瞄着动物或拿着物品的申请永远压过 gamma 的唤醒词，即使 gamma 的优先级更高。
- 同一源档内再比 priority，所以 alpha（30）压过 beta（20）；把条件改到互不重叠时则各自单独中标。
- `alpha` 的实体列表留空表示“任意准星实体”；要只认某些动物就填 `minecraft:cow,minecraft:pig`。
- `beta` 的物品 ID 留空、或 `gamma` 的唤醒词留空，会导致该参与者不注册（页面状态区会显示原因），避免空条件变成“任意手持物/任意触发词”。
- 改完条件点“注册 / 更新测试参与者”，会先注销再按新条件注册。

## 4. 一条可复现的测试序列

1. 从 `tianshu-intake` 的 `runClient` 进入游戏，新建世界。
2. 看聊天：应出现三行 `参与者注册：module.lab/alpha、beta、gamma`。没有的话去测试台页面看“最近错误”或点“注册 / 更新测试参与者”。
3. **准星测试**：对准一头牛（或任意生物），按 V 说一句任意话（或注入一段文本）。预期 `claims` 里出现 `module.lab:alpha(CONTEXT,30)`，owner 为 `module.lab:alpha`，随后 `投递 → module.lab:alpha`、`LAB 投递 → alpha：…`。
4. **手持测试**：手持钻石，准星移开生物，再说一句。预期 `claims` 里只有 `module.lab:beta(CONTEXT,20)`，owner 为 beta。
5. **同时命中**：手持钻石并对准生物再说一句。预期 claims 同时有 alpha 与 beta 两条，owner 是 alpha（同源档比 priority）。
6. **唤醒词测试**：准星移开、手中不拿钻石，说“伽马，打开箱子”（或注入同样文本）。预期 `claims` 为 `module.lab:gamma(UTTERANCE,10)`，owner 为 gamma。
7. **无申请**：三样都不满足时说一句，预期 `IA 拒绝：…；claims=；NO_OWNER`（有参与者但无人中标）。
8. **手工会话**：关闭“投递后立即释放会话”，投递后点“延长 10 秒”应看到 `CONVERSATION_CLAIMED` 且 `reason=PROCESSING_EXTENDED`；点“释放当前会话”应看到 `CONVERSATION_RELEASED` / `SESSION_FINISHED`。

## 5. 不需要麦克风的文本注入

设置页听澜的“调试（文本注入）”分组可以把一段文本按 `INPUT.ASR_FINAL_TEXT` 的同一路径送进 IR/IA，不打开麦克风、不经过 ASR 引擎、不进入 listening 状态；注入的 turn 带 `inputMode=debug`。它和准星/手持条件可以叠加：只要映迹已经把当前交互摘要推给 IA，注入的仲裁同样会用**最新摘要**（没有语音起点就没有冻结帧），所以“瞄着动物 + 注入一句”也能测出 alpha 的 CONTEXT claim。

听澜页“主设置”里的“设置按键”按钮会打开原版按键绑定界面（天枢分类），改完关闭即回到设置页；只有支持该界面的平台才显示这个按钮。

## 6. 故障排查

- **聊天没有调试行**：不是 Debug 构建，或调试开关被手动关闭。
- **没有参与者注册行**：lab 没被安装（确认是从 `tianshu-intake` 启动的 runClient，或命令里带 `featureMods=...,lab`）；或注册被拒，看“参与者被拒”的 CODE。
- **准星/手持不产生 claim**：确认映迹正在推送交互摘要（进入世界后等一两秒再按 V）；`alpha` 的实体过滤是否写成了别的类型；`beta` 的物品 ID 是否是手持物的注册名而不是显示名。
- **只有 gamma 中标**：说明准星/手持条件没满足，或交互摘要是空的；gamma 只看文本，不看上下文。
- **投递后立刻结束**：自动释放是默认行为，关掉再看租期。
- **麦克风路径**：PTT 仍需可用的录音设备；注入路径不需要，两者是独立入口。
