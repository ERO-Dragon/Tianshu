# 听澜游戏内测试说明

本文是听澜（ASR + IR + IA）在开发客户端里做黑盒测试的操作手册：怎么启动、在哪里打开调试出口、看到的每一行聊天代表链路哪一步、以及怎样在没有麦克风的情况下确定性地走完 IR/IA。

## 1. 启动

```text
gradlew.bat :tianshu-adapter:1.21-1.21.1-neoforge:runClient ^
  "-PfeatureMods=intake,presence,lab" ^
  "-PquickPlayWorld=新的世界" ^
  --configure-on-demand --no-configuration-cache
```

- `featureMods` 显式列出听澜、它必需的 presence，以及测试台 `lab`；测试台不在产品装配里，只有显式要求才会安装。
- `quickPlayWorld` 直接进存档，省掉菜单操作；存档名按本机实际情况改。
- `--configure-on-demand` 是当前 1.20.2-neoforge（NeoGradle 7.1.39）配置期退出的临时规避，不启用时整棵项目树会在 1.20.2 上中止配置。该问题另行统一处理；听澜的测试不依赖它。
- 想先只验证内核/其它模组时，把 `featureMods` 换成对应列表即可；不传则从 adapter 目录启动只装内核。

开发运行默认是 Debug 构建。调试开关在 `config/tianshu-client.toml` 的 `debug.enabled`，本机存档里通常已经打开；没有的话在“天枢设置”右下角把“调试”切到开。调试出口全部依赖这个开关，开关关闭时既没有聊天行也没有注入控件。

## 2. 调试回显

开启调试后，聊天栏会按链路顺序出现听澜自己的诊断行（文案在 `tianshu-intake/src/main/lang/` 的 `tianshu.chat.progress.*` 下，中英各一份）：

| 聊天行 | 来源 | 说明 |
| --- | --- | --- |
| `ASR 识别完成：…` | `RECOGNITION_COMPLETE` / `STREAM_RESULT` | 识别器给出的原文；注入通路也会发一行 |
| `IR：原文 → 修复文（匹配视图：…）` | `ANALYSIS_PUBLISHED` | `repairedText` 与去填充词后的匹配视图 |
| `IR 命中：对象 …；触发 …` | `IR_MATCHES` | 对象是 `spoken=registryId`，触发是 `module:spoken=registered(kind)`；没有命中时不发 |
| `参与者注册：module/participant（优先级 N）` | `PARTICIPANT_REGISTERED` | 测试台或其它 owner 注册成功 |
| `参与者被拒：module/participant（CODE）` | `PARTICIPANT_REGISTER_REJECTED` | 契约校验拒绝，CODE 是具体原因（如缺少伙伴图标） |
| `IA 接收：文本；owner=…；claims=…；原因` | `ARBITRATION_ACCEPTED` | claims 是 `module:participant(source,priority)` 列表 |
| `IA 拒绝：文本；claims=…；原因` | `ARBITRATION_REJECTED` | 没有参与者时原因为 `NO_PARTICIPANT` |
| `会话 EVENT（STATE）；owner=…；原因` | `DIALOGUE_SESSION_EVENT` | 开始、认领、owner 变更、释放、拒绝、过期都从这里出 |
| `投递 → owner；会话 …；轮 …` | `DIALOGUE_DELIVERED` | 只有真正投递成功才有 |
| `LAB 投递 → alpha：正文（会话 …）` | 测试台 | 测试台确实收到了正文 |

同一轮语音最多一行 `ASR`、一行 `IR`、一行 `IR 命中`、一行 `IA`，加上若干会话行与一行投递。聊天行可能包含正文，这是调试构建的预期；诊断日志仍按原有隐私级别落盘。

## 3. 文本注入（不需要麦克风）

1. 打开“天枢设置”→“【听澜】ASR语音识别”。
2. 向下滚动到“调试（文本注入）”分组（只有调试开关打开时才存在）。
3. 在“注入文本”里输入一句话，例如 `阿尔法，帮我找一个钻石`。
4. 点“注入一轮”。

注入走的是 `INPUT.ASR_FINAL_TEXT`，与识别结果完全同一条路：IR 先修复，再发布 `IR.RESULT`，IA 随后仲裁。它不打开麦克风、不加载引擎、也不进入 listening 状态，所以模型没下载、麦克风不可用都不影响这一条测试。注入的 turn `inputMode=debug`，消费方可以据此区分。

## 4. 仲裁测试台

设置页里的“【听澜】仲裁测试台”是一个 dev-only 模组的页面：

- **参与者**：`alpha`（优先级 30，唤醒词 `阿尔法` / `alpha`）和 `beta`（优先级 10，唤醒词 `贝塔` / `beta`）。模块启动时会自动注册；也可以在页面上注销后重新注册。
- **自动释放**：默认开。开时测试台收到投递后立即 `RELEASE`，下一轮不会被上一轮卡住；关闭后页面上的“释放当前会话”“延长 10 秒”才用于手工观察租期与续期。
- **状态区**：参与者是否注册、当前会话、持有者、最近投递正文、最近错误。

参与者是通过公开协议注册的第三方角色，因此它同时验证了外部模组的接入契约（route capability、delivery payload、session control），而不只是 IA 的内部判定。

## 5. 一条可复现的测试序列

1. 启动后看聊天：应当先出现两行 `参与者注册：module.lab/alpha…` 和 `…/beta…`。没有的话去测试台页面点“注册测试参与者”，或看“参与者被拒”的 CODE。
2. 注入 `阿尔法，帮我找一个钻石`。
3. 预期依次出现：
   - `ASR 识别完成：阿尔法，帮我找一个钻石`
   - `IR：…（匹配视图：阿尔法 找一个钻石）`
   - `IR 命中：对象 钻石=minecraft:diamond；触发 module.lab:阿尔法=阿尔法(wake)`
   - `IA 接收：…；owner=module.lab:alpha；claims=module.lab:alpha(UTTERANCE,30)…`
   - `会话 CONVERSATION_SESSION_STARTED…`、`…CLAIMED…`
   - `投递 → module.lab:alpha；会话 …；轮 …`
   - `LAB 投递 → alpha：阿尔法，帮我找一个钻石（会话 …）`
   - 自动释放开时，接着出现 `CONVERSATION_RELEASED` 与 `CONVERSATION_SESSION_FINISHED`。
4. 反向用例：在测试台注销参与者，再注入同一句，预期 `IA 拒绝：…；claims=；NO_PARTICIPANT`。
5. 优先级用例：注入包含两个唤醒词的句子（如 `阿尔法，贝塔，打开箱子`），预期 owner 为优先级更高的 `alpha`，`claims` 里两条都在。
6. 手工会话用例：关闭“自动释放”，注入后停在投递；点“延长 10 秒”应看到 `CONVERSATION_CLAIMED` 且 `reason=PROCESSING_EXTENDED`；点“释放当前会话”应看到 `CONVERSATION_RELEASED` / `SESSION_FINISHED`。

## 6. 故障排查

- **聊天没有任何行**：调试开关没开，或当前不是 debug 构建；没有调试开关时注入分组也不会出现。
- **注入后只有 ASR 行**：IR 没有产出，检查 IR 缓存/关键词表日志；`ASR 识别完成` 由注入通路直接发，不代表 IR 成功。
- **IA 一直 NO_PARTICIPANT**：测试台未注册或注册被拒；先看 `参与者注册/被拒` 行。参与者是 RULES 模式时必须声明伙伴图标，否则契约校验拒绝。
- **投递后立刻结束**：自动释放是默认行为；关掉它再看租期。
- **麦克风路径**：PTT 仍需可用的录音设备；注入路径不需要，两者是独立入口。
