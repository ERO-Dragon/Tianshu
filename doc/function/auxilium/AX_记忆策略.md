# AX 记忆策略

AX 怎么把对话变成长期记忆、怎么在每轮把它检索回来。以当前代码为准：数据结构、字段、默认值都对应实现；设计意图与不变量来自记忆设计文档。

## 1. 定位与不变量

### 1.1 目标

| 序 | 目标 |
|---|---|
| 1 | 保真：长期记忆从**原文**抽取，不从二手摘要再抽一次 |
| 2 | 可回溯：每条记忆能指回它来自哪几轮原文 |
| 3 | 不失真：真实发生过的历史**永不因"相似"被删除** |
| 4 | 模型无关：2B 本地模型与云端模型走同一套流水线，切换只改档位与预算 |
| 5 | 不污染前缀：记忆产物只进尾部注入，不改 system、不改写历史 |

### 1.2 不变量

| ID | 不变量 | 检测信号 |
|---|---|---|
| M1 | **客观事实第一性**：长期记忆是客观事实型原子事件；禁止主观重要性结论、情绪判断、性格推断 | 记忆里出现"玩家性格…"这类跨事件概括 |
| M2 | **真实历史不可篡改**：压缩、摘要、抽取都是 raw 的派生；派生出错只能重放 raw，不得反向修改 raw | 原文被改写或删除 |
| M3 | **不为去重删除真实历史**：两条事件只要溯源轮次不同就是两条事件 | 文本相同即被合并 |
| M4 | **兴趣分只在写入时定一次**：`importance` 由抽取阶段打分并落库；读路径不得改写 | 同一份历史两次检索给出不同 importance |
| M5 | **跨世界隔离**：记忆按世界归属；唯一例外是按玩家 UUID 的偏好 | 世界 A 的记忆出现在世界 B |
| M6 | **注入只在尾部**：检索产物不拼进 system、不进摘要块、不写回历史 | 记忆内容出现在 system |
| M7 | **活跃代次的事件不可检索**：原文还在 prompt 里的那一代，其抽取事件不得同时被召回 | 同一段历史在 prompt 里说两遍 |

## 2. 核心对象

### 2.1 Raw Turn（原文层）

一轮原始对话：角色、内容、时间、世界、IA 会话与轮次 id、token/字符长度、内容哈希、说话人（非二元对话来源）。

角色取值：`user` / `assistant` / `world_event`（事件与第三方话语都落在这里）/ `system`。

原**文只有两种状态**：

| 状态 | 含义 |
|---|---|
| 在窗口 | 会被渲染进 prompt 的历史段 |
| 已归档 | 不在 prompt 里，但仍在 append-only 归档文件中，可回溯 |

在窗口内部再分两个**渲染分区**（不是状态）：

| 分区 | 内容 | 何时离开 |
|---|---|---|
| 压缩窗口 | 已被某个单元摘要覆盖、原文仍在 prompt 里的轮次 | 换代时整体移出（写归档后标记） |
| 保持窗口 | 最近 `KEEP_MAX` 个 token 的逐字原文 | 只在新的轮次把它挤出边界时左移；任何路径都不得缩短它 |

两条硬规则：

1. **归档先成功、再移出窗口**。顺序反了会在崩溃后丢原文。
2. **分区以"一轮"为粒度**：同一轮的提问与其回复永远在同一分区。

### 2.2 压缩单元与代

| 概念 | 含义 |
|---|---|
| 单元 | 一段连续、尚未被任何单元摘要覆盖的对话轮次，按 `UNIT` token 预算从旧到新取 |
| 单元摘要（STM 块） | 一个单元的压缩结果：摘要文本、覆盖的轮次区间与轮数、代次、代内序号、内容哈希、前驱/后继链 |
| 代 | 同一批单元摘要的集合编号。换代 = 代次 +1，旧代整体翻为 `superseded` |

事件轮次不进单元（见《AX_事件系统》§10）。

### 2.3 摘要块（进 prompt 的部分）

| 字段 | 含义 |
|---|---|
| `generation` | 当前活跃代 |
| `units` | 本代通过淘汰规则的单元（按代内序号连续后缀，最靠边界的一批） |
| `summaryBlockTokens` | 块 token 量（用于预算与观测） |
| `droppedTotal` | 因容量被淘汰的单元总数 |

只有**活跃代**进 prompt；被淘汰的单元与 `superseded` 代只留在存储里，其事件可被检索。

### 2.4 事件（长期记忆原子）

| 字段 | 含义 |
|---|---|
| `id` | 事件 id（含单元与序号，稳定可复现） |
| `fact` | 一句客观事实（模型抽取的最终形态） |
| `factHash` | 事实哈希（检索去重与索引键，不是"合并相同事实"的依据） |
| `stmId` | 来源单元 |
| `sourceKind` | 来源类型（默认 `stm_fact`） |
| `worldId` / `dimension` / `position` / `spatiallyBound` | 空间归属（有坐标的事实才绑定空间） |
| `createdAtMillis` / `happenedAtMillis` | 写入时刻 / 事发时刻（衰减用后者） |
| `entityTags` | 实体标签（用于"关于谁"的过滤） |
| `turnRefs` | 轮级溯源，**至少一条**；这是"不去重"的前提 |
| `importance` | 1–10 的整数，缺省 5；写入时定，读路径只读 |

### 2.5 偏好

偏好不是独立表，而是**按玩家 UUID 存储**的一类条目（`players/<id>/preferences.json`），跨世界生效：

| 字段 | 含义 |
|---|---|
| `id` / `playerId` | 条目与归属 |
| `fact` | 明示偏好的原话形态 |
| `confidence` | 置信（0–1）；抽取只接受**明示**倾向，推断出的倾向丢弃 |
| `turnRefs` | 溯源的轮次 |
| `batchId` | 来自哪次压缩 |
| `createdAtMillis` | 写入时刻 |

偏好是**可能缺席**的：绝大多数单元摘要里没有偏好条目，`preferences` 为空数组是正常结果，不得为了凑字段而编造。

但一旦产出就必须准确：只收玩家**明示**的倾向（"我不喜欢下矿"），推断出来的（"他经常在地下，应该喜欢下矿"）一律丢弃，`fact` 保留原话形态。

冲突处理：新偏好追加并指向被覆盖者，不删除旧条目（与 M2 一致）。

## 3. 一段式压缩

### 3.1 形态

一个单元只发**一次**模型请求，输出同时包含三要素：

```json
{
  "schemaVersion": 2,
  "summary": "本单元摘要",
  "eventChain": [
    {"event": "客观事实", "importance": 6, "turnRefs": ["turn-a", "turn-b"]}
  ],
  "preferences": [
    {"fact": "玩家不喜欢下矿", "confidence": 0.9, "turnRefs": ["turn-a"]}
  ]
}
```

- 输入 = system（规则表 + schema + 打分锚例，同一条提示词）+ 本代已产出的摘要 + 本单元原文 + 指令。
- `importance` 与事实在**同一次**调用里产出，不额外调用、不事后补抽。
- 规则表、schema、锚例全部在语言资源里，代码里不出现自然语言判定规则。

### 3.2 解析与降级

| 情况 | 处理 |
|---|---|
| `schemaVersion` 不认识 | **整批拒绝**并记诊断（静默降级等于用旧解析器读新 schema） |
| 事实为空 / 超长 / 含替换字符 | 该条事件丢弃并记诊断，其余照常 |
| `turnRefs` 缺失、为空、或指到本批之外 | 该条事件丢弃并记诊断（防模型编造轮 id） |
| `importance` 缺失或非整数 | 兜底 5，记诊断 |
| `importance` 越界 | 夹到 1–10，记诊断 |
| 摘要解析失败但事件良好 | 事件照常落库、单元照常消费，只是不写摘要块 |
| 整份输出不可解析 / 空响应 | 什么都不提交，不消费窗口，下次重试 |
| 偏好缺 `confidence` 或溯源 | 该条不落库 |

摘要解析失败**不阻塞**事件落库：事件来自原文的一次性取舍，重试只会增加无界成本，而断层由事件检索兜底。

### 3.3 时序

```text
轮次追加 ──► 窗口水位/容量达标
                 │
                 ▼
         冻结输入快照（本轮请求看到的历史版本）
                 │
                 ▼
         取候选单元（连续未覆盖轮次，按 UNIT 预算）
                 │
                 ▼
         后台车道发起一次压缩请求
                 │
     ┌───────────┴────────────┐
     ▼                        ▼
 摘要成功                  摘要失败
 写单元摘要（代内序号）      不写摘要块
 写事件（含溯源与分数）      事件仍落库
 写偏好（明示）
     │                        │
     └───────────┬────────────┘
                 ▼
         消费窗口（原文进归档，换代时移出）
```

三条纪律：

1. **压缩不改 prompt**：单元压缩期间不动摘要块的其余部分、不移窗、不改 raw 渲染。
2. **快照冻结**：压缩看到的输入是本轮请求用的那个版本。
3. **单作业互斥**：同一世界同时只有一个压缩作业；重复触发直接跳过。

## 4. 检索

### 4.1 打分

```text
score       = relevance × recency × importanceFactor
recency     = floor + (1 − floor) × 2^(−ageHours / halfLifeHours)
halfLife    = 168h × S
S           = min(8, 1 + 0.5 × (|turnRefs| − 1))        （上限来自 7 的加成封顶）
importanceFactor = clamp(importance / 10, 0.1, 1.0)
```

| 常量 | 值 | 作用 |
|---|---|---|
| 衰减地板 | 0.05 | 极旧事件仍保留 5% |
| 钉子地板 | 0.50（importance ≥ 7） | 位置、明示偏好、未完成承诺不被时间打进冷区 |
| 半衰期基数 | 168 小时（7 天） | S=1 时的寿命 |
| 强度上限 | S = 8（56 天） | 被反复提到的同一事实更耐久 |

`relevance` 来自向量检索命中分，本层不改它的算法。相关性由"分数反推"得到（`relevance = score / (recency × importanceFactor)`），保证排序键与展示分同源。

### 4.2 分档（相对线）

```text
hot  = max(0.22, 0.72 × topScore)
warm = max(0.08, 0.45 × topScore)
cold = 0.02                                    （只是"值得展示"的地板，不是独立档）
```

相对线的理由：分数是三个因子的乘积，会随整批候选漂移；绝对线在"整批都弱"和"整批都强"两种情况下都会判错——前者把全部打成冷区，后者把全部推入热区。

两条特权：

| 规则 | 条件 | 效果 |
|---|---|---|
| 强制 Hot | `importance ≥ 8` 且 `relevance ≥ 0.60` | 不受相对线约束，直接进 Hot |
| Cold 可容 | `importance ≥ 4` | 重要度不足 4 的事实不进冷区（它们不该长期占配额） |

### 4.3 复核与链式发散

- 同一事实被多个来源命中时按 `1 + 0.10 × ln(1 + 命中数 − 1)` 加成（复核证据）。
- 命中锚定在某个单元上时，允许沿单元链向前后各走若干跳：

| 上下文档 | 半径（跳） | 广度（相邻块） |
|---|---|---|
| 紧凑 | 1 | 2 |
| 标准 | 2 | 4 |
| 扩展 | 3 | 6 |
| 大 | 4 | 8 |

档位只影响"能走多远"，不影响注入条数（尾部预算是固定尺寸）。

### 4.4 去重、排序与注入

| 步骤 | 规则 |
|---|---|
| 去重 | 按事实哈希去重；**先按分数排序、再去重、保留首个** |
| 排序 | 分数降序 → 单元 id → 事发时刻（稳定 tie-break，保证字节可复现） |
| 截断 | 只按整条记忆截断，不切半句 |
| 注入 | 一条尾部消息内的多行；条数由上下文预算给出（记忆块 + 知识命中共享一个联合上限） |

活跃代次的单元对应的事件**不参与检索**（M7）：那批原文还在 prompt 里。

### 4.5 与上下文预算的关系

注入配额不是常量，而是由尾部检索池推导：记忆块按 40 token/块、知识按 20 token/条换算，记忆侧占池的 85%，联合上限 20 条。公式见《AX_上下文编排》§3.3，本文不复述——两处各写一套是漂移的源头。

## 5. 存储与隔离

```text
<root>/
  shared/
    prompts/                记忆任务提示词、提示词文本（可被玩家覆盖的内置资源副本）
  worlds/<worldId>/
    raw_turns/              原文归档（append-only）与检查点
    stm/blocks              单元摘要
    summary/                摘要块（按代）
    events/                 长期记忆事件
    vectors/                事件向量（按嵌入命名空间）
    indexes/                检索索引快照
    stats/                  统计
  players/<playerId>/
    preferences.json        按玩家 UUID 的偏好（跨世界）
```

| 原则 | 含义 |
|---|---|
| 权威 vs 派生 | 原文是权威；摘要、事件、向量、索引都是派生，可重放重建 |
| 追加优先 | 归档与事件库只追加；检查点与摘要块允许按代重写 |
| 世界隔离 | 事件、单元、摘要按 `worldId` 分目录，不跨世界读 |
| 偏好例外 | 只有偏好按玩家 UUID 存放，跨世界生效 |

## 6. 写入安全

1. **原子提交**：原文先归档成功，再把轮次标记移出窗口；事件与摘要按单元一次性提交。
2. **版本号**：事件、单元、摘要块、偏好各有 schema 版本；不认识版本就拒绝，不静默降级。
3. **存储兼容检查**：启动时比对清单与文件集，缺文件/多文件/版本不符给出可读报告，而不是等运行期报错。
4. **不做文本级去重**：入库路径上禁止"相似合并"（M3）。
5. **诊断可观测**：抽取低产、覆盖率不一致、importance 兜底、偏好丢弃都进诊断，不自动重试（重试会放大成本并掩盖提示词问题）。

## 7. 参数表

| 参数 | 默认 | 说明 |
|---|---|---|
| 摘要块容量 `SB` | `clamp(0.05W, 2048, 24576)` | 累积摘要的容量 |
| 保持窗口 `KEEP_MAX` | `clamp(0.10W, 2048, 49152)` | 逐字原文 |
| 压缩水位 | `0.70W` | 触发压缩 |
| 压缩窗口 | `max(1, 水位 − SB − KEEP_MAX − 尾部)` | 待压原文容量 |
| 压缩单元 `UNIT` | `min(8192, 压缩窗口)` | 一次压缩的候选量 |
| 半衰期基数 | 168h | S=1 |
| 强度上限 | 8 | 56 天 |
| 衰减地板 | 0.05（钉子 0.50） | 钉子线 importance ≥ 7 |
| Hot / Warm 线 | `0.72 / 0.45 × topScore`，地板 `0.22 / 0.08` | 相对分档 |
| Cold 地板 | 0.02 | 展示下限 |
| 强制 Hot | importance ≥ 8 且 relevance ≥ 0.60 | 特权通道 |
| Cold 可容 | importance ≥ 4 | 条数保护 |
| 链式发散 | 1/2、2/4、3/6、4/8（半径/广度） | 按档位 |
| 复核加成 | `0.10 × ln(1 + 命中数 − 1)` | 多源命中 |
| 记忆块估计 | 40 token/块 | 配额换算 |
| 事件 importance | 1–10，缺省 5 | 写入时定 |

`W` 为上下文总量，公式与尾部尺寸见《AX_上下文编排》§3。

## 8. 禁止事项

| # | 禁止 | 理由 |
|---|---|---|
| 1 | 让 LLM 模块决定记忆生命周期 | 生命周期是工程代码的职责 |
| 2 | 把临时状态直接写入长期记忆 | 状态每轮重建，不属于事实层 |
| 3 | 把所有原文无限追加进 prompt | 原文进归档，不进 prompt |
| 4 | 为"去重"删除真实发生的相似历史 | 违背 M2/M3 |
| 5 | 读路径上改写 importance / 热度 | 违背 M4，且让回放不一致 |
| 6 | 跨世界共享记忆 | 违背 M5（偏好是显式例外） |
| 7 | 把摘要块拼进 system | 换代会让前缀从第 0 个 token 起失效 |
| 8 | 把检索注入放在历史之前 | 每轮打断整个历史前缀 |
| 9 | 摘要跨代累积（上一代内容拼进本代） | 摘要只承接当前代；跨代信息由事件检索承载 |
| 10 | 缩短保持窗口（含崩溃恢复路径） | 它是近期上下文保真的唯一保证 |
| 11 | 活跃代次的原文对应事件参与检索 | 同一段历史会被说两遍 |
| 12 | 在代码里写死判定规则文本 | 规则只在语言资源里 |
| 13 | 为偏好新建独立存储表 | 偏好就是按玩家存放的一类条目 |
| 14 | `turnRefs` 留空或允许编造 | 溯源是"不去重"的前提 |
| 15 | 未知 schema 版本静默降级 | 旧解析器读新 schema 会静默丢字段 |

## 9. 验收

1. 一个单元只发一次请求；三要素在同一次输出里。
2. 未知版本整批拒绝；字段级失败只影响该字段。
3. 摘要失败仍然落事件、仍然消费窗口；整份不可解析时不消费窗口。
4. 事件的 `turnRefs` 全部落在本批轮次内。
5. 打分可用事件重算（分数 = 相关性 × 衰减 × 重要度）；同分排序稳定可复现。
6. 相对分档在两个极端（整批弱、整批强）都给出有意义的分布。
7. 换代只移出被覆盖的对话轮次；事件留在原文窗口。
8. 活跃代次的事件不出现在检索结果里。
9. 原文归档 append-only；崩溃后原文不丢。
10. 偏好按玩家跨世界读取；非明示偏好不落库。
