## 2. 事件与状态的分界

### 2.1 一张表

| | 事件 `<event>` | 状态（尾部注入） |
|---|---|---|
| 本质 | 有发生时刻的**变化** | 持续存在的**当前事实** |
| 例子 | 死亡、进入下界、获得效果 | 准星物品、附近敌对数量、剩余背包格 |
| 处理 | **追加进历史**，按类别播报或静默 | **每轮重建**，不播报、不进历史 |
| 可重复观测 | 否。发生一次就是一次，有先后、可计数 | 是。每轮重算，算出来一样就是一样 |
| 典型失败 | 把"当前血量 2 心"写成事件 → 每轮都发一条"你血量很低" | 把"刚被炸了"写成状态 → 下一轮就消失，模型永远不知道发生过 |

### 2.2 为什么必须分开

1. **语义不可互换**：状态是幂等的，事件是非幂等的。混在一个通道里，模型分不清"他现在血少"与"他刚才掉血"——前者该建议吃东西，后者该问"被什么打了"。
2. **成本结构相反**：状态每轮重算、每轮必 miss，因此必须可重复生成；事件只发生一次，走历史天然只出现一次。把一次性事实放进每轮重建的槽位，等于专门为它造一套去重。
3. **可复现性**：能被压缩抽成长期记忆的信息必须先进历史；记忆原料是 raw 轮次，尾部块不进原料。

### 2.3 落点纪律：同一事实只说一遍

```text
正确：
  状态块  ：准星：无目标 | 血量：2 心 | 维度：下界
  <event>：从高处坠落，失去 6 心

错误：
  状态块  ：血量：2 心（上次 8 心，下降 6）
  <event>：血量从 8 心掉到 2 心
```

三条纪律：

1. 状态块只描述**值**，不描述变化量，不带"上次是…"。
2. `<event>` 只描述**变化**，不带"现在的值是…"；最新值由同轮或下一轮的状态块负责。
3. 状态块因预算未出现时，**不得**用 `<event>` 顶替它说明当前状态。

### 2.4 落点

`<event>` 追加为一条历史轮次（角色 `world_event`），不是每轮重建的尾块。

| | 落点 | 每轮重建 | 进历史 |
|---|---|---|---|
| 状态 | 尾部注入 | 是 | 否 |
| 事件 | 历史轮次 | 否（发生即写一次） | 是 |

**为什么必须是历史**：记忆只从 raw 轮次里抽取（§10）；尾块每轮丢弃，事件下一轮就消失，进不了任何记忆路径；历史 append-only，天生只出现一次，不需要"已投递"标记去重。

### 2.5 只有一种包裹

Prompt 里的历史轮次只有一种包裹：`<event>…</event>`。所有非玩家来源都是事件——世界自身的变化、其他玩家的聊天、其他模组投递的话语——不再有第二种标签。

带说话人的事件把说话人写进正文：

```text
<event>同伴 Steve 说：有人一起挖矿吗</event>
<event>玩家击杀了僵尸</event>
<event>天气转为雷雨</event>
```

措辞规则（模型只看得到句子，看不到来源字段）：

| 来源 | 句式 |
|---|---|
| 其他玩家/实体的言语 | `同伴 <名字> 说：<内容>` |
| 当前玩家自己的行为（死亡、击杀等） | `玩家<动词短语>` |
| 环境自身变化 | 直接陈述 |

说话人模板是语言表里的一个键（`recent_dialogue.event.said`），渲染层用同一个渲染器输出；模板缺失时退化为"说话人 + 空格 + 内容"，不丢主体。

## 3. 对外契约

### 3.1 字段表（`AXEventDescriptor`）

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `kind` | 是 | string | 命名空间化事件类型：`tianshu:death`、`mymod:ritual_complete` |
| `tier` | 否 | enum | `RARE` / `NORMAL` / `FREQUENT`；省略则查内置表，查不到按 `FREQUENT` |
| `suppress` | 否 | bool | 生产者逐次声明"不要出声"：等价于黑名单 |
| `highlight` | 否 | bool | 生产者逐次声明"这次值得说"：**等价于白名单，且优先于静态名单** |
| `payload` | 是 | 对象 | `count`（≥1，默认 1）、`magnitude`（可选整数，语义由 kind 定义） |
| `text` | 是 | 值对象 | 语言键 + 参数（`AXEventText`），由接收侧渲染一次 |
| `fold` | 否 | enum | `NONE` / `COUNT` / `RANGE`，SILENT 融合时用哪种句式；默认 `NONE` |
| `sourceId` | 否 | string | 提交方标识，仅用于日志与诊断，**不参与任何判定分支** |

被拒的提交：`kind` 为空或不符合 `^[a-z0-9_.-]+:[a-z0-9_./-]+$`、`payload` 为空、`text` 为空（`NullPointerException`，属于调用方 bug）。

### 3.2 字段纪律

| # | 纪律 | 原因 |
|---|---|---|
| 1 | `kind` 必须命名空间化，且内置表只占 `tianshu:` | 第三方不得伪造前缀借用内置档位 |
| 2 | 未知 `kind` 一律按 `FREQUENT` | 宁可少说，不可乱说：陌生模组不能打断玩家 |
| 3 | 档位与名单是 `kind` 的静态属性（`highlight`/`suppress` 是显式的逐次声明） | 同一 kind 不得因实例数值被判成不同档位，否则 prompt 字节不可复现 |
| 4 | 生产者不提供句子，只提供键与参数 | 渲染只有一处，语言表只有一份 |
| 5 | 渲染结果视为不可信输入 | NFC 归一；剥离 `<` `>`（防模板注入 `<event>` 或其它标签）；超过 120 字符按词/句边界截断，不切断代理对 |
| 6 | `count` / `magnitude` 必须是整数 | 无浮点，血量类语义统一用心数 |
| 7 | 提交不得发起模型请求 | 播报不调模型；事件只改历史与出声 |

### 3.3 谁可以提交

| 项 | 规则 |
|---|---|
| 提交方 | 本模块把映迹的世界事件（含可选服务端组件送来的事实）映射成 kind；外部模组通过事件型入口 `AX.EVENT_INPUT` 投递，见《AX_协议中心》§4 |
| 通道 | 本地同步投递；不跨进程、不走网络 |
| 反转 | 只读旁听：不改世界状态、不写回游戏对象 |
| 幂等 | AX 不做键级去重；同一条事件被提交两次就是两条。调用方负责"每次发生只提交一次" |
| 频率 | kind 的频率由本表决定；外部模组只声明**行为**（`IMMEDIATE`/`DEFERRED`/`SILENT`），不声明频率——频率是本模块的私有词汇 |

## 4. 档位：频率

档位只回答一个问题——**这个 kind 多久发生一次**。它不是"重要程度"，因为两者方向相反：`RARE` 意味着罕见，因此才值得打断；`FREQUENT` 意味着天天发生，因此必须闭嘴。

| 档位 | 语义 | 条数 |
|---|---|---|
| `RARE` | 罕见（死亡、首次踏入维度、稀有收获） | 8 |
| `NORMAL` | 普通（有收益但不紧急） | 13 |
| `FREQUENT` | 高频波动（肉眼可见的数字变化） | 20 |

### 4.1 判据（评 kind 时用，不评实例）

| 判据 | RARE | NORMAL | FREQUENT |
|---|---|---|---|
| 有即时威胁（现在不行动就继续受伤/死亡） | ✅ | — | — |
| 不可逆（死亡、进入新维度、永久改变） | ✅ | 部分 | — |
| 有明确游戏收益（拿到、做成、达成、交易成） | — | ✅ | — |
| 纯状态波动（数字变了，没有新因果） | — | — | ✅ |
| 玩家肉眼可直接看到 | — | — | ✅ |

读法：从上往下第一条命中的判据决定档位；命中多条取最高档。

三条裁决惯例（评新增 kind 时用，避免拍脑袋）：

| 惯例 | 内容 | 例 |
|---|---|---|
| 成对事件只让一头占高档 | A 导致 B，只让触发因占高档，结果降一档 | `death` RARE → `respawn` NORMAL |
| 威胁是否仍在 | 持续存在→高；已过去但留下因果→中；只剩数字→低 | `on_fire` RARE / `fall_damage` NORMAL / `health_change` FREQUENT |
| 可见 ≠ 可解释 | 看得见形状看不懂含义→中；连含义都看得见→低 | `effect_gained` NORMAL / `exp_level` blacklist |

### 4.2 "肉眼可见"这一条为什么必须存在

语音是抢占式通道：血条就在屏幕正下方，半秒前数字从 8 变成 2，玩家已经看到了。此时再说"你掉血了"，信息增量为零、注意力消耗为正。"看到了"不等于"懂了"，但要由 kind 来分：`health_change`（数字变了）是 FREQUENT，`health_critical`（进入危急档）是 RARE——后者意味着"现在需要行动"，是语义不是数字。把这个区分交给 kind，是这套表同时防噪和防漏的关键。

漏报的代价远小于误报：语音助手只有"静音"这一种降级手段，一次误报会被记住。所以取向是宁可漏、不可多——这也是"未知 kind 按 FREQUENT"的同一个取向。

## 5. 名单：三态

名单与档位是两个独立维度：档位说"多久发生一次"，名单说"玩家是否额外想听"。

| 取值 | 含义 |
|---|---|
| `whitelist` | 值得比基线更主动一步 |
| 中性（未列出） | 按档位基线 |
| `blacklist` | 不值得打断 |

当前分布：白名单 5、黑名单 14、中性 22。

| 白名单 | 理由 |
|---|---|
| `death` / `health_critical` / `drowning` / `on_fire` | 可行动警告：晚几秒说就没有意义 |
| `boss_engage` | 危险 + 里程碑 |

`respawn` 保持中性：死亡那一轮已经说过，紧接着再念"你重生了"是重复信息；这也顺带解决了"死亡与重生相邻"的噪音。

### 5.1 `highlight`：生产者的动态白名单

`highlight=true` 等价于白名单，**优先于静态名单**：模组自己最清楚这次值不值得说。它与 `suppress` 同时为真时 `highlight` 胜出。

动态白名单**不豁免频率修正**（§6）：否则一个"总标 highlight"的模组会把 AX 变成复读机。

## 6. 频率修正：发生在档位层

档位本身就是频率，所以频率判定修正的是**档位**，不是类别。类别不含任何阈值。

```text
N ≥ 3   同 kind 在 30s 窗口内   RARE   → NORMAL
N ≥ 6                           NORMAL → FREQUENT
FREQUENT 不再降
```

按序施加，所以一个 RARE kind 连续发生足够多次会走完两级（第 6 次成为 FREQUENT）。修正只降不升，且以上限为声明的档位封顶。

两条阈值来自 `AXEventSettings`，判定处不出现裸数字。

## 7. 类别：纯函数

`AXEventPolicy.classFor(修正后档位, 名单)`。实现是"阶梯 + 一步升降 + 两端截断"，不是九格硬编码：

```text
阶梯：   IMMEDIATE > DEFERRED > SILENT > DROP
基线：   RARE → DEFERRED    NORMAL → SILENT    FREQUENT → DROP
规则：   白名单 = 上一档    中性 = 基线        黑名单 = 下一档（两端截断）
```

展开：

| 档位 | 白名单 | 中性 | 黑名单 |
|---|---|---|---|
| RARE | IMMEDIATE | DEFERRED | SILENT |
| NORMAL | DEFERRED | SILENT | DROP |
| FREQUENT | SILENT | DROP | DROP |

两个推论值得单独说：

- **RARE + 黑 = SILENT，不是 DROP**：罕见但被标记为"不要打断"的事，攒到空闲期再说，不丢弃。
- **FREQUENT + 白 = SILENT**：白名单只把高频事件抬到"进历史"，不会让它出声。

## 8. 落地：四类的行为

| 类别 | 是否出声 | 是否进历史 | 时机 |
|---|---|---|---|
| `IMMEDIATE` | 是 | 是 | 到达即出声；被"忙且不允许打断"挡住时排队，本轮结束时合并出声 |
| `DEFERRED` | 是 | 是 | 冷却窗口到期，合并成一轮主动对话 |
| `SILENT` | 否 | 是（融合后） | 窗口到期或用户先开口 |
| `DROP` | 否 | 否 | 什么都不发生，不记日志 |

### 8.1 IMMEDIATE 与"忙"

- 不忙 → 立即出声，并把同一句写入历史（说过的话必须能在记忆里找到）。
- 忙且玩家允许打断 → 仍然立即出声，TTS 队列的位置由语音层决定。
- 忙且玩家不允许打断 → 进入**立即队列**等待，此时**尚未**进历史。
- 队列的出口有两个：**本轮结束**（下一次 tick 发现不忙）→ 队列里所有条目**合并成一次播报**说出，每条各自落历史；**用户先开口** → 只落历史、不再出声（说话的机会已经过去，见 §8.3）。

"忙"的定义是**当前有一轮 LLM 对话未结束**（`AXTurnOrchestrator.hasActiveTurn()`），不是播放状态、不是模块活性。

### 8.2 DEFERRED 与冷却窗口

- 第一条进入缓冲时开窗：`120s + random(0..60s)`，**每次说完重新随机**，不落在固定节拍上。
- 窗口到期且缓冲非空 → 合并成一轮主动对话（多句合并为一条 utterance），随后清空并重新计时。
- 缓冲里的每一条在出声时**各自**写入历史：它们是一次呼吸里说出的事，但是各自发生的。

### 8.3 用户先开口：两个缓冲并入该轮

只要一轮由用户发起，立即队列与冷却缓冲里的条目**按到达顺序（跨两个区统一排序）**追加为该轮之前的 `<event>` 历史轮次，然后两个缓冲清空，冷却窗口重新开始。

三条约束：

1. **必须追加在用户这句话之前**——历史顺序等于真实发生顺序。
2. **必须作为历史轮次**，不能塞进 current-input；否则它进不了压缩原料，也就永远成不了记忆。
3. 到期未说的 DEFERRED 条目走这条路径时**只进历史、不再出声**：用户已经在说话了，主动播报的机会已经过去。

### 8.4 时序

```text
提交 ──► 频率修正 ──► 类别
                       ├─ DROP     : 结束
                       ├─ SILENT   : 进融合窗口 ──┐
                       ├─ DEFERRED : 进冷却缓冲 ──┤
                       └─ IMMEDIATE: 出声+写历史   │
                                                  │
每 tick  ──► 到期融合窗口落历史；本轮结束 → 立即队列合并出声；冷却到期 → 合并成一轮主动对话
用户说话 ──► 到期融合窗口落历史 → 立即队列+冷却缓冲按到达序落历史 → 清空
停止    ──► 关闭全部融合窗口 → 剩余队列/缓冲落历史 → 关闭服务
```

## 9. SILENT 的融合

目的是"让模型知道发生过，而不是读四十遍"。

- 窗口键 = **kind + 主体标识**。主体标识取模板键与**非数值参数**：不同物品分开计数（`合成圆石` 与 `合成泥土` 各一条），数值参数不参与身份（`失去 5 心` 与 `失去 4 心` 同属一个窗口，也正是 RANGE 折叠要汇总的东西）。
- 窗口空闲达到聚合窗口长度即关闭；关闭时若命中数达到阈值，用 kind 声明的 `fold` 形态渲染一条带计数的句子；未达阈值则原样逐条落历史（事件不丢）。
- `fold = NONE` 的 kind 不进入窗口，逐条落历史。
- 融合只压**粒度**，不压**事实**：非 DROP 的事件最终一定留下痕迹。

## 10. 与压缩链路的关系

当前实现：

- 事件轮次（角色 `world_event`）**不进入压缩单元**。压缩单元只由对话轮次构成；事件留在原文窗口里，随窗口容量淘汰。
- 换代（压缩窗口占满）只移出被单元覆盖过的对话轮次，**不清事件**。
- 因此事件不参与摘要抽取，也就不会变成 `E`/偏好；它靠"仍在原文窗口里"被模型看见，窗口容量决定它还能被看见多久。

这条规则对使用方有一个直接后果：**要进长期记忆的事，必须走对话或由记忆侧另行抽取**，不能指望事件被压缩。

## 11. 参数表

全部来自 `AXEventSettings`，代码里不出现对应裸数字。

| 参数 | 默认 | 含义 |
|---|---|---|
| `frequencyWindowMillis` | 30s | 频率计数窗口 |
| `rareToNormalThreshold` | 3 | RARE→NORMAL 的命中数 |
| `normalToFrequentThreshold` | 6 | NORMAL→FREQUENT 的命中数 |
| `deferredCooldownBaseMillis` | 120s | 冷却窗口基数 |
| `deferredCooldownJitterMillis` | 60s | 冷却窗口随机量（取值 `[0, jitter)`） |
| `aggregateWindowMillis` | 30s | 融合窗口空闲阈值 |
| `aggregateThreshold` | 3 | 融合成一条所需的最少命中数（下限 2） |
| `busy` | 宿主提供 | 是否有一轮 LLM 对话在跑 |
| `allowInterruption` | 玩家设置 | 忙时是否允许打断 |

固定常量：渲染句子上限 120 字符；`kind` 正则 `^[a-z0-9_.-]+:[a-z0-9_./-]+$`；主动对话的多句以换行连接。

## 12. 观测

| 日志键 | 触发 |
|---|---|
| `ax.event.speech_pending` | 一条事件即将出声（含 kind、reason、文本） |
| `ax.event.queued` | 忙且不打断，进入立即队列（含当前队列长度） |
| `ax.event.deferred` | 进入冷却缓冲（含当前缓冲长度） |
| `ax.event.voluntary_turn` | 冷却到期，合并成一轮主动对话（含合并条数） |
| `ax.event.text.unresolved` | 模板无法渲染，回退为 kind 码（含 key 与原因：缺键/参数） |

`DROP` 不产生任何日志：没有发生任何事。回退为 kind 码是刻意的——空行会占掉一个历史槽位却什么都没说，比一个裸 kind 码更糟。

## 13. 验收门禁

测试覆盖以下断言，改动后必须保持：

1. 策略矩阵九格（档位 × 名单）与两端截断。
2. 频率修正在第 3 次（RARE→NORMAL）、第 6 次（NORMAL→FREQUENT）生效；旧命中移出窗口后恢复原档位；计数按 kind 隔离。
3. 白名单 kind 的完整衰减链：`IMMEDIATE → DEFERRED → SILENT`（以 `death` 验证）。
4. 忙且不打断 → 不出声、入队；用户开口 → 按到达序变历史并清空；不忙 → 立即出声且写历史。
5. 冷却窗口在 `[120s, 180s)` 且每次重抽；未到期不出声；到期合并为一轮；期间用户开口 → 并入历史并清空。
6. 融合：同主体折叠成带计数的一条；不同主体分开计数。
7. `DROP` 不落历史、不出声、不记日志。
8. 旧档位名（`high`/`mid`/`low`）、旧类别名（`APPEND_AND_*`）在源码、测试与表里零残留。
9. 语言表键缺失时正文回退为 kind 码，且诊断可观测。

## 14. 禁止事项

| 禁止 | 原因 |
|---|---|
| 在判定里按实例数值改档位 | 同一 kind 时高时低，字节不可复现、冷却与观测失去意义 |
| 在代码里写死阈值、冷却、窗口 | 全部必须是 `AXEventSettings` 项 |
| 在代码里写自然语言（含兜底句） | 文案一律语言表；缺失时回退 kind 码 |
| 因提交事件而发起模型请求 | 播报不调模型；事件只改历史与出声 |
| 因冷却/忙碌/融合而丢弃非 DROP 事件 | 记录与出声是两条通道，只有 DROP 同时关掉两者 |
| `kind` 分支进决策 | 决策只看档位、名单、频率；`sourceId` 只进日志 |
| 把事件写进 current-input 或尾块 | 只有历史能让它被模型看见并被压缩/留档 |
| 让 `<event>` 之外的包裹回流 | 只有一种标签；说话人写在正文里 |
