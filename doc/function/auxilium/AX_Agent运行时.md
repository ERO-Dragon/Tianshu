# AX Agent 运行时

AX 怎么把一次模型调用跑成"一轮对话"，以及需要查资料时怎么异步委派、怎么把结果带回来。以当前代码为准。

## 1. 定位与范围

### 1.1 负责

| # | 负责 | 章节 |
|---|---|---|
| 1 | 输出契约：平时说人话，需要查时挂标签 | §2 |
| 2 | 主对话为什么不带 `tools[]` | §3 |
| 3 | 运行循环、两套策略预设、终止判定 | §4 |
| 4 | 异步委派的时序、票据、终态 | §5 |
| 5 | 三个通道分离与播报门槛 | §6 |
| 6 | 工具分类与"元能力"边界 | §7 |
| 7 | 运行期消息编排边界 | §8 |

### 1.2 不负责

- 提示词的段序与预算：归《AX_上下文编排》。
- 记忆的抽取与检索：归《AX_记忆策略》。
- 事件的定档与落地：归《AX_事件系统》。
- 模型/ASR/TTS 的协议细节：归各引擎模块与协议中心。

### 1.3 不变量

| ID | 不变量 | 检测信号 |
|---|---|---|
| A1 | **无世界动作**：任何运行的可用能力都不改变世界状态 | 能力表里出现放置/给予/攻击类动作 |
| A2 | **委派不回传原始材料**：跨运行边界只允许"结论（至多三句）+ 可选来源" | 投递正文出现长段材料或文档片段 |
| A3 | **主对话无工具**：主对话请求 `tools` 为空，历史里工具消息恒为 0 | 主对话 payload 出现 tools；历史出现工具消息 |
| A4 | **投递必达**：每个票据在事件线上留下**恰好一条**终态记录 | 票据数 − 已投递数 ≠ 0 |
| A5 | **状态与检索不进历史，事件必进历史** | 历史里出现状态/检索原文；事件缺失 |
| A6 | **禁止嵌套**：复杂运行内不再发起委派；主对话不同步起复杂运行 | 复杂运行上下文里出现票据创建 |
| A7 | **单票据单运行**：一次委派对应一次运行；唯一复用是同会话 5s 内**逐字节相同**的查询 | 5s 窗口内同一查询出现两个运行 |
| A8 | **上限是闭集**：两套策略的步数与时长不可被调用方覆盖 | 出现第三套策略或运行期改上限 |
| A9 | **委派不做键级去重**：去重只靠记忆召回与 5s 回放窗 | 委派代码里出现"问题正文 → 键"的哈希表 |
| A10 | **结论自足**：投递正文能脱离来源上下文读懂，不出现"如上所述"这类指代 | 正文含指代词 |

A2 与 A10 是一对：前者限制带回多少，后者保证带回的那点够用。

## 2. 输出契约

### 2.1 形态

```text
平时：正常说人话，零格式。
需要查时：这个问题让我去查一下。<delegate>检索如何进入暮色森林</delegate>
```

主对话不带工具，历史里也没有工具消息，所以"要委派"只能靠标签表达。判别只有两态：

| 形态 | 条件 | 语义 |
|---|---|---|
| `Delegated` | 第一个完整标签的内容非空 | 标签内是一次异步检索的**控制信息**；标签外的话才是答句（"我查一下"） |
| `Plain` | 其它一切（无标签、内容空白、只有开标签、多个标签里第一个为空） | 剥掉标签后剩下的文本就是答句 |

### 2.2 剥离规则

| # | 情形 | 处理 |
|---|---|---|
| 1 | 无标签 | 全文即答句 |
| 2 | 完整标签且内容非空 | 标签外为答句，标签内 strip 后为查询 |
| 3 | 标签内容空白 | 不委派；空标签连同标记一起剥掉，按普通文本念 |
| 4 | 只有开标签 | 不委派；剥掉开标记，剩余文本照常念 |
| 5 | 多个标签 | 只认第一个；其余标签连同内容一并剥除 |
| 6 | 标签在中间 | 前后段直接拼接（只删标签字符，不插空白），阅读顺序不变 |

标记按字面量匹配（区分大小写，允许两侧空白）。大小写写错时它只是普通文本，不会被当成委派。

### 2.3 硬约束

- **标签不进 TTS、不进历史**：所有出口只认"剥标签后的正文"。
- 没有任何"违约"概念：模型说了人话就是答句，标签只是可选控制后缀。因此不存在"格式错误重试"这条路径。
- 正文里的标签由输出侧统一剥离；TTS 侧还会再做一次确定性清洗（防模型把标签写进正文）。

## 3. 主对话为什么不带 `tools[]`

| 理由 | 展开 |
|---|---|
| 模型能力参差 | 本地小模型的工具调用成功率不稳定；一次工具参数写错就是一轮废掉 |
| 语音通道没有"看" | 工具结果最终仍要被说成一句话，直接要求模型说成一句话更短 |
| 前缀稳定 | 工具 schema 是 system 之后的又一段固定前缀，动态工具集会让前缀抖动 |
| 成本 | 工具调用往往意味着多步；语音场景的交互预算是 1–2 步 |

因此主对话的"能力"来自**注入**（状态快照、记忆检索、知识命中）与**标签**（委派检索），不来自工具调用。需要多步自主能力的那部分被隔离在异步委派里（复杂运行），并受 A2/A6/A7 约束。

## 4. 运行循环

### 4.1 一套循环，策略参数化

`AXAgentLoop` 是唯一的循环实现：发请求 → 解释输出 → 继续或收尾。循环里没有"这是主对话还是委派"的分支，差异全部来自策略对象。

| 预设 | 步数上限 | 挂钟上限 | 带工具 | 无进展检测 | 取消范围 |
|---|---|---|---|---|---|
| 简单（主对话、压缩、判定类调用） | 3 | 10s | 否 | 否 | 只取消自己 |
| 复杂（异步委派） | 25 | 120s | 是 | 是（连续相同一步即中止） | 取消派生的全部子请求 |

两步的语义：**1 步 = 1 次模型请求**。简单预设给 3 步的余量用于"输出不合契约时的一次修复"。

### 4.2 终止判定

每次请求**之前**按固定顺序检查：**步数上限 → 挂钟超限 → 取消**。因此撞阀时不会再多发一次请求。

| 一步的结果 | 运行终态 |
|---|---|
| 完成（拿到可交付内容） | `COMPLETED` |
| 中止（被取消） | `CANCELLED`（保留"谁到期"） |
| 拒绝（输出不可用且不可修复） | `FAILED` |
| 继续 | 继续循环，或撞无进展检测 → `ABORT_NO_PROGRESS` |

超时来源**不许压平**：循环自己的截止时间与来自某一步的到期是两种不同的归因，前者记"循环截止"，后者按它给的值原样带出。撞步数记 `ABORT_MAX_STEPS`，撞超时记 `ABORT_TIMEOUT`。

### 4.3 无进展检测

只对复杂运行启用：连续相同的一步（相同调用 + 相同参数）达到阈值即中止。判据必须能离线判定——不依赖模型自评、不依赖模糊相似度。

### 4.4 分层纪律

循环不出现玩家、播报、提示词装配，也不引用任何宿主平台类型；它只认识"一步"这个抽象。生产接线把"一次模型请求 + 有界等待"实现成一个步骤源，取消探针来自当轮执行对象。

## 5. 异步委派

### 5.1 时序

```text
主对话输出带 <delegate>查询</delegate>
      │
      ▼
登记票据（同会话 5s 内逐字节相同的查询复用既有票据）
      │
      ├─► 回执"我查一下"（一条投递，资源键独立）
      │
      ▼
复杂运行（25 步 / 120s，带检索工具）在后台车道执行
      │
      ▼
终态 → 事件线登记一条（必达）→ 历史追加一条 <event> → 播报（受门槛）
```

### 5.2 票据与终态

| 项 | 规则 |
|---|---|
| 票据 id | 由查询哈希前缀与序号拼成，可预测 |
| 回放窗 | 5s；窗口内同查询复用票据，不新建运行 |
| 终态 | 四值：成功 / 失败 / 超时 / 取消；"没查全"（撞步数、无进展）按**失败**投递 |
| 登记 | 每个终态恰好一条记录（A4），不因播报门槛或预算丢弃 |
| 取消 | 取消父运行即取消其派生的全部子请求 |

### 5.3 投递

投递载荷包含：票据 id、终态分类、运行终态、正文、来源列表、播报资源键。回执不是终态，因此不带终态分类。

## 6. 三个通道分离

| 通道 | 载体 | 是否必达 | 受约束 |
|---|---|---|---|
| ① 登记 | 事件线（本地、只追加） | 必达 | 无 |
| ② 进 prompt | `<event>` 历史条目 | 必达 | 历史容量与压缩 |
| ③ 出声 | TTS | 按门槛 | 播报门槛与队列 |

把三条合成一条会退化成两种错误：要么"失败也要立刻打断玩家"，要么"空闲时干脆不登记"（A4 破掉而没人发现）。**登记与落历史永远发生，出声看门槛。**

### 6.1 播报门槛

| 场景 | 动作 |
|---|---|
| 玩家空闲 | 立即出声；队列里还有则接着逐条播 |
| 正在对话或在播报 | 入队，在本轮结束时出队；不打断当前轮 |
| 失败 / 超时 / 取消 | **必须出声一句**（措辞来自资源键），不允许静默失败 |
| 多条待播 | 不合并、按登记顺序逐条播：每条结论对应一次独立委派，合并会丢掉"哪条是哪条" |
| 会话结束 | 队列丢弃，但事件线记录保留 |

措辞纪律：播报文本一律资源键；"我查一下"与"查到了…"是两条不同键，不得复用；结论播报直接读结论正文，不再二次改写（二次改写等于多一次模型调用，还会引入未被 A2 约束的新材料）。

## 7. 触发源与"没事找话"的边界

AX 只有一个输出引擎、三种触发源，没有第四种：

| # | 触发源 | 形态 |
|---|---|---|
| 1 | 玩家提问 | 一轮主对话（回答或委派） |
| 2 | 游戏内事件 | `<event>` 进历史 + 按类别决定是否出声 |
| 3 | 后台任务完成 | 事件线登记（必达）+ `<event>` 进历史 + 播报 |

**禁止**：定时开场白、随机话题、"玩家在位就打招呼"、模型自发起话题、无触发源的开口、跨会话的自主提醒。这些都没有可验证的触发源，误报一次就只能整条关掉。

**允许**：有触发源且过门槛的出声。判据只有一条可验证的问题——**这句话有没有触发源**。

## 8. 工具分类

| 类 | 例子 | 归属 |
|---|---|---|
| 状态查询 | 血量、坐标、背包、附近实体 | **不设工具**：由状态块每轮注入，避免同一事实两条注入路径 |
| 检索（知识/记忆） | 查资料、查历史 | 复杂运行内部使用；主对话通过标签触发 |
| 世界改动 | 放置、给予、攻击 | **不存在**（A1） |
| 元能力 | 取消、超时、步数 | 本地状态机，同步判定，不是模型工具 |

"元能力做成工具"是明确的反例：模型不能决定自己是否超时、能否取消；这些必须由本地状态机在每步之前判定。

## 9. 运行期消息编排边界

| 段 | 归属 | 每轮 |
|---|---|---|
| system | 单一冻结文本 | 不变 |
| 摘要块 | 记忆侧产出 | 只在写入新摘要时变 |
| 历史 | 对话正文 + `<event>` 条目 | 只追加 |
| 尾部（状态 / 检索 / 当前输入） | 每轮重建 | 变，且必然 |

运行期的职责只有"哪一块在什么时候动"，具体预算与段序见《AX_上下文编排》。三条边界：

1. 状态与检索是**一次性注入**，不进历史、不进压缩（A5）。
2. `<event>` 是**发生即追加**，不参与每轮合成、不合并成块、不插回历史中段。
3. 标签与内部标记不得外泄到正文；外泄防护在输出侧与 TTS 侧各做一层（概率层 + 确定性剥离层）。

## 10. 观测与验收

必落字段：票据 id、终态分类、运行终态、步数、挂钟耗时、正文长度、来源数、播报资源键、是否回执。

验收：

1. 每个票据恰好一条终态登记（A4）。
2. 主对话请求不含工具，历史无工具消息（A3）。
3. 委派正文不超过三句、不含指代词（A2/A10）。
4. 5s 窗口内同查询只有一个运行（A7）；窗口外再次查询是**正常**行为。
5. 撞步数 / 超时 / 取消分别归因，不压平（§4.2）。
6. 标签不进 TTS、不进历史（§2.3）。
7. 无触发源时完全静默（§7）。

## 11. 禁止事项

| # | 禁止 | 理由 |
|---|---|---|
| 1 | 给主对话加 `tools[]` | 破坏前缀稳定与语音交互预算 |
| 2 | 让模型自己判定超时/取消/步数 | 元能力必须是本地状态机 |
| 3 | 把原始材料带回主对话 | 违背 A2；正文会被无关材料兑水 |
| 4 | 嵌套委派 | 违背 A6，步数与成本都无法预测 |
| 5 | 键级去重（问题正文哈希） | 违背 A9；会吞掉"同一句问第二次"这类正常交互 |
| 6 | 只登记成功终态 | 违背 A4；失败被静默等于功能悄悄失效 |
| 7 | 把多条结论合并成一句 | 丢失指代，且需要第二次自由生成 |
| 8 | 静默失败 | 失败必须出声一句；措辞来自资源键 |
| 9 | 自行发起话题/提醒 | 没有可验证的触发源，误报代价不可恢复 |
| 10 | 在代码里写自然语言播报 | 文案一律资源键 |
| 11 | 重试"格式违约" | 契约里没有违约形态，重试等于白烧一轮 |
