# 辅星-技能协作设计

## 1. 定位

本文描述辅星的二期能力，也就是技能协作期。它会切换一套新的编排方式，并在一期底座上增加技能相关模块。

这不是重做记忆系统，而是让 AX 从“一期编排核心”升级到“技能编排 + 结果回流”的新链路。

## 2. 核心原则

- 技能与记忆隔离。
- 技能执行与最终回答隔离。
- 子执行体只负责隔离技能任务，不拥有独立人格和长期记忆。
- 能力切换只影响后续 turn，不改变历史记忆归属。
- 改变游戏状态的能力必须单独做权限、确认、回滚和审计。
- 二期会新增技能编排模块，但不会把一期的记忆和 prompt 底座推倒重来。

## 3. 协作边界

二期允许的方向是：

- 只读查询类技能。
- 受控动作类技能。
- 结构化任务转交。
- 外部模块协作。

典型例子包括：

- 记录日程或提醒。
- 向公屏发送结构化消息。
- 向 NPC 或其他模块下发任务请求。

## 4. 二期模块

二期建议新增以下模块：

- `AXIntentRouter`：识别需要技能参与的意图。
- `AXSkillRegistry`：管理可用技能和可见能力。
- `AXSkillExecutor`：隔离执行技能任务。
- `AXSkillResultNormalizer`：把技能结果归一化为 AX 可消费内容。
- `AXOrchestratorV2`：把技能结果并回一期上下文装配流程。

## 5. 编排回流

技能结果必须先回到二期 `core`，由其统一校验、归一化，再决定是否进入 prompt 或玩家可见输出。

AX 不允许：

- 由技能直接写记忆主链路。
- 由技能绕过 `core` 直接输出。
- 由模型自行执行未校验的技能调用。

## 6. 与一期的关系

二期复用一期的记忆底座，但会更换编排器，并新增技能相关模块。prompt 结构仍然保留分区思想，但内容来源和装配顺序会更偏向技能结果与任务流。
