# 织言黑盒测试

面向织言的端到端测试：不桩掉传输，也不桩掉模块。测试启动真实的 `LlmModule`，通过协议运行时投递 `LLM.REQUEST` / `LLM.CACHE_MANAGE` / `LLM.PRIMITIVE_QUERY`，模块自己构建 `OpenAiCompatibleInferenceClient` 并连接本机真实 HTTP 端点。失败意味着玩家路径会失败，而不是两个 mock 意见不合。

代码入口：`tianshu-weaving/src/test/java/com/rheinmetal/tianshu/function/weaving/blackbox/`。

## 组成

| 文件 | 作用 |
|---|---|
| `FakeOpenAiEndpoint` | 真实 `com.sun.net.httpserver` 端点，按场景吐 SSE / JSON；记录每个请求体 |
| `BlackBoxDriver` | 启动模块（register → prepare → start）、等待 RUNNING、投递 envelope、捕获响应 envelope |
| `BlackBoxConfig` | 测试配置：端点、模型、窗口、超时、推理梯子、`wireCompat`、嵌入模型名 |
| `WeavingBlackBox*Test` | 场景本身 |

默认套件只依赖本机端口，不需要网络、模型文件或游戏运行时。

## 场景矩阵

聊天（`WeavingBlackBoxChatTest`，17 个）

- 阻塞请求：结果、usage、请求体（`stream=true`、`stream_options`、messages）；
- 流式请求：thinking/text 分片、结束帧、`index` 顺序；
- 取消：CANCEL envelope 中止在途流，终态 CANCELLED，结束帧 CANCELLED；
- 推理梯子：DeepSeek 档位编码、tier 0 非思考、超界夹到最高档、`none`/`xhigh`；
- 传输兼容：不发 `stream_options`、改发 `max_completion_tokens`；
- 接收端宽容：`reasoning` 字段、嵌套 `cached_tokens` 与 miss 推导；
- 故障：401、503、`content_filter`、静默流超时、malformed 帧、无 `[DONE]` 的 EOF、空回复、空消息列表；
- 状态：两次请求复用同一客户端并累计 usage。

缓存与 RAG（`WeavingBlackBoxRagTest`，11 个）

- 无向量时 `LLM.CACHE_MANAGE` 为 FAILED、`LLM.PRIMITIVE_QUERY` 为 READY；
- 库注册 / 查询 / 预向量写入 / 词法检索 / 删除；
- 内容 PATCH、CLEAR_UID、UNREGISTER_LIBRARY；
- 按 modid / tags 的共享检索，且 private 库不进入共享结果；
- 内联内容检索不依赖存储；
- 未知 action 返回失败结果而不是抛异常；
- 模块重启后缓存回读与检索仍命中；
- 无向量时 token 计数与状态仍可用。

原语（`WeavingBlackBoxPrimitiveTest`，5 个）

- `TOKEN_COUNT`；`STATUS` 的窗口/预算/嵌入不可用/推理梯子；
- `EMBED` 在无模型时返回 `LLM_EMBEDDING_UNAVAILABLE`；
- 未知查询类型返回失败。

模型目录（`WeavingBlackBoxCatalogTest`，1 个）

- 通过真实 HTTP 请求 `GET /v1/models` 并解析 id 列表。

可选真实模型（默认跳过）

- `WeavingBlackBoxBgeIntegrationTest`：真实 BGE-M3（Q8_0）GGUF，CPU 加载，验证 `EMBED` 1024 维、`STATUS.embeddingAvailable`、`CACHE_MANAGE` READY、内容写入后向量检索命中；
- `WeavingBlackBoxLocalModelIntegrationTest`：真实 llama.cpp 端点（Qwen2.5-0.5B-Instruct），验证阻塞与流式请求。

## 运行

普通套件（黑盒测试使用本机假端点；真实模型用例自动跳过）：

```powershell
.\gradlew :tianshu-weaving:test --offline
```

只跑黑盒：

```powershell
.\gradlew :tianshu-weaving:cleanTest :tianshu-weaving:test `
  --tests 'com.rheinmetal.tianshu.function.weaving.blackbox.*' --offline
```

真实 BGE（约 605 MB，来自 `https://hf-mirror.com/gpustack/bge-m3-GGUF/resolve/main/bge-m3-Q8_0.gguf`）：

```powershell
$env:TIANSHU_BLACKBOX_BGE = "$env:TEMP\blackbox-models\bge-m3-Q8_0.gguf"
.\gradlew :tianshu-weaving:cleanTest :tianshu-weaving:test `
  --tests 'com.rheinmetal.tianshu.function.weaving.blackbox.*' --offline
```

也可以传 `-Dblackbox.bge=<path>`（测试同样接受该属性）。

真实小模型（llama.cpp）：

```powershell
llama-server --model qwen2.5-0.5b-instruct-q4_k_m.gguf --alias test-model `
  --host 127.0.0.1 --port 18089 -c 2048 -t 4

$env:TIANSHU_BLACKBOX_LLM_URL = 'http://127.0.0.1:18089/v1'
$env:TIANSHU_BLACKBOX_LLM_MODEL = 'test-model'
.\gradlew :tianshu-weaving:cleanTest :tianshu-weaving:test `
  --tests 'com.rheinmetal.tianshu.function.weaving.blackbox.*' --offline
```

## 测试发现并修复的问题

**CANCEL envelope 原先不能中止在途请求。** 黑盒测试第一次跑取消场景时，取消后请求仍然 COMPLETED：

- 入站 CANCEL 只把 envelope 状态改成 CANCELLED，运行时不会打断执行任务的线程；
- `LlmPromptRequestHandler` 没有注册 `context.onCancel`，因此客户端流继续读完；
- 修复：在 handler 里注册取消回调，取消时 interrupt 执行线程；传输层的 `await` 捕获中断、取消 future、关闭响应体，最终以 CANCELLED 收尾。`finished` 标志防止请求完成后的迟到取消误伤复用线程。

修复后黑盒取消场景通过，全量测试无回归。

## 已记录的行为

- 请求超时的下限是 5 秒（`OpenAiCompatibleInferenceClient.MIN_TIMEOUT`）；配置 1 秒实际是 5 秒，静默流测试因此等 6 秒。
- 供应商只发 `[DONE]`、没有 `finish_reason` 也没有内容时，结果是 COMPLETED + 空文本；这是“供应商说了结束”的语义，不是传输失败。
- `QUERY_UID.exists` 表示该 uid **有缓存条目**，不是“库已注册”；注册后先写入再查询才是 true。
- 无嵌入模型时，只带内容、不给向量的 `UPSERT_ENTRY` 会返回 `EMBEDDING_NOT_READY`；预向量写入可用，这也是无向量环境下的受支持路径。
- `/models` 只返回 id，窗口仍按“预设清单 → 200K → 手动”规则声明。

## 边界

- 这是协议层黑盒，不是 Minecraft 客户端/服务端联机测试；设置页交互由 `LlmProviderEditorPanelTest` 覆盖。
- 假端点按场景构造 SSE，不代表任何特定供应商的全部怪癖；真实 BGE / 小模型用例补上了“真实 tokenizer、真实流、真实模型”的一端。
- 取消已覆盖；`EMBED` 批量文本、`PATCH_ENTRY` 的 updateVector 分支、多模型条目切换仍是后续可补项。
