# Dubhe 搜索（`search`）

> **要点**
> - 只答**描述性知识**：这个物品/方块干什么、这个模组怎么玩、这个原版机制怎么运作。配方归舟楫、版本与依赖本地已知、崩溃不做。
> - 三层源按序降级：**本地手册（Patchouli）→ 中文站 → 英文站**。
> - 不引入任何需要 API key 的通道。
> - **纯内部技能**：不向舟楫注册任何能力（G66），本文只管天枢自己怎么查。

## 1. 边界：不管什么

| 问法 | 归谁 | 为什么 |
|---|---|---|
| 配方 / 合成表 | 舟楫 `tianshu:recipe.query` | 存档里的真实配方，含整合包魔改；网页必然可能错 |
| 支不支持我这版本、依赖什么 | 本地 `ModList` | 启动时已知，联网是绕远路 |
| 报错了 / 崩溃 | 不做 | 客户端日志不在我们手里 |
| 整合包推荐、下载站浏览 | 不做 | 不是游戏内会发生的事 |
| 世界动作 | 不做（A1） | 天枢无实体 |

剩下只有三问：**这是什么、怎么玩、原版机制怎么运作**。

## 2. 两个轴

- **轴一：问什么** → 决定去哪个源。唯一的轴。
- **轴二：怎么取**（API / HTML / jar 资源）→ 源的属性，模型不用管。

## 3. 三层源与降级

| 层 | 源 | 前提 |
|---|---|---|
| L1 本地 | 已装模组的 Patchouli 手册 | 模组用了 Patchouli |
| L2 中文 | MC百科、中文 Wiki、BWIKI | 网络可用 |
| L3 英文 | CurseForge、Modrinth、`minecraft.wiki` | 网络可用 |

- 上层无命中 → 下层；任一源超时/报错/零结果 → 跳过。
- **跨语言不标注**：模型读英文、用玩家语言转述是 simple 的本职，不需要「来自英文源」这种提示。
- **不做国产判断**：`ModList` 给不出可靠产地；让 L3 查不到自然落到 L2，机制等价且不会误判。

## 4. 站点清单

### 中文

| 站点 | 覆盖 | 取法 | 状态 |
|---|---|---|---|
| MC百科 `mcmod.cn` | 模组词条（中文侧唯一） | HTML + 站内搜索 | robots 允许正文；无官方 API |
| 中文 Wiki `zh.minecraft.wiki` | 原版 | MediaWiki API | 实测可用 |
| BWIKI `wiki.biligame.com/mc` | **只有原版** | MediaWiki API | 实测可用；搜「机械动力」0 条 |

### 英文

| 站点 | 覆盖 | 取法 | 状态 |
|---|---|---|---|
| CurseForge | 作者原话（描述、文件） | `api.cfwidget.com` 公开镜像 | 实测可用；官方 API 需 key，不用 |
| Modrinth | 作者原话（描述、版本） | 官方 API | 实测可用，免 key |
| `minecraft.wiki` | 原版 | MediaWiki API | 实测可用 |

**不收录**：9Minecraft（转载站）、Planet Minecraft（地图/皮肤）、Minecraft Forum（已衰退）、GitHub（开发视角）、B站/YouTube（视频读不了）。

**官方 wiki 不设计成链路上的一环**：CF 的 `links` 实测为空（Create 就是空），Modrinth 的 `wiki_url` 实测常为 null（Botania 就是 null），「从发布站跳到官方 wiki」不可靠。已有 URL 时只作事后补充。

## 6. 本地手册（L1）：Patchouli

数据在**模组自己的 jar**（`assets/<ns>/patchouli_books/<book>/`），不在 Patchouli 的 jar 里——**没装 Patchouli 也能读**。

两级检索，不整本进模型：

| 步 | 做什么 |
|---|---|
| 建索引 | **首次查询时**读一遍所有模组的书，常驻内存；没人问就不读 |
| 匹配 | 问法切成词（英文按词、中文按二字滑窗），标题命中权重高于正文 |
| 取正文 | 只回命中的 1–3 条，整次回答的正文上限 1800 字 |

实现落点：

- **端口**：`InstalledModIds` + `ModResources`（`tianshu-api/assembly`）。适配器实现，模块不接触加载器 API；两边共用的 IO 在 `mc.resource.ModResourceFiles`。
- **技能**：`agent/skill/book/`——`book` 是技能 id，目录、语言回退、格式控制清理全在解析器里，模型只看到"问什么 → 标题 + 正文"。
- **缓存挂在技能实例上**，不挂静态字段：模块停掉缓存即消失，测试也不会互相污染。

**对"书长得不一样"的三条兜底**：

| 差异 | 处理 |
|---|---|
| 正文页类型五花八门（`text` / `spotlight` / `entity` / 模组自造） | **按"有没有 `text` 字段"取，不按类型名取**。物品条目多是 `spotlight`，按类型筛会正好漏掉它们 |
| 文本是翻译键还是直接写的 | 一条规则：语言表里有就用表的，没有就当正文 |
| 条目没有 `name` | 退回文件名当标题，不整条丢掉 |
| 书的语言 | 跟**客户端语言**走（`DubhePromptLanguageProvider`），不再写死中文 |
| 文件异常 | 剥 BOM；单文件 >2MB 跳过；单条目坏掉只丢那条；总条目上限 2 万 |

**已知限制（本版不解决）**：只读**模组自带**的资源，读不到**资源包**里的书与汉化覆盖。汉化补丁常以资源包装的形式覆盖 `lang/zh_cn.json`，那种情况下我们会回退到模组自带语言，可能拿到英文原文。补这一层需要另一个端口（资源包视图 + 覆盖优先级），等真有玩家反馈再评估。

实测（Botania `lexicon`，第 1 本）：

| 项 | 值 |
|---|---|
| 条目数 | 246 |
| 文本页 | 491（约占全部页一半；其余是配方/图片/多元块，跳过） |
| 单条目正文 | ~267 字（中）/ ~667 字（英） |
| 整本 | ~6.6 万字（中）/ 16.4 万字（英）——**不能整本进 prompt** |
| 中文覆盖率 | 100%（246/246 条目名、491/491 文本页） |
| 索引体积 | 246 条标题共 1030 字，≈ 650 token |

解析要点：

- **文本解析只有一条规则**：先查语言表，命中就当键解析，没命中就当正文原样用。这一条同时覆盖「翻译键」（`"text": "botania.page.apothecary0"`）和「硬编码」（`text` 就是正文）两种写法，也容忍缺翻的键。
- 只取 `text` 页；`crafting` / `spotlight` / `image` 跳过。
- 语言：优先 `<book>/zh_cn/`（模组自带分语言结构时），否则用 `en_us/` 结构 + 查 `zh_cn` 语言表，再否则原文。
- 硬编码的条目只有一套文字，通常没有中文——照常读，不因此降级。
- 宏与模板不展开；坏 JSON 跳过并记日志，不拖垮整体。

## 7. 频控与失败

| 项 | 规则 |
|---|---|
| MC百科 | 单轮合计 ≤2 次（搜索 1 + 页面 1）；同域名 60s 冷却；不重试 |
| 其余站 | 单轮 ≤3 次/站；不重试 |
| 同 URL | 进程内缓存，只取一次 |
| 失败 | 降级 + 回答里说明；**三层都无命中就说查不到**，给已知信息并标置信度，不许编 |

## 8. 输出

结论 + 依据（每条带来源站点）+ 不确定处，嵌进报告三字段的 `result`。
