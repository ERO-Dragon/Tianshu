# Dubhe Agent 与技能

> 三层：**simple**（扮真人，唯一出口是委托）→ **代理**（有界循环，技能即它的工具）→ **技能**（自描述的执行单元）。
> 本文管"一次运行怎么跑、技能怎么描述与装配"；提示词段序见《上下文编排》，记忆见《记忆策略》，事件见《事件系统》。

## 1. 不变量

| ID | 不变量 | 破了会怎样 |
|---|---|---|
| A1 | **无世界动作**：运行内不出现放置/给予/攻击 | 越权 |
| A2 | **不回传原始材料**：只回结论（报告三字段） | 正文被材料兑水 |
| A3 | **simple 无工具**：`tools` 恒为 `{delegate}`，历史无工具消息 | 前缀抖动、语音预算爆掉 |
| A4 | **投递必达**：每个票据恰好一条终态 | 失败被静默 |
| A5 | 状态/检索不进历史，事件必进历史 | 记忆被污染 |
| A6 | **禁止嵌套**：运行内不再起委派 | 成本不可预测 |
| A7 | **单票据单运行**：只复用同会话 5s 内逐字节相同的查询 | 重复计费 |
| A8 | 上限是闭集，调用方不可覆盖 | 失控 |
| A9 | 委派不做键级去重 | 吞掉正常追问 |

## 2. 一套循环，策略参数化

`DubheAgentLoop` 是唯一实现：发请求 → 解释 → 继续或收尾。差异全在策略对象里。

| 预设 | 步数 | 挂钟 | 工具 | 无进展检测 | 取消范围 |
|---|---|---|---|---|---|
| simple（主对话/压缩/判定） | 3 | 30s | 否 | 否 | 只取消自己 |
| complex（代理任务） | 25 | 120s | 是 | 连续相同一步即止 | 取消全部子请求 |

- **1 步 = 1 次模型请求**；simple 的 3 步是留给"输出不合契约时修一次"。
- 终止判定在请求**之前**按序检查：步数 → 挂钟 → 取消（撞阀不再多发一次）。
- 终态：`COMPLETED` / `CANCELLED` / `FAILED` / `ABORT_MAX_STEPS` / `ABORT_TIMEOUT` / `ABORT_NO_PROGRESS` / `PAUSED` / `EXPIRED`。超时来源不压平。
- 循环不认识玩家、播报、提示词，也不引用宿主类型；生产接线把"一次模型请求 + 有界等待"实现成步骤源。

## 3. simple 的输出契约

平时正常说人话；需要代办时在句末挂一个标签：

```text
这个问题让我去查一下。<delegate>如何进入暮色森林</delegate>
```

- 标签内是**控制信息**，标签外才是要说出口的话；
- 只认第一个标签；空标签/只有开标签 → 不委派，剥掉标记照常念；
- 标签不进 TTS、不进历史；没有"格式违约"概念，因此不存在"格式错误重试"。

**simple 不带工具**的理由：小模型工具成功率不稳、语音只需要一句话、工具 schema 会让前缀抖动、交互预算只有 1–2 步。它的能力来自**注入**（状态/记忆/知识）与**标签**（委托）。

## 4. 委派与票据

```text
simple 输出 <delegate>问题</delegate>
   → 登记票据（5s 内同查询复用）→ 回执"我查一下"
   → 代理任务在后台车道跑（25 步 / 120s）
   → 终态：事件线登记一条（必达）→ 历史追加一条 → 按门槛出声
```

| 项 | 规则 |
|---|---|
| 票据 id | 查询哈希前缀 + 序号，可预测 |
| 回放窗 | 5s；窗口外再问是**正常**行为 |
| 终态 | 恰好一条（A4）；"没查全"按失败投递 |
| 取消 | 取消父运行即取消其派生的全部子请求 |
| 暂停 | 预算耗尽但**有进展** → `PAUSED` + checkpoint；玩家说继续（同意词表精确匹配）→ 新票据带 `resumes=<旧taskId>` 续跑，最多 2 次，用尽 `EXPIRED` |
| 重试 | 技能失败静默重试**一次**；失败尝试不落任何东西 |

## 5. 三个通道

| 通道 | 载体 | 必达 | 受约束 |
|---|---|---|---|
| ① 登记 | 事件线（本地只追加） | 是 | 无 |
| ② 进 prompt | `<event>` 历史条目 | 是 | 历史容量与压缩 |
| ③ 出声 | TTS | 按门槛 | 播报门槛与队列 |

**登记与落历史永远发生，出声看门槛。** 玩家空闲立即说；正在对话则入队、本轮结束出队；失败/超时/取消**必须出声一句**；多条不合并（每条的指代不同）；会话结束丢队列、保留事件线。

措辞一律资源键；"我查一下"与"查到了…"是不同键；结论直接播正文，不二次改写。

## 6. 触发源

只有两个：**玩家输入**、**事件**（后台完成以事件上报）。禁止定时开场白、随机话题、模型自发起话题、无触发源的开口。判据只有一条：**这句话有没有触发源**。

## 7. 边界：什么不是工具

| 类 | 归属 |
|---|---|
| 状态查询（血量/坐标/背包） | 不设工具，状态块每轮注入（同一事实不允许两条路径） |
| 检索（知识/记忆） | 代理内部技能 |
| 世界改动（放置/给予/攻击） | 不存在（A1）；天枢无实体 |
| 元能力（取消/超时/步数） | 本地状态机，同步判定，给模型只会失控 |

## 8. 技能：自描述的执行单元

一个技能 = **描述符 + 执行器**，注册进 `DubheSkillRegistry`；代理读目录、按需调用。加技能不改循环。

| 描述符字段 | 含义 |
|---|---|
| `id` | 小写稳定标识，进诊断与 `skillsUsed` |
| `description` | 给代理看的一句话（≤200 字） |
| `inputSchema` | 参数 JSON Schema |
| `visibility` | 只有 `INTERNAL`（技能不对外发布，见《对外接口》） |
| `autonomy` | 技能自己声明的风险档；只收紧不放宽 |
| `budget` | 单次超时 + 步数上限（必填） |
| `reportSchema` | 必含 `outcome`，失败不能是空成功 |
| `lane` | `PLAYER` / `BACKGROUND` |

**代理目录 = 内部技能 + 宿主工具**（G60）：`DubheHostToolSkills` 把 `TianshuTools.catalog(caller)` 的每个工具适配成带 schema 的代理工具——工具名 `tianshu:recipe.query` → `tianshu_recipe_query`，调用走 `callJson`，返回 envelope 原样；按档位过滤，关闭的工具与 `body.*` 不进目录；每次委派重取。

## 9. 技能包（SKILL.md + references）

技能的**文件形态**（`com.rheinmetal.tianshu.dubhe.skills/`），遵循 Agent Skills 规范：

```
<skill>/
├── SKILL.md          # 必填：frontmatter（name/description/allowed-tools/metadata）+ 正文
└── references/       # 可选：一层 .md，按需读
```

| 级 | 加载什么 | 何时 |
|---|---|---|
| 1 | `name` + `description` | 常驻目录（约百 token） |
| 2 | 正文 | 模型决定用这个技能时 |
| 3 | `references/*.md` | 需要细节时按路径读 |

写作要求（否则模型读完不会用）：

1. **调用格式**：工具 id + 参数对象、成功/失败返回形状；
2. **决策表**：玩家这句话 → 先调哪个工具 → 看哪个字段；
3. **例子跟着功能走**：每篇 reference 自带该主题的例子，入口只放**一个**完整往返；不要单独建 `examples.md`；
4. **references 按稳定轴分**：平台工具按档位（read-only / conservative / full），不按工具逐个拆；
5. **失败与确认**：写操作何时先确认、失败怎么说。

解析复用平台实现 `FrontMatter` / `SkillFileProvider`（`tianshu-api`），天枢只保留清单与适配器（`skills/index.json` + `DubheSkillPackageResourceLoader` + `DubheSkillPackageAdapter`）。

当前内置包：`work`（干活策略）、`diplomacy`（外交，含 `relay` reference）。

## 10. 平台的公共技能

三档与工具说明由**舟楫**注册成公共技能 `tianshu:minecraft-tools`（入口 + 按档位的三篇 references）。模组运行时用 `tianshu:capability.read` 读它，**不在本地存副本**；天枢把它包成内部技能 `read-shared-skill`，`work` 第 0 步先读。

## 11. 验收

1. 每票据恰好一条终态（A4）；2. simple 请求无工具（A3）；3. 报告只有三字段；4. 5s 内同查询只有一个运行（A7）；5. 撞步数/超时/取消分别归因；6. 标签不进 TTS 与历史；7. 无触发源时完全静默；8. 技能包只加载元数据到目录，正文与 references 按需读。
