## 1. 一键门禁（改完必跑）

```bash
./gradlew :tianshu-api:test :tianshu-core:test :tianshu-client:test \
  verifyFeatureIsolation verifyFeatureOptionalDependencies verifyClientMediaWiring \
  verifyServerToolRegistration verifyHostHasNoFeatureDependency verifyCommonAdapterNeutral \
  verifyNoPlatformImport verifyUniversalModuleJars verifyAdapterProperties \
  verifyAdapterMatrixCoverage verifyProtocolVersionSingleSource verifySettingsRenderersCoverOptionEntries \
  verifyEveryToolHasADocument
```

**不要用 `./gradlew check`**：它会带上听澜的既有抖动用例（`IaModuleProtocolFlowTest` 的 `await` 超时），
与本模块改动无关。

游戏内那一层用 `:tianshu-adapter:1.21.1-neoforge:runGameTestServer`，
**判据是日志里的 `All N required tests passed`**——这个任务的退出码不反映游戏内崩溃。

## 2. 验收台（`tianshu-lab`）

入口两个：无人值守（`-PtianshuLabAcceptance=1` / `=world`）与游戏内（设置 →【听澜】仲裁测试台 →「运行平台验收」）。
证据两处同源：`run/tianshu-lab/acceptance-<时间戳>.json` 与 `run/logs/tianshu-diagnostics.log` 的 `acceptance.run` 事件。

三条硬规矩：

1. 用例 id 与文档同源；覆盖声明与未覆盖清单都印在报告里；
2. 跑不了的显式 SKIP 并写原因，不许静默通过；
3. **`SELF-CHECK-1` 必须失败**，它若 PASS，整轮 `accepted=false`——验收台自己必须能证明会失败。

## 3. 四层"可用"

「可用」＝下面四层都有**当轮**证据，跑不了的写明原因。

| 层 | 跑什么 | 判据 |
|---|---|---|
| A 门禁 | §1 的命令 | `BUILD SUCCESSFUL`，输出里没有 `FAILED` |
| B 验收台 | 每个加载器各一次，**必须进世界**（模块装配发生在世界会话里） | 报告 `accepted=true`、`selfCheckHeld=true`；只有故意失败的 `SELF-CHECK-1` 记为 FAIL；SKIP 带原因 |
| C 专用服与联机 | 起服 + 进服（`ceiling=full` 与相关开关打开）；单侧安装（原版客户端进服 / 服务端原版时远端工具不出现） | 见 §4 待实机项 |
| D 人工项 | 设置页改一项重进、命令非法参数报码、切 `en_us` 无缺键、被拒调用在诊断日志里有 `code`/`message` | 与界面提示一致 |

实机前用 `-PquickPlayWorld=<世界名>` 让 adapter 的 `runClient` 直接进世界——没进世界，工具层就没有东西可测。

**写工具的人工验收判据**是"状态没变 + 码对得上"：开关关着回 `DISABLED`、非 OP 回 `NO_PERMISSION`、
连点回 `RATE_LIMITED`、这一端没有服务端回 `UNSUPPORTED_SIDE`，四种情况下世界都必须没变。

联机协议四条：未装舟楫的客户端可进服且保留本地功能；服务端装、客户端不装可进服且不发送无接收通道的包；
双端都装且服务端在目录里登记了这些工具时启用远程工具，否则保留本地功能；声明自定义实体的内容模组缺装则拒绝连接。

## 4. 证据清单

### 4.1 当轮拿到的（2026-11-26，`b2d6c6f2` 之后）

| 环境 | 结果 |
|---|---|
| NeoForge 单机、**默认安装**（`ceiling=conservative`、14 个开关全关） | 52 PASS / 4 SKIP / 1 FAIL |
| NeoForge 单机、`ceiling=full`、14 个开关全关 | 53 PASS / 2 SKIP / 1 FAIL |
| NeoForge 单机、`ceiling=full`、14 个开关全开 | 56 PASS / 1 SKIP / 1 FAIL |
| Fabric 单机、`ceiling=full`、14 个开关全开 | 54 PASS / 1 SKIP / 1 FAIL |
| NeoForge 专用服 + 客户端联机（`runServer` + `quickPlayServer`） | 51 PASS / 6 SKIP / 1 FAIL |
| **无舟楫客户端单侧安装**：服务端 `runServer -PfeatureMods=`（只装内核，不带验收台），客户端用 `D:\Minecraft\.minecraft\versions\Tianshu`（NeoForge 1.21.1、`mods/` 为空） | 进服成功：服务端 `VanillaTest joined the game`，两端 0 条 payload / ERROR，客户端的暂停菜单里**没有**「天枢控制台」（确实没装舟楫） |
| **身体存档重载**：验收台在世界里生成一具身体并把 id 写进 `tianshu-lab/persisted-body.txt` → 保存并退到标题（`region/*.mca` 与 `level.dat` 都更新）→ 重开同一世界再跑一轮 | `ACC-BDY-8` 从 SKIP 转 PASS：`body 0bee68f0-6eba-46e2-89b8-8ffff855bacc came back from the save` |
| NeoForge 单机、**一个进程三个会话**（世界 A → 标题 → 世界 B → 标题 → 回 A） | 工具层每次登录都可用（见下） |

- 那个 FAIL 永远是 `SELF-CHECK-1`（它必须失败），`accepted=true`、`selfCheckHeld=true` 都是当轮读出来的值；
- **玩家辅助三档与服务端动作开关**。以下 `ACC-ACT-*` 记录验证玩家侧管理工具。NPC 档位独立性由 `ToolAutonomyTest` 验证；`BodySequenceToolTest` 验证原生飞行、原生瞬移和额外瞬移受限时停止后续步骤。此处的实机记录仅覆盖玩家工具。默认安装那一轮四个 `ACC-ACT-*` 全部按规矩跳过，原因是 `ceiling` 低于 `full`——档位在开关之前就把作弊类动作挡住了；档位放开、开关还关着那一轮，`ACC-ACT-2` 才拿到 `DISABLED`；
- **14 个服务端动作逐个验过**：`ACC-ACT-5` 一次只开一个开关、14×14 逐对检查，每个动作只跟自己的开关走；配置键名与工具 id 的对应（`set_time`→`server.time`、`broadcast`→`server.broadcast`）在 `ServerActionTools` 与 `ServerActionConfig.switchFor` 里逐个对过。`ACC-ACT-4` 在开关全开时 10 个真的执行、4 个被自己的校验拒（空手附魔、编造的实体 id 之类）；全关时 0 执行、14 个全被各自的开关拒；
- **单侧安装**：发布 jar `tianshu_ferry-0.1.0.jar` 里没有 lab（966 个条目、lab 相关 0 个，`neoforge.mods.toml` 只声明 `tianshu_ferry`）；开发运行默认会把验收台当额外 mod 装进去（`devRunFeatureEdges` 的 `root`/`adapter` → `lab`），所以测单侧安装必须显式 `-PfeatureMods=` 只要内核。按这个跑的那一轮，没装任何模组的客户端进服正常，舟楫自己的 payload 注册器是 `.optional()`；
- **一个进程三个会话**（世界 A → 标题 → 世界 B → 标题 → 回 A）：三次 `platform.world.login/logout` 都在同一进程里，世界 B 与回到 A 之后各跑一次工具控制台，`tool.console` 两次都是 `ok=true`；`ClientTools` 的一次性注册守卫让第二次登录不重复注册，日志里没有注册冲突；
- **工具总体接线**：`ACC-ALL-1` 扫目录里的每个工具行、空参各调一次，`accepted` 轮次都是"56 个全部给出信封，无异常无超时"。注意它只证明接线：空参被 schema 拒的占多数，真正执行的只有 8 个；
- 报告在 `run/tianshu-lab/acceptance-<时间戳>.json`，两个加载器各自一份。

## 5. 门禁的教训

- 13 个 `verify*` 里曾有 4 个在空转（路径写死、`inputs.dir` 不展开目录）——**"通过"只有在能证明它会失败时才算数**。
- **写门禁自己的三个坑**：Groovy 插值出来的 `GString` 拿去 `contains` 恒为 false（先 `.toString()`）；
  用正则啃 JSON 会在 `${...}` 的 `}` 处截断（用 `JsonSlurper`）；`file()` 写在 `doLast` 里会破坏配置缓存。
- **会静默吞测试**：`sourceSets.test` 指向一个不存在的目录时，Gradle 静默忽略——曾经导致整条版本线的
  共享层单测从未运行，每个包只跑了 2/5 个用例。新增 srcDir 之后要确认测试数量变了。
- **两个门禁是"看得穿"的**：`verifyHostHasNoFeatureDependency` 查 Gradle 项目依赖图（不是文本搜索）；
  `verifyNoPlatformImport` 扫编译产物的常量池（`net/minecraft/`、`net/neoforged/`、`org/lwjgl/`、
  `com/mojang/blaze3d/`），注释与全限定名都绕不过。宿主词汇清洁的判据是"命中数为 0"。
- **模块守卫要传加载器 mod id，不是协议模块 id**：`InstalledMods` 传 `tianshu_echo` 才对，
  传 `module.tts` 在生产环境永远判为"未安装"。
- 盲区仍在：本地文件系统故障、并发正确性、跨版本 API 存在性（后者要靠离线 API 签名索引）。
- 验收台抓出来的 bug 比人工点出来的多，所以新功能先加用例，再补人工项。
