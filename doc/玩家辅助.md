# 玩家辅助

> 两个功能方向之一（[职责边界](职责边界.md) §2 方向 4）。替玩家做他用手能做的事，**以该玩家本人的身份执行**。
> 工具契约、档位规则、共享与门禁是两个功能方向共用的，见 [智能体能力中心](智能体能力中心.md)。
> 实体侧的工具在 [实体操作](实体操作.md)——两个方向不共用 id，也不共用一份说明书。

## 1. 这个方向管什么

**管**：合成、操作工作方块、容器搬运、方块交互（按钮 / 拉杆 / 门）、读状态、客户端偏好。

**不管**：玩家的两只手。放方块、拆方块、用手里的物品这三件事基座不提供玩家侧工具——
那是玩家自己在干的事，替它做就是把模组变成外挂。要做就让**身体**去做（[实体操作](实体操作.md)）。

判据是那句老话：**这件事玩家自己用手能不能做**。能做，才轮到基座代劳。

## 2. 工具清单（35）

`minecraft:` 命名空间下 35 个，其中 14 个是服务端动作。每份详细说明在
`skills/player-tools/references/<id>.md`，用 `capability.read` 按 id 读。

档位就是那三个（[职责边界](职责边界.md) §3）。按档位从低到高排：

| id | 做什么 | 档位 | 默认 | 权限 |
|---|---|---|---|---|
| `tag.query` | 查物品或方块的标签 | `READ_ONLY` | 开 | EVERYONE |
| `inventory.inspect` | 列自己背包里非空的槽位 | `READ_ONLY` | 开 | EVERYONE |
| `container.inspect` | 读当前打开的容器内容与槽位索引 | `READ_ONLY` | 开 | EVERYONE |
| `recipe.query` | 按产物 id 查能做出它的配方 | `READ_ONLY` | 开 | EVERYONE |
| `loot.query` | 查方块或实体的掉落表 | `READ_ONLY` | 开 | EVERYONE |
| `block.inspect` | 读一个方块：id、状态、容器内容、能量，不打开界面 | `READ_ONLY` | 开 | EVERYONE |
| `item.inspect` | 读一个槽位的物品：数量、耐久、附魔、自定义名 | `READ_ONLY` | 开 | EVERYONE |
| `craft.available` | 列自己现在能做的配方，并标出哪些要工作台 | `READ_ONLY` | 开 | EVERYONE |
| `world.info` | 读所在世界的维度、群系、时间、天气、难度、光照 | `READ_ONLY` | 开 | EVERYONE |
| `world.locate` | 在本维度已完整生成的区块中查结构起点或采样群系，包括已卸载的存档区块。水平半径默认 256 格、上限 512 格 | `READ_ONLY` | 开 | EVERYONE |
| `world.survey` | 世界勘探，同一半径内也可查从未生成的地形 | `READ_ONLY` | 开 | EVERYONE |
| `client.audio.list` | 列客户端音量通道与各自百分比 | `CONSERVATIVE` | 开 | EVERYONE |
| `client.audio.set` | 把一个音量通道设成 0..100 | `CONSERVATIVE` | 开 | EVERYONE |
| `client.pack.list` | 列已装资源包、显示名与启用状态 | `CONSERVATIVE` | 开 | EVERYONE |
| `client.pack.set` | 按 id 启用/禁用一个资源包并应用（会重载资源） | `CONSERVATIVE` | 开 | EVERYONE |
| `server.say` | 以自己的身份在聊天里说一句 | `CONSERVATIVE` | 开 | EVERYONE |
| `block.interact` | 按钮、拉杆、门、活板门、栅栏门——相当于右键一下 | `CONSERVATIVE` | 开 | EVERYONE |
| `block.machine` | 操作炉子家族：投燃料、投原料、取产物 | `CONSERVATIVE` | 开 | EVERYONE |
| `container.transfer` | 在容器槽位与自己背包槽位之间搬物品 | `CONSERVATIVE` | 开 | EVERYONE |
| `craft.recipe` | 按配方 id 合成一次，材料从自己背包扣 | `CONSERVATIVE` | 开 | EVERYONE |
| `command.run` | 以自己身份执行一条命令：先回一次性令牌，operator 批准后才执行 | `FULL` | 关 | EVERYONE |
| `server.teleport` | 传送到当前维度的坐标 | `FULL` | 关 | OPERATOR |
| `server.weather` | 设天气：clear / rain / thunder | `FULL` | 关 | OPERATOR |
| `server.time` | 设时间：day / noon / night / midnight / ticks:n | `FULL` | 关 | OPERATOR |
| `server.give` | 按注册 id 给物品，溢出掉在脚下 | `FULL` | 关 | OPERATOR |
| `server.spawn_entity` | 按注册 id 在玩家位置生成实体 | `FULL` | 关 | OPERATOR |
| `server.broadcast` | 向全服发一条系统公告（等同 /say） | `FULL` | 关 | OPERATOR |
| `server.gamemode` | 设自己的游戏模式 | `FULL` | 关 | OPERATOR |
| `server.effect` | 给状态效果，或 clear 清空 | `FULL` | 关 | OPERATOR |
| `server.xp` | 增减经验等级 | `FULL` | 关 | OPERATOR |
| `server.setblock` | 在绝对坐标放一个方块 | `FULL` | 关 | OPERATOR |
| `server.kill` | 按 id 清除所在世界的一个实体 | `FULL` | 关 | OPERATOR |
| `server.enchant` | 给主手物品附魔 | `FULL` | 关 | OPERATOR |
| `server.difficulty` | 设服务器难度 | `FULL` | 关 | OPERATOR |
| `server.gamerule` | 设白名单里的一条游戏规则 | `FULL` | 关 | OPERATOR |

`server.say` 是 `CONSERVATIVE` 而不是 `FULL`：任何玩家都能在聊天里说话，它不是作弊。
`command.run` 是 `FULL` 但不是 `OPERATOR`：令牌必须有人批，而批的人才是 op。

**已知缺口**：14 个服务端动作只有 `description` 与 schema，没有逐份 `references/`——
`verifyEveryToolHasADocument` 只扫 `ToolId.of("…","…")` 字面量，而这 14 个 id 是从 `ServerActions` 的
whitelist 表拼出来的，门禁看不见它们。补齐这 13 份说明（`server.xp` 已有）是待办。

## 3. 档位与开关

三道门（[智能体能力中心](智能体能力中心.md) §3）在这个方向上这样落：

| 门 | 这里的样子 |
|---|---|
| 档位 | 读 `READ_ONLY`、生存写 `CONSERVATIVE`、作弊与 `command.run` `FULL` |
| 权限 | 全部 `EVERYONE`，除了 14 个服务端动作要 `OPERATOR` |
| 开关 | **只有 `FULL` 档有开关**。`READ_ONLY` / `CONSERVATIVE` 没有开关，档位就是闸门 |

所以 `ceiling = conservative` 的服务器上，合成、搬物品、操作工作方块、按按钮**直接可用**，
不需要先去配置文件里打开什么。要收紧就把 `ceiling` 调低，错误码是 `NO_PERMISSION`。

原版权限、领地规则、游戏模式照常拦截——**动作以该玩家身份执行**，基座不绕过任何一层。

## 4. 说明书与技能

- 技能 `minecraft:player-tools`，随 jar 发布在 `tianshu/skills/player-tools/`；
- 约定（信封、档位、失败怎么读）写在它的 `SKILL.md`；
- 每个工具一份 `references/<id>.md`，四段模板见 [技能撰写规范](技能撰写规范.md) §4。

## 5. 加一个工具

1. 在 `tianshu-client/.../tool/` 写一个 `TianshuTool`，`category()` 按它碰什么选（读 / 写世界 / 本地）；
2. `requiredAutonomy()` 一般不用覆盖：`SERVER_WRITE` 自动是 `CONSERVATIVE`，其余 `READ_ONLY`。
   差一档才显式写（`client.audio.set` 改客户端但仍算 `CONSERVATIVE`）；
3. 生存动作要覆盖成 `EVERYONE` + `withEnabledByDefault(true)`——不做这一步，它会继承 `SERVER_WRITE`
   的 operator 要求，玩家会被莫名拒绝（`SurvivalToolPermissionTest` 就是拦这个的）；
4. `ClientTools` 里 `declare` 一份，适配层在服务器侧 `registrations.tool(...)` 注册；
5. 写 `references/<id>.md`——`verifyEveryToolHasADocument` 会数；
6. 如果它是世界操作且有实体侧对等物，把逻辑放在 `*Ops` 里，两侧只适配参数（见 [实体操作](实体操作.md) §5）。
