## 一、A 类：扩展性

### A1. 诊断只认 5 个写死的模块 id

- **现在**：`ClientDiagnosticPolicy` 用 `Set.of(ASR, IA, AX, LLM, TTS)` 决定一条诊断事件收不收；不在名单里的模块（包括映迹）事件**直接丢弃**，日志和聊天进度都到不了。
- **为什么疼**：新模块装上了却"看不见"，没有任何报错；排查问题时也没有线索。
- **怎么改**：把"谁能写诊断"从宿主搬到模块自己。照 `HudHost` / `KeyBindings` 的样子加一个端口，模块装配时注册自己的 moduleId（以及诊断码 → 文案/级别）。`ClientDiagnosticRouter` 只负责路由与限流。
- **最小步**：先把白名单换成"任何已注册模块 id"，再把聊天文案目录化（见 A2）。
- **改动面**：`tianshu-client` 的 `ClientDiagnosticPolicy` / `ClientDiagnosticRouter` + 装配处 1 行。默认 debug 关闭时行为不变。

### A2. 聊天进度按功能事件码 switch

- **现在**：`ClientDiagnosticProgress` 里对 `RECOGNITION_COMPLETE`、`LLM_SUBMITTED`、`SYNTHESIS_COMPLETED` 这类**功能业务事件码**做 switch，宿主认识听澜/织言/回响的语义。
- **怎么改**：与 A1 合并——模块注册"码 → 文案"，宿主查表，不再认识任何业务码。
- **改动面**：同 A1。

### A3. 语言门禁的模块名单

- **现在**：`ModuleStatusKeys` 里写死 5 个模块 id（`LIFECYCLE_MODULES`），只用于语言测试扫描；新模块不在名单里就漏扫，缺 en/zh 也没人拦。
- **怎么改**：删掉名单，测试改成扫描所有 `src/main/lang` 分片的键求并集。
- **改动面**：`tianshu-api` 1 个类 + 1 个测试。

### A4. 内核里还留着四个老模块的词汇

- **现在**：`ProtocolBootstrap` 替听澜/织言/回响登记 **7 个 topic**；`PayloadType` 常量表里有 **25 个功能名**（`ASR_*` / `IR_RESULT` / `LLM_*` / `TTS_*` / `DIALOGUE_*` / `AX_WORLD_EVENT`）。映迹已经做到自注册，这四个没有。
- **为什么疼**：删/改任一模块都要改 `tianshu-api`（冻结契约）；"装谁是谁"在最底层不成立；新人读代码会以为载荷该进 api。
- **怎么改**：照映迹的范本——每个模块在自己的 `provider.contribute()` 里 `registerTopic(...)`、`PayloadType.of(name, cls)`；内核只留 `SYSTEM.RUNTIME_INTERRUPT` / `MODULE.STATUS` / `WORLD_EVENT` 与通用基类名字。
- **顺序**：先搬 topic（低风险，7 行），再降 `PayloadType` 常量（改名要同步所有引用，放最后）。
- **改动面**：4 个功能模块各 1 个协议适配类 + `ProtocolBootstrap`。协议测试多，改完要全量回归。

### A5. API 没有版本，改名等于静默破坏

- **现在**：`CoreCapabilityProbe` 的 `apiVersion` 恒为 `"1"`、`coreVersion` 恒为 `"tianshu-core"`；`PayloadType` 的身份就是名字，改名在加载期**没有任何提示**。
- **怎么改**：构建时把版本号写进产物（`tianshu-build.properties` 或生成的常量），`probe().apiVersion` 读它；`PayloadType` 支持"别名 + 弃用"；Envelope 加一个 payload schema 版本字段，旧版本仍可路由并记一条弃用诊断。
- **性质**：这是设计题，建议先写一页 RFC 再动手，不要直接改。

### A6. 加一个 HUD 视觉家族要改宿主

- **现在**：`HudProgram` 枚举只有两个值；`NeoForgeHudSurface` 里写死 8 个 uniform 名（`Time/Intensity/.../Morph`）。加第三个视觉必须同时改 `tianshu-api` 与 adapter。
- **怎么改**：模块声明 shader 时**同时给出 uniform 描述**（名字 + 类型），宿主按描述设置；`HudProgram` 从封闭枚举改成模块自带的 id。
- **改动面**：api 的 `HudSurface` / `HudShaderParams` / `HudProgram` + adapter 的 surface + 映迹的视觉参数。改动集中，但要和映迹一起动。

### A7. 个别端口的形状带业务味（低优先）

- `ClientFilePicker.chooseWavFile`：一个 TTS 音色导入的形状，将来别的文件选择要改 api。
- `KeyBindings.declare(id, int 默认键码, 分类)`：通用模块被迫知道 GLFW 键码。
- **怎么改**：文件选择器改成 `chooseFile(过滤器)`；键位改成抽象键描述由 adapter 映射。现在各只有一个使用者，不急。

## 二、B 类：小债（本轮已清）

以下 7 项已改完，`build` 全绿（1,504 测试 / 323 套件）：

| # | 原本的问题 | 现在的做法 |
|---|---|---|
| B1 | `RuntimeGates` 静态输入门登出不清，可能跨会话残留、吞掉下一局的按键 | `onWorldLogout` 里调一次 `RuntimeGates.clear()`。**没有**动摇 `InputSignals`/`TickSignals`：`AXEventClock` 是静态订阅，清了会永久失效 |
| B2 | 设置页每帧重复算 layout、重复算裁剪区、滚动条每帧新建 `ScrollState` | 布局按窗口尺寸缓存（`pageLayout()`），裁剪矩形按区域缓存并在重建/改尺寸时失效；滚动条改用整数直接算 |
| B3 | 死信每次 `add` 用 `Deque.size()`（O(n) 遍历） | 换成 `AtomicInteger` 计数，超容量再 `pollLast` |
| B4 | 配置临时文件固定 `<file>.tmp`，`Files.move` 不是原子的，并发/断电可能互相踩 | `Files.createTempFile` 唯一临时名 + `ATOMIC_MOVE`（不支持则回退 `REPLACE_EXISTING`），失败时删除临时文件 |
| B5 | 断点续传元数据损坏时静默重下整包 | 文件存在但解析失败时写一条 `MODEL_DOWNLOAD_RESUME_METADATA_UNREADABLE` warn，仍按原行为重下 |
| B6 | 关服最后一条日志永远写不进（先关诊断再写） | 由 router 在关闭前写最后一条 `diagnostic.log_closed`；删掉 bootstrap 里那条永远丢失的 `shutdown_completed`。保留"从未写过的 router 不创建日志文件"的既有约定 |
| B7 | 诊断轮转参数在 router 与 bootstrap 各写一份 | 新增 3 参构造器，参数只留在 router/writer 内部 |

剩下的两项：

| # | 为什么没做 |
|---|---|
| B8 服务端每个事实发一个包 | 合并会改变"事实到达时间"的语义，需要先跟辅星的事件窗口确认；已并入 C2，不在这批里瞎改 |
| B9 文件选择器退出时可能拖住进程 | 代码里已有 `pending.cancel` → `cancelSelection` 的路径，属"待实机确认"，不是已知缺陷；开一次音色导入再退出即可验证 |
