## 一、A 类：扩展性

**本轮已完成**（`build` 全绿，1,512 测试 / 324 套件）：

- **A1 诊断门**：`ClientDiagnosticPolicy` 不再持有 5 个写死的 id。判定时向会话要"已装配模块 + 已声明集成模块"
  （`TianshuCoreManager.managedModules()` / `integrationModuleIds()`），新模块装上即可见；debug 开关保留。
- **A2 聊天进度**：`ClientPorts` 新增 `diagnosticChat`（`DiagnosticChatCatalogue`）。模块在 provider 的
  `contribute()` 里注册「码 → 文案键 + 每个占位符的属性候选」，`ClientDiagnosticProgress` 的 switch 整个删掉，
  只做查表与失败兜底。五个模块各自注册（听澜 2、思衡 2、辅星 1、织言 2、回响 1）；文案键仍在原分片，
  渲染结果与改前逐字一致。唯一没有生产者的 `LLM_SUBMITTED` 不再有映射——它本来就没有发布方。
- **A3 语言名单**：`ModuleStatusKeys` 不再自持 `LIFECYCLE_MODULES`，改引用
  `ProtocolModuleIds.LIFECYCLE_MODULES`——要扩只有一处。
- **A4 功能词汇下沉**：7 个功能 topic 改由各自模块在 `register()` 里 `registerOwnedTopics(...)` 登记
  （TopicDescriptor 三个参数逐字保留）；`ProtocolBootstrap` 只剩三个平台 topic，`ProtocolTopics` 也只剩
  `SYSTEM.RUNTIME_INTERRUPT` / `MODULE.STATUS` / `WORLD_EVENT`——功能 topic 名已搬到各模块的
  `IntakeTopics` / `IaTopics` / `LlmTopics` / `TtsTopics`（照 `PresenceTopics` 的样子）。25 个 `PayloadType`
  功能常量改为模块侧 `PayloadType.of("NAME")` 并删除（132 处代码引用 + 42 处文档），另同步 52 处 topic 名。
- **A5 版本如实上报**：adapter 构建把 `version` 与由 MAJOR 推导的 `apiVersion` 写进 `tianshu-build.properties`，`CoreCapabilityProbe` 报真值（此前是 `"tianshu-core"` / `"1"` 占位）。
  别名兼容与 payload schema 版本**未实现**：当前没有外部消费者、所有模块同仓同构建，属于过度设计；按 `doc/architecture/API兼容策略.md` 在 1.0.0 前一次性补上。
- **A6 HUD 家族**：见下方 A6 小节（模块自带 program 与 uniform，宿主零名单）。
- **A7 端口形状**：`ClientFilePicker.chooseFile(title, extension, filterLabel)`；`KeyBindings.declare(...,
  String defaultKeyName, ...)` 由平台解析键名，未知名字留空并记诊断——模块不再需要知道 GLFW 键码。
- **词汇清洁（收口）**：`ProtocolCapabilities` 的 14 个功能能力名搬到
  `LlmCapabilities` / `TtsCapabilities` / `IaCapabilities` / `AxCapabilities`；`ProtocolModuleIds` 只剩
  `PLATFORM_ONNX_RUNTIME` 与 `PLATFORM_AUDIO`，各模块用自己的 `MODULE_ID` 字面量、跨模块引用用字符串 id；
  `ExecutionLane` 的 `TTS_*` / `ASR_*` 改为 `AUDIO_*`；根语言键 `ax.input.*` 改为
  `tianshu.gui.text_input.*`；宿主注释里的功能名一并清掉。宿主 main 词汇扫描（功能 import / 能力 / 模块 id /
  功能 lane / 字符串 id / `ax.` 键 / 功能中英文名）命中 **0**。
- **文案归属**：`ClientUiHost` 新增 `setTextInputLabels(title, hint)`（默认空实现），辅星在装配时注册
  `tianshu.gui.ax.text_input.*`；宿主保留中性兜底键 `tianshu.gui.text_input.*`。文案是语言键，切换语言
  会重新解析；辅星未安装时显示中性文案。

**仍待做**：

### A6. HUD 视觉家族（已完成，留档）

- **原问题**：`HudProgram` 是封闭枚举；`NeoForgeHudSurface` 写死 uniform 名。加第三个视觉或新 uniform 要改 api 与 adapter。
- **现在的做法**：`HudProgram` 改成模块拥有的 `HudProgramId` + `HudProgram<P>` + `HudUniformSink`。模块声明自己的
  program id 与 shader 资产，`HudProgram.bind` 在模块侧写自己的 uniform；宿主只编译、绘制和失败降级，不认识
  uniform 名，也没有固定参数表。新增/改名 uniform、增加参数或预设都不需要更新北辰。
- **验证**：映迹的 `PresenceHudProgram` / `PresenceHudShaderParams` 承载全部 uniform 契约；presence 与 adapter
  测试通过。

## 二、B 类：小债（本轮已清）

以下 7 项已改完，`build` 全绿（1,529 测试 / 330 套件）：

| # | 原本的问题 | 现在的做法 |
|---|---|---|
| B1 | `RuntimeGates` 静态输入门登出不清，可能跨会话残留、吞掉下一局的按键 | `onWorldLogout` 里调一次 `RuntimeGates.clear()`。**没有**动摇 `InputSignals`/`TickSignals`：`AXEventClock` 是静态订阅，清了会永久失效 |
| B2 | 设置页每帧重复算 layout、重复算裁剪区、滚动条每帧新建 `ScrollState` | 布局按窗口尺寸缓存（`pageLayout()`），裁剪矩形按区域缓存并在重建/改尺寸时失效；滚动条改用整数直接算 |
| B3 | 死信每次 `add` 用 `Deque.size()`（O(n) 遍历） | 换成 `AtomicInteger` 计数，超容量再 `pollLast` |
| B4 | 配置临时文件固定 `<file>.tmp`，`Files.move` 不是原子的，并发/断电可能互相踩 | `Files.createTempFile` 唯一临时名 + `ATOMIC_MOVE`（不支持则回退 `REPLACE_EXISTING`），失败时删除临时文件 |
| B5 | 断点续传元数据损坏时静默重下整包 | 文件存在但解析失败时写一条 `MODEL_DOWNLOAD_RESUME_METADATA_UNREADABLE` warn，仍按原行为重下 |
| B6 | 关服最后一条日志永远写不进（先关诊断再写） | 由 router 在关闭前写最后一条 `diagnostic.log_closed`；删掉 bootstrap 里那条永远丢失的 `shutdown_completed`。保留"从未写过的 router 不创建日志文件"的既有约定 |
| B7 | 诊断轮转参数在 router 与 bootstrap 各写一份 | 新增 3 参构造器，参数只留在 router/writer 内部 |

剩下的两项：

| # | 为什么没做 |
|---|---|
| B8 服务端每个事实发一个包 | 合并会改变"事实到达时间"的语义，需要先跟辅星的事件窗口确认；已并入 C2，不在这批里瞎改 |
| B9 文件选择器退出时可能拖住进程 | 代码里已有 `pending.cancel` → `cancelSelection` 的路径，属"待实机确认"，不是已知缺陷；开一次音色导入再退出即可验证 |

## 三、C 类：设计题（要拍板）

- **C1 玩家可见通道（已完成，流式留给模块 HUD）**：宿主提供本地表现原语 `ClientPresentationPort`（chat/actionBar/toast/title/playSound），辅星用 `AuxiliumChatOutput` 把最终回答送到 `chat`、失败用 `tianshu.gui.ax.output.failed`。流式输出不做在聊天栏（会刷屏），由辅星自己的 `HudLayer` 逐帧绘制。
- **C2 服务端事实合并（已完成）**：传输层改为**按 tick 批量**：服务端采集器缓存本 tick 的事实，tick 末 flush 成一个 `GameFactBatchPacket`（列表按生产顺序、每条保留自己的 `occurredAtMillis`，超过 64 条拆包）；接收端在同一个客户端任务里按序逐条 publish。语义合并仍只在映迹的接收窗口，映迹与消费者零改动。协议版本从 1 升到 2。
- **C3 门禁升级（已完成，行为级测试保留源码断言）**：`verifyHostHasNoFeatureDependency` 现在直接检查 Gradle 项目依赖图（构建脚本里的字符串扫描仍留作护栏，可被变量/插件绕过的问题由依赖图兜住）；`verifyNoPlatformImport` 从"逐行读 import"改为扫描各模块编译产物的常量池（`net/minecraft/`、`net/neoforged/`、`org/lwjgl/`、`com/mojang/blaze3d/`），注释和全限定名都绕不过。`NeoForgeMainThreadBoundaryTest` 这类"方法体里不能出现某调用"的行为断言仍是源码级，属于护栏而不是依赖边界。
- **C4 世界标识（已完成）**：本地世界的稳定标识从「游戏目录 + 关卡**显示名**」改为「游戏目录 + **存档目录名**」（`getWorldPath(LevelResource.ROOT)` 的文件名），显示名仍作为玩家可见标签。两个同名存档不再共享身份；因为尚未上线、没有存量记忆要迁移，若本地有旧存档的调试记忆会被视为新世界。

暂停菜单入口的几何也算验收项，日志里可直接查：`neoforge.pause.console_slot x=325 y=212 width=204 grid=6 wide=3 shifted=2`（与网格同左缘、同宽，占网格正下方那一行，并把「模组」「保存并退出」整体下移一行）。

**本轮实机抓到并修掉的两个真问题**（编译期发现不了）：

1. `NeoForgeEnvironment` 只实现了 `bindLogs`，没覆写 `IGameEnvironment.logs()`（接口默认返回 `LogSink.NOOP`）——平台上所有 `env.logs().info(...)` 被静默丢弃，装配摘要那行从来没落过盘。现已覆写，并由 `NeoForgeEnvironmentBoundaryTest` 守住。
2. 设置页「关闭」直接 `setScreen(null)`，从暂停菜单进去关掉后直接回到世界、跳过暂停菜单；现改为返回打开它的那个屏幕（`TianshuSettingsModule.openScreen()` 记住当前屏幕）。

仍未自动化：文字键对话一轮、锚点编辑保存、切麦克风、Esc 确认框、B9 文件选择器退出——要么需要听请求、要么需要麦克风，留给人工。

## 六、调试输出与日志（2026-10-30 收口）

**模块决定"是什么、长什么样"，宿主只决定"送到哪"**：

| 谁 | 决定什么 |
|---|---|
| 模块 | 事件 code、严重度（`TRACE`/`DEBUG`/`INFO`/`WARN`/`ERROR`）、字段、隐私级别；要不要让玩家看见——装配期把 code 注册进 `DiagnosticChatCatalogue`，聊天栏文案与参数候选都由模块给；自由文本日志行由模块经 `env.logs()` 自己写 |
| 宿主 | 路由与闸门：日志恒收 `WARN`/`ERROR`；`TRACE`/`DEBUG`/`INFO` 只在调试开关打开时落盘；聊天栏只在开关打开**且**模块注册过该 code 时出现 |

- 正式包 `TianshuBuildProfile.debugBuild()` 为 false ⇒ `ClientConfig.isDebugEnabled()` 恒 false ⇒ 开关按钮都不创建，**只产日志**，不可能产游戏内调试信息。
- 映迹「调试管线」一节从"关掉时变灰"改为"关掉时整节消失"（`enabled` 与 `visible` 都传开关），否则正式包仍会显示实时管线内容。
- 删除了无闸门的 `IGameEnvironment.displayMessageToPlayer`（主代码零调用，但它是任意写聊天栏的通道，留着就是 release 的漏水点）。
- `ClientDiagnosticPolicy` 只负责"这个模块属于本会话吗"，调试开关移到 `ClientDiagnosticRouter` 的输出路由——两者分开后，关掉游戏内提示不会连日志一起静音。
