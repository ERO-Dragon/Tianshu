## 1. 这个方向管什么

**管**：让一具身体走、看、挖、打、捡、装备、放、交互、合成、搬、用物品、跑一组步骤，
以及读它自己的状态与周围世界。

**不管**：这具身体该会什么。那是**注册它的那个模组**说的，基座不评价——
一个注册了"酒狐"的模组、一个加了十种新怪物的模组，它的实体能飞能穿送、能挖能打，
是它自己的产品，不是基座的事了。

这也决定了这个方向**没有档位**：玩家侧的 `READ_ONLY` / `CONSERVATIVE` / `FULL` 回答的是
"代理替玩家能走多远"，套到实体上等于基座替别人的模组决定它的怪物该会什么（[职责边界](职责边界.md) §3）。

## 2. 工具清单（28）

`minecraft:` 命名空间下 28 个。每份详细说明在 `skills/entity-tools/references/<id>.md`，
用 `capability.read` 按 id 读。

这里不列档位与默认：28 个全是默认开、没有服务器开关、不设档位——同一条规则写一遍就够了。

| id | 做什么 |
|---|---|
| `entity.list` | 列出所有身体与各自 id |
| `entity.status` | 自身位置、维度、血量、饥饿、手持物品、是否存活 |
| `entity.scan` | 按半径列周围方块与实体（必须给过滤） |
| `entity.inventory` | 背包槽位与数量 |
| `entity.inspect` | 按 id 读一个实体：类型、位置、维度、血量、归属 |
| `entity.block.inspect` | 身体读一个方块 |
| `entity.item.inspect` | 身体读自己背包某个槽位 |
| `entity.craft.available` | 身体能做的配方（答案由它背包里的东西决定） |
| `entity.world.info` | 身体所在位置的世界信息 |
| `entity.world.locate` | 以身体位置为原点找最近的结构或群系 |
| `entity.move` | 走到世界坐标（any / walk / fly / teleport） |
| `entity.look` | 转过 yaw/pitch，或朝向一个目标坐标 |
| `entity.mine` | 挖视线内、够得着的一个方块 |
| `entity.attack` | 对目标实体造成伤害 |
| `entity.pickup` | 捡起附近的掉落物 |
| `entity.equip` | 按槽位装备或卸下（`slot` 与 `entity.inventory` 索引一致） |
| `entity.drop` | 把手持或指定槽位的物品丢到地上 |
| `entity.give` | 把物品交给够得着的目标（玩家或容器） |
| `entity.use` | 对实体交互：喂食、驯服、挤奶、交易 |
| `entity.place` | 用**它自己的背包**放一个方块 |
| `entity.place.line` | 沿方向连放同种方块（最多 16） |
| `entity.interact` | 按钮、拉杆、门、活板门、栅栏门 |
| `entity.machine` | 操作炉子家族，物品进出都是它自己的背包 |
| `entity.transfer` | 容器槽位与**它自己背包**之间搬物品 |
| `entity.craft` | 按配方合成一次，材料从它自己背包扣 |
| `entity.item.use` | 用主手物品（即时生效；按住类会拒绝），`holdTicks` ≤ 100 |
| `entity.sequence` | 按顺序跑一组身体步骤（最多 32 步，失败即停） |
| `entity.command.run` | 身体申请执行一条命令：先令牌、operator 批准、单次有效 |

**放方块、拆方块、用物品这三件事只有这边有**：玩家的那两只手由玩家自己用，基座不替他做
（[玩家辅助](玩家辅助.md) §1）。身体做这些用的是**它自己的**背包、够得着的范围与权限。

## 3. 两道门：归属与能力位

| 门 | 谁回答 | 不通过时 |
|---|---|---|
| **归属** | 调用者是不是这具身体本身，或有没有被授权控制它 | `access.denied` |
| **能力位** | 这具身体注册时有没有声明那个 `EntityCapability` | `UNSUPPORTED` / `UNAVAILABLE` |

`body` 参数在实体侧可选：填了就是"那具身体"，不填就是"调用者自己"。
填了却拿不到控制权、或者调用者是玩家又没填 `body`，就是 `body.target.required` / `access.denied`。

完整的归属阶梯（controller 缺失、mismatch、未验证、self_only…）见 [实体](实体.md) §6。

## 4. 说明书与技能

- 技能 `minecraft:entity-tools`，随 jar 发布在 `tianshu/skills/entity-tools/`；
- 约定（信封、`body` 语义、失败怎么读）写在它的 `SKILL.md`；
- 每个工具一份 `references/<id>.md`，四段模板见 [技能撰写规范](技能撰写规范.md) §4。

## 5. 加一个工具

1. 先确认这具身体真的**声明了**对应能力位；没有就别加工具，加了也只会回 `UNSUPPORTED`；
2. 在 `tianshu-client/.../tool/` 写 `TianshuTool`，`category()` 用 `BODY_WRITE`（写）或 `SERVER_READ`（读）；
3. **不要**覆盖 `requiredAutonomy()` / `requiredBodyAutonomy()`——实体侧没有档位，覆盖了就是把玩家尺子带进来；
4. 用 `ActorScope.body(caller, bodyId)` 拿执行者，它已经做了"没填 body 就拒绝"和归属检查；
5. 世界操作写在 `*Ops` 里，玩家侧（如果有）只适配参数——见下。

### 与玩家侧共用一份逻辑

同一个动作两侧都有时（`interact`、`transfer`、`craft`、`place`…），**逻辑放在一个谁都不属于的类里**：

```
PlaceOps / PlaceLineOps / InteractOps / MachineOps / BlockInspectOps / TransferOps
CraftOps / CraftAvailableOps / ItemUseOps / ItemInspectOps / WorldInfoOps
WorldLocateOps / CommandRunOps
```

两边的工具类只做六件事：`id`、`category`、`policy`、`description`、`argsSchema`、解析 `ActorScope` 再调 `Ops`。
操作类的签名吃 `ActorRef` 加具体字段，**不吃任何一侧的 `Args` 记录**——吃了就等于一侧拥有另一侧。
检查过：`*Ops` 不引用任何 `Tool` 类，工具类之间也不互调。
