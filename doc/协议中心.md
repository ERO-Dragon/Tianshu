## 1. 两条公开寻址

| 方式 | 用途 |
|---|---|
| `CAPABILITY` | 找"能做某事"的模块：命令与请求 |
| `TOPIC` | 广播"某件事发生了"：所有订阅者都收到 |

协议中心不承载业务脑：它不理解 Payload 的内部含义，也不直接执行 Minecraft、LLM、TTS、ASR 或 UI 动作，
只负责把标准信封安全地路由、排队、取消、观测和清理。

**六条原则**：

1. 跨模块通信**只走协议中心**——不 import 对方实现类，不绕过去调内部服务。
2. 公开寻址只有能力和主题。**响应不是第三种寻址模型**，它是协议中心按请求 ID 管理的回包通道。
3. 协议中心**不拆业务 Payload**：Payload 是类型化黑盒，只校验 `PayloadType`、Java 类型、`PacketType`、
   优先级与注册声明是否匹配。
4. 模块声明能力，协议中心托管生命周期（排队、分发、完成、失败、取消、过期、死信）。
5. 业务编排留在业务模块，协议中心不硬编码流程。
6. 功能模块只拿到**受控运行端口**（见 §9）。

## 2. 统一信封

所有跨模块交互都封装为 `TianshuEnvelope`：

| 字段 | 含义 |
|---|---|
| `envelopeId` | 全局唯一，用于响应关联、取消、日志与防重复消费 |
| `traceId` | 链路追踪：同一业务链路的请求、派生信封、响应与流式片段共享 |
| `parentId` | 父信封 ID；响应的 `parentId` 必须指向被响应的请求 |
| `sourceId` | 发信模块或输入源 |
| `targetMode` / `target` | `CAPABILITY` 或 `TOPIC`，以及对应的能力/主题 ID |
| `deliveryPolicy` | 排队、只保留最新、合并等 |
| `packetType` | 信件语义：`COMMAND` / `REQUEST` / `RESPONSE` / `STREAM_START` / `STREAM_CHUNK` / `STREAM_END` / `CANCEL` / `STATUS` / `ERROR` / `HEARTBEAT` / `EVENT` |
| `payloadType` | Payload 类型枚举 |
| `ackPolicy` | 是否期待成功/失败确认 |
| `priority` / `threadPolicy` | 投递优先级、Handler 执行线程约束 |
| `deadline` / `expireAt` | 期望完成时间、绝对过期时间 |
| `cancellationScope` / `failurePolicy` | 取消传播范围、失败后的处理策略 |

Payload 必须实现 `ITianshuPayload`，推荐不可变 `record`。**禁止携带活对象**（`Entity`、`ItemStack`、`Level`、
`Player`、`Screen`、`PoseStack`），跨线程/跨模块数据必须先快照化。

## 3. 能力、主题、响应

**能力**＝"谁能处理这类请求或命令"。调用方不关心具体模块，只向能力 ID 投递。
登记能力必须声明：能力 ID、支持的 `PayloadType`、Payload Java 类、可接受的 `PacketType`、
最低优先级、Broker 类型、完成策略。

**主题**＝"某件事发生了"。主题**必须先注册**，未注册主题进死信。高频主题必须节流，
优先 `LATEST_ONLY` / `COALESCE` / 短生命周期；协议中心不是帧级渲染总线，模块私有逐帧状态自己维护快照。

**响应**：请求方发 `REQUEST` 到能力 → 登记该 `envelopeId` 的响应处理器 → 服务方 `respondTo(parent, …)`
生成 `RESPONSE` → 协议中心按 `parentId` 投给它。一个请求可以收到多个响应（流式分片 + 最终结果）。
最终响应到达、请求过期、模块卸载或调用方主动清理时，响应处理器必须注销。

**不要把回包做成公开能力**（`AX.LLM_RESULT` 这类伪能力）：公开能力只表达对外可调用的服务入口。

**模块卸载**由宿主统一调 `ProtocolRuntime.unregisterModule(moduleId)`：同时清理该模块的 capability provider、
topic 订阅、未完成请求的响应处理器、语音触发与模块描述；若某个能力/topic/请求还有别的模块登记，
只移除目标模块的条目，不影响其他 provider / subscriber / handler。

## 4. 生命周期与取消

状态流转（`EnvelopeStatus`）：`CREATED → ACCEPTED → QUEUED → DISPATCHED → RUNNING → COMPLETED`。
终态：`COMPLETED` / `CANCELLED` / `EXPIRED` / `FAILED` / `REJECTED` / `DEAD_LETTERED`。

| `CancellationScope` | 行为 |
|---|---|
| `SELF_ONLY` | 只取消当前信封 |
| `CHILDREN` | 当前信封及子链路 |
| `TRACE` | 整条追踪链路 |

没有"按资源聚合取消"这一档：运行时没有资源→任务的索引，需要同资源取消的模块自己维护映射。

| `FailurePolicy` | 行为 |
|---|---|
| `PROPAGATE_CANCEL` | **唯一有执行语义**：失败时按取消范围传播 |
| `FALLBACK` | 允许模块派生降级信封；派生由模块做，运行时只继续投递 |
| `IGNORE` | 只清理当前信封 |
| `REPORT_ONLY` | 只记录上报，不传播——也是模块没声明时的默认值 |

**没有 `RETRY`**：运行时不自动重试，需要重试的模块自己重新提交。留一个不会生效的枚举值是陷阱。

`cancelEnvelope(...)` 不是公开直投：它生成协议取消信封，由协议中心按目标与范围处理。

**取消是协作式的，不是抢占**：`CANCEL` 只改信封状态，不会打断工作线程；处理器必须注册 `onCancel`
并自己 `interrupt` 或复查取消信号，否则工作照跑、终态仍是 `COMPLETED`。同步占满线程的处理尤其如此。

## 5. Broker 与执行通道

Broker 是能力或订阅的资源控制器，负责排队、拒绝、合并、替换、打断与释放：

| Broker | 适合 |
|---|---|
| `EXCLUSIVE_INTERRUPT` | 独占且可打断的资源（播放） |
| `PARALLEL_LIMIT` | 有限并发（网络、推理） |
| `LATEST_ONLY` | 只关心最新值的高频事件 |
| `BOUNDED_QUEUE` | 普通短队列 |
| `STATELESS_FAST_PATH` | 快速无状态解析 |

"必须主线程"不是 Broker，而是信封的 `threadPolicy`（`MUST_MAIN` / `ASYNC_WORKER` / `IO_BLOCKING`）——
排队策略与执行线程是两件事，别混在一个枚举里。

阻塞任务不能在 Broker Handler 或主线程里直接执行，必须走统一执行通道（lane）：
`MAIN`（Minecraft 主线程）/ `CPU` / `IO`（网络、文件、HTTP 流）/ `AUDIO_IO` / `AUDIO_SYNTH_FAST` /
`AUDIO_SYNTH_AR` / `AUDIO_INPUT_STREAM` / `MODEL_LOAD` / `LONG`（长驻监控）/ `SCHEDULED`（定时清理与延迟）。

## 6. 死信与风暴防护

进死信的情况：目标能力或主题不存在、响应找不到请求处理器、`PayloadType` 或类不匹配、`PacketType` 不被接受、
优先级低于注册方最低要求、信封过期、Broker 拒绝且无法降级、Handler 抛未捕获异常、风暴防护触发。

死信默认记录 `envelopeId` / `traceId` / `sourceId` / `target` / `targetMode` / `packetType` / `payloadType` /
错误码与简短原因；完整 Payload 只在显式 Debug 模式下脱敏输出。

风暴防护盯五件事：同一 `sourceId` 单位时间投递量、同一主题回环发布、同一 trace 派生深度、
同一 `PayloadType` 连续重复、流式分片频率。

**默认上限是每个「来源 → 目标」每秒 200 条**（`ProtocolRuntimePolicy`）。所以逐 token / 逐分片发流式结果
会持续触发 `SOURCE_RATE_LIMITED`，分片甚至终态都可能被丢——**消费方必须自己合批**（例如 25ms 一个窗口）。

## 7. 观测

协议中心暴露轻量快照：Broker 队列与运行状态、模块列表、能力列表、主题列表、主题订阅列表、
响应处理器数量或请求 ID 摘要、语音触发注册、最近死信、信封状态流转、StormGuard 拒绝统计。
观测只服务 Debug 与开发者工具，不参与业务判定。

## 8. 模块怎么接

适配器是模块接入协议中心的边界层：把业务意图写成信封，把能力/订阅/响应处理器登记给协议中心。
它不决定业务流程，不直接调别的模块实现，也不建私有通道。

```java
public final class MyModuleProtocolAdapter extends AbstractProtocolAdapter {
    public static final String MODULE_ID = "module.my_module";
    public static final String SOURCE_ID = "module.my_module";

    public MyModuleProtocolAdapter(ModuleRuntimeAccess moduleRuntime) {
        super(MODULE_ID, SOURCE_ID, moduleRuntime, AdapterDefaults.standard());
    }
}
```

适配器只接收 `ModuleRuntimeAccess`；它不暴露 `ProtocolRuntime`、`ProtocolExecutorManager` 或协议内部 registry。

### 8.1 发信

| API | 用途 |
|---|---|
| `commandCapability(...)` | 能力命令：请"会这件事"的模块做一件事，通常不要业务结果 |
| `requestCapability(...)` | 能力请求：可能要回包 |
| `publishTopic(...)` | 发布主题事件 |
| `submitToCapability(...)` / `submitToTopic(...)` | 需要自定义 `PacketType` 时 |
| `respondTo(parent, …)` | 回复上一封请求 |
| `cancelEnvelope(...)` | 请求取消某个信封 |
| 带 `parent` 的重载 | 继承 `traceId`、设置 `parentId`，表达同一业务链路的派生关系 |

### 8.2 收信登记

| API | 用途 |
|---|---|
| `registerCapability(...)` | 声明能处理某能力（能力 ID / PayloadType / Payload 类 / Broker / PacketType / 最低优先级 / 完成策略 / handler） |
| `subscribeTopic(...)` | 声明订阅某主题 |
| `registerResponseHandler(...)` | 声明要接收某个请求的响应 |
| `unregisterResponseHandlers(...)` | 清理某个请求的响应处理器 |

**先登记响应处理器再提交请求**，避免服务方极快返回时响应先于登记到达。

### 8.3 后台任务

不要自建无界线程池，也不要在 Handler 或主线程里跑阻塞任务：

```java
submitTask(taskSpec(ExecutionLane.IO)
        .envelopeId(envelopeId)
        .concurrencyKey(MODULE_ID + ":llm")
        .maxConcurrency(1).queueCapacity(4).build(), task);
```

### 8.4 默认值与常用调整

`AdapterDefaults.standard()`（普通异步）/ `mainThreadUi()`（客户端 UI 或主线程读取）/
`highFrequencyFact()`（短生命周期最新态）。常改项：优先级、线程策略、投递策略、超时、取消范围、
失败策略、并发与队列容量。

### 8.5 常见错误

1. 把回包做成公开能力（应使用响应处理器）。
2. 把事件做成能力（多方关心的状态变化应是主题）。
3. `PayloadType` 与 Payload 类不匹配（会被拒绝投递）。
4. 高频状态用普通队列（应使用最新态策略）。
5. Handler 里跑阻塞任务（应提交执行通道）。
6. Payload 携带 Minecraft 活对象（必须不可变快照）。
7. 绕过协议中心调用别的模块（会破坏生命周期、取消、观测与资源仲裁）。

一句话：**公开调用走能力，广播事件走主题，请求结果走响应处理器。**

## 9. 装配期的内核端口

这些不是协议的一部分，但同样是"模块能看见什么"的边界：

| 端口 | 说明 |
|---|---|
| `ClientPorts` | 装配期客户端服务：scheduler / uiHost / texts / filePicker / settingsLayers / audioDevices / configStores / modelLoadQueue |
| `ModuleRuntimeServices` | 设置页用的最小内核面：findService / requireService / requestRefresh |
| `NamedObjectIndex` | 内核只持有索引的生命周期调用；索引本体属于听澜，缺 jar 则端口不存在 |
| `WorldFactsSource` | 平台世界事实（`kindId` 为字符串），语义由消费模块解释 |
| `VoiceInputPort` | 语音按键语义，听澜实现 |
| `GameEventPort` | 平台采样（血量/饥饿/维度/群系/死亡信息），探针与措辞在天枢 |
| `KeywordTableReloadPort` | 平台读资源包字节，听澜解析词表 |
| `TianshuRuntimePorts` | 会话之前就要用的端口的注册表 |

两条约束：**实现方**要么是平台，要么是某个模块，内核不实现功能语义；端口**可以缺席**，
查不到就降级（没有索引就没有对象纠错），不得因此启动失败。

**世界事实有两条通道，不能混算**：客户端本地采集与服务端采集器各产一份。同一条事实两边都产时，
去重键不同会让记忆里出现两条——所以聊天、成就这类只由客户端产。某个版本确实拿不到的事件（受加载器
事件 API 限制）由覆盖测试的 `ABSENT` 集合登记，声明与代码不一致即失败。
