# 智能体接入层

> 面向"任何智能体"的稳定入口。不包含循环、提示词或天枢逻辑；只把平台的发现、调用、能力读取、
> 取消与变更订阅组合成一个门面。

## 为什么需要它

平台已经有工具注册表、能力表、权限、限流、Schema、取消和事件，但这些是**分散的底层原语**。
智能体不应该逐个认识它们，也不应该依赖 Minecraft 类型。`AgentSession` 是唯一的接入面：

```java
AgentSession session = AgentSession.client(ToolCaller.agent(false));

session.tools();                    // 当前可调用的工具（ToolSpec）
session.capabilities();             // tool/skill/resource/prompt 行
session.call(id, args);             // JSON 信封
session.callHandled(id, args);      // 可取消的调用
session.read(capabilityId, args);   // 工具走工具路径；内容走能力表
session.onChange(listener);         // 进程内目录变化
session.cancel(requestId);
```

`AgentSession.server(caller)` 用于服务端逻辑；`client` 用于客户端智能体。

## 先取契约

外部智能体在第一次调用前可以取一份机器可读描述：

```java
JsonObject contract = session.describe();
```

形状：

```json
{
  "protocol": "tianshu.agent/1",
  "revision": 42,
  "caller": { "kind": "AGENT", "id": "tianshu", "operator": false },
  "side": "CLIENT",
  "limits": { "maxPending": 64, "maxInFlightPerCaller": 8 },
  "tools": [
    { "id": "tianshu:recipe.query", "category": "LOCAL", "description": "...", "enabled": true,
      "argsSchema": { "type": "object" } }
  ],
  "capabilities": [
    { "id": "tianshu:tianshu-tools", "kind": "skill", "binding": "local", "permission": "EVERYONE",
      "description": "..." }
  ]
}
```

`revision` 来自 `CapabilityCatalog.revision()`；变化时智能体可以重新取契约或订阅 `onChange`。

## 保证

- 所有调用都返回标准信封：`{ok:true,result,durationMs,bytes}` 或 `{ok:false,code,message,durationMs}`；
- 权限、启用状态、风险档、限流、Schema 校验、取消都与模组调用走同一条路径；
- 能力读取返回 `{ok:true,text}`；未知 id、坏分页、坏文件路径都是结构化错误；
- `callHandled` 的 `cancel()` 是尽力而为，边界与平台取消一致。

## 边界

- **线程/侧**由调用方负责：平台不会替智能体把调用切到服务端线程；`client`/`server` 必须选对；
- 它不提供提示词、轮次、记忆或工具选择策略——那是智能体自身；
- 跨进程外部智能体仍走 MCP 只读端点；`AgentSession` 是进程内门面。
