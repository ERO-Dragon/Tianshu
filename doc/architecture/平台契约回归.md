# 平台契约回归

> 目的：把最近补的底层契约固定成可重复的验收，不再靠"应该没问题"。
> 全部是平台层测试，不启动游戏、不依赖天枢。

## 一键运行

```bash
./gradlew :tianshu-api:test :tianshu-client:test
```

完整门禁：

```bash
./gradlew test verifyNoPlatformImport verifyClientPlatformBoundary verifyFeatureIsolation verifyAdapterMatrixCoverage
```

## 契约与覆盖

| 契约 | 覆盖测试 | 验收点 |
|---|---|---|
| typed + JSON 两条入口 | `TianshuToolsTest`、`PlatformContractTest` | 本地/服务端工具都能走；结果信封 `ok/result` |
| 参数 Schema | `ToolArgumentValidatorTest`、`TianshuToolsTest` | 缺字段/错类型/额外字段/enum/数组项 → `INVALID_ARGS` + `args.x` 路径；边界不拦夹取类工具 |
| 结果元数据 | `TianshuToolsTest.envelopesCarryTimingAndPayloadSize`、`PlatformContractTest` | `durationMs`、成功 `bytes`；失败只有 `durationMs` |
| 取消 | `ConnectionToolChannelTest`、`ServerToolDispatchTest`、`PlatformContractTest` | 客户端 pending 立即 `CANCELLED`，服务端在飞 future 被取消 |
| 并发配额 | `ConnectionToolChannelTest`、`ServerToolDispatchTest` | 同一调用者第 9 个在飞 → `BUSY`；服务端同样 |
| 目录刷新 | `ServerToolDispatchTest`、`ConnectionToolChannelTest` | 保留 id `tianshu:tool.catalog` 返回工具；刷新激活声明 |
| 目录事件/推送 | `CapabilityCatalogTest`、`ToolCatalogPushRegistryTest` | ADDED/UPDATED/REMOVED；异常监听器被隔离；revision 递增；推送按玩家可见工具计算 |
| MCP 健康 | `McpClientTest` | connected/toolCount/lastError；不可达服务器不抛；关闭后断开 |
| 错误分类 | `McpClientTest`、`ConnectionToolChannelTest` | 远端拒绝 `FAILED`，传输失败 `UNAVAILABLE`；未知工具/限流等稳定 code |

## 手动验收（需要游戏）

1. `./gradlew :tianshu-lab:runClient`；
2. 设置 → 【听澜】仲裁测试台 → 能力自检；
3. 状态行应出现 `capabilities: tool=9 skill=1 resource=1 prompt=1` 和 `inventory.inspect: OK`；
4. `logs/tianshu-diagnostics.log` 应出现 `capability.self_check` 事件。

## 边界

- 取消是尽力而为：服务端同步工具可能跑完才看到取消；
- 目录跨进程刷新是 60 秒轮询，不是事件推送；
- 并发超限返回 `BUSY`，没有排队/优先级；
- 这些边界都在 [舟楫对智能体流程的支持评估](舟楫对智能体流程的支持评估.md) 中记录。
