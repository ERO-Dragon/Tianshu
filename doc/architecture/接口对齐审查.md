# 接口对齐审查：以 1.21.1-neoforge 为基线

审查日期：2026-11-02。基线：`tianshu-adapter/1.21-1.21.1-neoforge`（产品最初对接的版本，也是事实产出最全的一套）。
判定"这一版确实拿不到"必须有证据：要么游戏/加载器没有该钩子，要么该钩子在该版本实际解析到的依赖里不存在——用 jar 反查（`javap`），不靠印象。

## 1. 结论先写

1. **版本扩展没有造成能力退化。** 客户端 12 个 `ClientGameContextPort` 方法在全部 13 棵共享树上都有真实实现；事实产出在同一加载器内部完全一致（21 个 NeoForge 包彼此相同，22 个 Fabric 包彼此相同）。差异只在**加载器**这一维，与 Minecraft 版本无关。
2. **事实有两条通道，不能混着比。** NeoForge 侧有一半"事实"是**客户端本地**发布的（`NeoForgeClientFactWatch` 与 `NeoForgeBossEventWatch`），另一半才是服务端收集器（`GameFactCollector`）。Fabric 侧同样的分工是 `FabricClientFactWatch` 与 `FabricGameFactCollector`。
3. 按通道算，Fabric 比 NeoForge 少 **14 类**：客户端本地少 3 类（`DIMENSION_CHANGED`、`RESPAWN`、`BOSS_ENGAGE`），服务端少 11 类。其中 5 类有现成 Fabric 原生钩子可以补，9 类在 fabric-api 里没有钩子。
4. 另有 2 个常量在**服务端收集器**里没有产出：`EVENT_CHAT_MESSAGE`、`EVENT_ADVANCEMENT_UNLOCKED`。前者确认是遗漏，后者是当时漏数了客户端通道（`AdvancementTracker` 一直在产出），两件事的复核见 §5。

## 2. 实测矩阵（按通道）

### 2.1 客户端本地事实

| 事实 | NeoForge（21 个包） | Fabric（22 个包） |
|---|---|---|
| `EVENT_CONTAINER_OPEN` | `NeoForgeClientFactWatch`（`ScreenEvent.Opening`，容器界面） | `FabricClientFactWatch` |
| `EVENT_DIMENSION_CHANGED` | `NeoForgeClientFactWatch`（关卡加载） | **缺** |
| `EVENT_RESPAWN` | `NeoForgeClientFactWatch`（`ClientPlayerNetworkEvent.Clone`） | **缺** |
| `EVENT_BOSS_ENGAGE` | `NeoForgeBossEventWatch`（`BossEvent`） | **缺** |

### 2.2 服务端事实

| 加载器 | 种类 | 集合 |
|---|---|---|
| NeoForge（21 个包） | 17 | `BLOCK_BROKEN` `BLOCK_PLACED` `DAMAGE_TAKEN` `DISMOUNT` `EFFECT_EXPIRED` `EFFECT_GAINED` `EXP_LEVEL` `FISHING_CATCH` `FRIEND_JOIN` `FRIEND_LEAVE` `ITEM_CRAFTED` `ITEM_PICKUP` `MOB_KILLED` `MOUNT` `PLAYER_DEATH` `TAMED` `TRADE` |
| Fabric（22 个包） | 6 | `BLOCK_BROKEN` `DAMAGE_TAKEN` `FRIEND_JOIN` `FRIEND_LEAVE` `MOB_KILLED` `PLAYER_DEATH` |

Fabric 侧缺的 11 类正是 `ServerFactCoverageTest` 里 `ABSENT` 列出的那 11 个，两处一致——也就是说服务端缺口是**登记过的**，客户端 3 类则是**没登记的空白**。

## 3. 缺口逐条定级

证据：每个 Fabric 线实际解析到的 `fabric-api` 版本 → 对应模块 jar → `javap` 看类与成员是否存在。

### 3.1 客户端本地缺的 3 类

| 事实 | Fabric 原生手段 | 版本线 | 定级 |
|---|---|---|---|
| `EVENT_DIMENSION_CHANGED` | `ClientWorldEvents.AFTER_CLIENT_WORLD_CHANGE`（1.21.1 实测存在）；26.x 该包改名，对应 `ClientLevelEvents` | 全线 | **可补（原生）**，26.x 需按线分叉类名 |
| `EVENT_RESPAWN` | `ClientEntityEvents.ENTITY_LOAD` / `ENTITY_UNLOAD`（1.21.1 与 26.3 都有）：本地玩家实体被卸载又加载即为重生 | 全线 | **可补（原生，启发式）** |
| `EVENT_BOSS_ENGAGE` | 无原生 BossBar 事件；客户端每 tick 读 `BossOverlay`/`Gui` 的 Boss 列表即可 | 全线 | 可补（轮询，成本低） |

### 3.2 服务端缺的 11 类

| 事实 | Fabric 原生钩子 | 定级 |
|---|---|---|
| `EVENT_EFFECT_GAINED` / `EVENT_EFFECT_EXPIRED` | `ServerMobEffectEvents`（`AFTER_ADD`/`AFTER_REMOVE`…），**仅 1.21.11 起**（entity-events 3.1.1+）；1.20–1.21.10 无此类 | 4 条线可补，其余需 mixin/轮询 |
| `EVENT_BLOCK_PLACED` | 无（`UseBlockCallback` 是右键交互；26.3 的 `BlockEvents` 只有 `USE_ITEM_ON`/`USE_WITHOUT_ITEM`） | mixin 或轮询 |
| `EVENT_ITEM_PICKUP` | 无（26.3 `ItemEvents` 只有 `USE`/`USE_ON`） | mixin 或轮询 |
| `EVENT_ITEM_CRAFTED` | 无 | mixin 或轮询 |
| `EVENT_FISHING_CATCH` | 无 | mixin 或轮询 |
| `EVENT_TAMED` | 无 | mixin 或轮询 |
| `EVENT_TRADE` | 无 | mixin 或轮询 |
| `EVENT_MOUNT` / `EVENT_DISMOUNT` | 无 | mixin 或轮询 |
| `EVENT_EXP_LEVEL` | 无 | **轮询**（每 tick 比等级，零风险） |

"需 mixin 或轮询"是实现代价问题，不是产品取舍问题：数据在服务端本来就拿得到（背包、等级、BossBar、驯服/交易状态都能读），只是 fabric-api 没替我们挂好钩子。

## 4. 语义差（接口在，拿到的东西不一样）

| 事实 | 差异 | 证据 |
|---|---|---|
| `EVENT_DAMAGE_TAKEN` | 1.21 线只有 `ALLOW_DAMAGE`（结算前、可否决），记的是**入射伤害**；1.21.1 起是 `AFTER_DAMAGE`，可拿实际落地伤害 | `ServerLivingEntityEvents`：1.6.12 只有 `ALLOW_DAMAGE`/`AFTER_DEATH`，1.8.0 起才有 `AFTER_DAMAGE` |

## 5. 两个常量：chat 真漏了，advancement 早就在产出（2026-11-03 复核更正）

`EVENT_CHAT_MESSAGE`：两个加载器的服务端收集器都没有产出，确认是遗漏（映迹时期的设计意图就是"玩家聊天"也发一个世界事件，事实键早已备好）。本轮补齐全部 43 个包，见 §10。

`EVENT_ADVANCEMENT_UNLOCKED`：**不是缺口**，本条原判断错在只统计了服务端 `GameFactCollector`。真实产出点是客户端共享层的 `mc.event.AdvancementTracker`：

| 环节 | 证据 |
|---|---|
| 注入点 | `ClientPacketListenerMixin` 在 `handleUpdateAdvancementsPacket` 的 `TAIL` 调 `WorldEventHooks.recordAdvancementUpdate` |
| 是否启用 | `tianshu.mixins.json` 在 13 棵共享树全部带该混入且 `required: true`；43 个 adapter 的客户端引导都调用 `WorldEventHooks.bind(...)` |
| 标题/描述 | 直接取客户端 `DisplayInfo.title()/description()`，即玩家自己语言的成品文本，不需要 lang key 中转 |
| 语义 | 只要"有 toast 或聊天播报"的成就（`showToast() || announceToChat()`），也就是游戏本身认为值得告诉玩家的那批 |

因此服务端**不**再重复产出这条事实：同一次解锁会变成两条语义重复、去重键相同的事件，得不偿失。

混入目标写错会因 `required: true` 直接崩游戏，所以目标方法逐版本查过：Fabric 侧 loom 映射里 1.20–1.21.11 共 21 个版本全部命中；26.1/26.2/26.3 是原始 mojmap 名，`javap` `ClientPacketListener` 命中；NeoForge 侧 20.2/20.3/20.5 的 NeoForm 反编译源码命中，26.1/26.2/26.3 的 `build/moddev` 映射 jar 命中。NeoForge 与 Fabric 编译期用的是同一套 mojmap 名，故一个版本验证一次对两种加载器都成立。


## 6. 需要拍板的决策

1. **Fabric 侧是否允许 mixin？** 允许 → 11 类服务端事实可补齐，代价是每线一套 mixin（约等于现有 `ScreenWidgetMixin` 的 11 倍）；不允许 → Fabric 永远少这 11 类，必须在设置界面/文档里如实标注，不能静默。
2. **`EVENT_EXP_LEVEL` 用轮询还是 mixin？** 建议轮询（每 tick 一次整数比较）。
3. **第 5 节两个常量怎么处理？** 删掉常量（若确认不需要）或补产出（若需要）。

## 7. 建议实施顺序（尚未开始）

1. **Phase 1（原生 API，零/低风险）**：客户端本地 3 类——`DIMENSION_CHANGED`（全线，26.x 换类名）、`RESPAWN`（`ClientEntityEvents` 启发式）、`BOSS_ENGAGE`（轮询）。
2. **Phase 2（按线分叉）**：`ServerMobEffectEvents` 覆盖 1.21.11 + 26.1/26.2/26.3 的效果两类；`EXP_LEVEL` 轮询覆盖全线。
3. **Phase 3（待决策）**：其余 8 类，按第 6 节结论决定 mixin 还是登记为已知缺口。
4. 每补一类必须同步三处：收集器实现、该线 `ServerFactCoverageTest` 的期望集合、本文档第 3 节的表。

## 8. 本轮没有做的事

- 没有为 Fabric 补任何一类事实；本文档只做审查与定级。
- 没有改 `ServerFactCoverageTest`（等 Phase 1 一起按线分叉，避免 22 个包各改一次又对不齐）。
- 没有验证真机行为；本文档的"存在/不存在"全部来自依赖 jar 的字节码。

## 9. 决策记录：不做 mixin（2026-11-02 用户拍板）

结论：**第 3 层（mixin）全部放弃**，只做第 1 层（原生事件/回调）与第 2 层（每 tick 状态差分）。

因此以下 4 条在 Fabric 侧永久缺失，按"该版本确实拿不到"如实登记，不再视为待办：

| 事实 | 为什么只能 mixin | NeoForge 侧 |
|---|---|---|
| `EVENT_ITEM_CRAFTED` | fabric-api 无"制作完成"钩子 | 有原生 `PlayerEvent.ItemCraftedEvent`，保留 |
| `EVENT_FISHING_CATCH` | 无；轮询鱼钩状态不可靠 | 有原生 `ItemFishedEvent`，保留 |
| `EVENT_TAMED` | 无；轮询 owner 变化噪声大 | 有原生 `AnimalTameEvent`，保留 |
| `EVENT_TRADE` | 无；轮询商人界面不可靠 | 有原生 `TradeWithVillagerEvent`，保留 |

（`EVENT_ADVANCEMENT_UNLOCKED` 原本也列在本表里，复核后移除：它由共享层的 `AdvancementTracker` 在客户端产出，两个加载器都有，见 §5。）

保留并要补的（第 1、2 层）：

| 层 | 事实 | 范围 | 状态 |
|---|---|---|---|
| 1 | `CHAT_MESSAGE` | 两侧全部包 | **已完成**（§10） |
| 1 | `DIMENSION_CHANGED` | Fabric 全部包（26.x 用 `ClientLevelEvents`） | 已完成 |
| 1 | `RESPAWN` | Fabric 全部包（`ClientEntityEvents` 启发式） | 已删除该事实（与 `PLAYER_DEATH` + `DIMENSION_CHANGED` 重复） |
| 1 | `BLOCK_PLACED` | Fabric 全部包（`UseBlockCallback`） | 已完成 |
| 1 | `EFFECT_GAINED` / `EFFECT_EXPIRED` | Fabric 的 1.21.11、26.1、26.2、26.3 | 已完成 |
| 2 | `EXP_LEVEL`、`ITEM_PICKUP`、`MOUNT`、`DISMOUNT`、`BOSS_ENGAGE` | Fabric 全部包 | 前四类已完成，`BOSS_ENGAGE` 转永久缺口（§10.1） |
## 10. 进度（2026-11-02 夜）

已落地的对齐项（每个都是全树 `gradlew build` 验证过的）：

| 项 | 范围 | 实现 |
|---|---|---|
| `CHAT_MESSAGE` | **全部 43 个包**（2026-11-03 补齐剩余 41 个） | Fabric `ServerMessageEvents.CHAT_MESSAGE`（`PlayerChatMessage.signedContent()`，各线签名一致）；NeoForge `ServerChatEvent.getRawText()`（1.20.1 是 Forge 同名事件，`getPlayer()`/`getRawText()` 与 NeoForge 一致） |
| `DIMENSION_CHANGED` | 22 条 Fabric 线 | ≤1.21.11 与 1.20 走 `ClientTickEvents` 引用差分（各线 lifecycle 版本不一致，事件类并不都存在）；26.x 用 `ClientLevelEvents`（`Identifier.getPath()`） |
| `EXP_LEVEL` | 22 条 Fabric 线 | 每 tick 比较 `experienceLevel`，值变化才发 |
| `ITEM_PICKUP` | 22 条 Fabric 线 | 每 4 tick 做背包计数差分，只报增加（`getContainerSize`/`getItem` 跨线兼容） |
| `MOUNT` / `DISMOUNT` | 22 条 Fabric 线 | 每 tick 比较 `getVehicle()` 引用 |
| `RESPAWN` | 全仓删除 | api 常量、presence 别名、auxilium 映射规则、21 个 NeoForge 发射点（`ClientEvents.onPlayerClone` 身份刷新保留） |

Fabric 现状：服务端 12 类（`EFFECT_GAINED`/`EFFECT_EXPIRED` 只在那 4 条线，共 14 类）+ 客户端本地 2 类 + 客户端 `ADVANCEMENT_UNLOCKED`；NeoForge 服务端 18 类 + 客户端本地 3 类 + `ADVANCEMENT_UNLOCKED`，即 22 个常量全覆盖。

Fabric 仍缺（皆无原生钩子、按决定不做 mixin）：`BOSS_ENGAGE`（§10.1）、`EFFECT_GAINED`/`EFFECT_EXPIRED`（仅 1.21.11 起可用 `ServerMobEffectEvents`）、`ITEM_CRAFTED`/`FISHING_CATCH`/`TAMED`/`TRADE`。

**批量改动注意**：adapter 源码是 CRLF 行尾，脚本里的替换串必须用 `\r\n`，否则 `Set.of(...)` 的多行序列匹配不到、条目会插进错误集合（本轮为此红过三次）。
### 10.1 BOSS_ENGAGE 改为永久缺口（2026-11-02 实测）

26.3 的 `BossHealthOverlay` 只暴露 `extractRenderState` / `update` / `reset` / `shouldPlayMusic` 等方法，**没有任何读取当前 Boss 列表的公开访问器**；`Gui` 侧也只有 `getBossOverlay()` 拿实例。因此"每 tick 读 Boss 列表"这条路不成立，只能 mixin `update` 或渲染入口——按既定决策不做。

结论：`BOSS_ENGAGE` 与那 5 条 mixin-only 事实同类，Fabric 永久缺失；NeoForge 侧保留（`NeoForgeBossEventWatch` 用 `BossEvent`）。
## 11. 最终能力账（2026-11-03 收口）

`WorldEventTypes` 删除 `RESPAWN` 后共 22 个常量。逐个对账：

| 加载器 | 服务端事实 | 客户端本地事实 | 合计 |
|---|---|---|---|
| NeoForge（21 个包） | 18 | 3（`CONTAINER_OPEN`、`DIMENSION_CHANGED`、`BOSS_ENGAGE`） | **22（全覆盖）** |
| Fabric（22 个包） | 12（`EFFECT_GAINED`/`EFFECT_EXPIRED` 只在 1.21.11、26.1、26.2、26.3 四条线，故那四条线是 14） | 2（`CONTAINER_OPEN`、`DIMENSION_CHANGED`） | 15（四条线 17） |

两个加载器另有 1 个**共享的客户端事实** `ADVANCEMENT_UNLOCKED`（`AdvancementTracker` + 混入，见 §5），已计入上表合计。

Fabric 缺的 7 个常量里，5 条是永久缺口（4 条只能 mixin，1 条无访问器）：`ITEM_CRAFTED`、`FISHING_CATCH`、`TAMED`、`TRADE`、`BOSS_ENGAGE`；另 2 条是版本限制：`EFFECT_GAINED`/`EFFECT_EXPIRED` 需要 `ServerMobEffectEvents`（1.21.11 起），18 条旧线因此没有。

**验证口径**：43 个包全树 `gradlew build` 通过、700+ 套测试 0 失败；但**仍然没有任何一版做过真机验证**，以上全部是编译 + 单元测试 + 字节码/映射反查三层证据。

**已知遗留（下一阶段）**：

1. 18 条没有 `ServerMobEffectEvents` 的 Fabric 线里，`EFFECT_*` 仍如实留在 `ABSENT`，这是版本限制不是遗漏。
2. 服务端事实在 Fabric 侧完全没有门禁测试：`ServerFactCoverageTest` 只查字符串是否出现在收集器里，不验语义（条数、去重、方向）。NeoForge 侧连这类测试都没有。
