> 本文是**唯一的契约与验收落点**：门禁命令、契约清单、验收台、覆盖矩阵、游戏内清单都在这里。

## 1. 一键门禁

```bash
./gradlew :tianshu-api:test :tianshu-core:test :tianshu-client:test \
  verifyFeatureIsolation verifyFeatureOptionalDependencies verifyClientMediaWiring \
  verifyServerToolRegistration verifyHostHasNoFeatureDependency verifyCommonAdapterNeutral \
  verifyNoPlatformImport verifyUniversalModuleJars verifyAdapterProperties \
  verifyAdapterMatrixCoverage verifyProtocolVersionSingleSource verifySettingsRenderersCoverOptionEntries
```

**不要用 `./gradlew check`**：它会带上 `tianshu-intake` 的既有抖动测试（`IaModuleProtocolFlowTest` 的 `await` 超时），
那是既有失败，与本模块改动无关（已用 `git stash` 回退到基线复现过）。

门禁的教训写在 §6：**一个门禁"通过"只有在能证明它会失败时才算数**。

## 3. 验收台（`tianshu-lab`）

**入口两个**：

```bash
# ① 无人值守（启动后自动跑一次，等工具表填满；加 world 还会等世界与玩家就绪）
./gradlew :tianshu-adapter:1.21.1-neoforge:runClient -PtianshuLabAcceptance=1
./gradlew :tianshu-adapter:1.21.1-neoforge:runClient "-PquickPlayWorld=New World" -PtianshuLabAcceptance=world
# ② 游戏内：设置 →【听澜】仲裁测试台 →「运行平台验收」
```

**证据两处同源**：`run/tianshu-lab/acceptance-<时间戳>.json` 与 `run/logs/tianshu-diagnostics.log` 的 `acceptance.run` 事件。

**实机状态（2026-11-16，专用服务器 + op 玩家）**：**44 通过 + 2 跳过 + 自检变红，accepted=true，0 失败**。跳过的是两条身体用例——验收台的身体 provider 在客户端进程内，远程服务端没有它，因此按范围跳过。三条"服务端动作"用例在专用服上真实执行/被拒：`xp` 执行成功、`setblock` 非法方块名回 `INVALID_ARGS`、`teleport` 开关关着回 `DISABLED`。

要验证"动作真的被执行"这一半，需要 op 环境：① 专用服务器 + `ops.json`（首选，动作本来就是服务端职责）；② 或开作弊的单机世界。验收前还需把 `config/tianshu_ferry-server.toml` 的 `ceiling` 调到 `full` 并打开对应动作开关；验收后要改回 `conservative`。

**当前规模**：47 条 + 1 条自检，分 11 个面（新增"服务端动作"一面）：

| 面 | 条数 | 代表断言 |
|---|---|---|
| 模型工具能力注册与调用 | 5 | 两视角一致、关闭工具仍列出、FULL 档对保守档不可见、放宽档位只增不减 |
| 工具参数契约 | 3 | 严格 schema 拒绝未声明字段、两种拒绝不混、每个已发布 schema 都声明严格性 |
| 能力表 | 14 | revision 与监听器、快照不变、预算切断、`page` 透传、三类能力都能读 |
| 智能体门面 | 4 | 真实注册表上的发现/调用/读取、契约里的协议名与并发上限、退订 |
| 设置 | 1 | 无 `persist` 拒绝构建 |
| 实体工具 | 6 | 13 个 `body.*` 注册与参数契约；无 operator standing 碰不到身体端口 |
| 模块执行通道 | 1 | 任务在通道执行，抛异常不污染通道 |
| 模型下载校验 | 2 | 校验失败绝不提升；坏字节同主机重下 |
| 世界上下文 | 2 | 有世界时 11 项采集齐全且不抛 |
| 诊断 | 4 | 空白身份被拒、异常监听器不饿死别人、null 归一、缺 severity 被拒 |

**三条硬规矩**：

1. 用例 id 与文档同源；覆盖声明（`coveredAreas`）与未覆盖清单（`uncovered`）都印在报告里。
2. 跑不了的显式 SKIP 并写原因，不许静默通过。
3. **`SELF-CHECK-1` 必须失败**；它若 PASS，整轮 `accepted=false`——验收台自己必须能证明会失败。

## 6. 门禁的教训

- 12 个 `verify*` 里曾有 **4 个在空转**（路径写死 `core/<module>`、`inputs.dir` 不展开目录），修好后两个做过变异验证。
- 教训写成一句：**"通过"只有在能证明它会失败时才算数**。验收台的 `SELF-CHECK-1` 就是这条规则的产物。
- 本地文件系统故障、并发正确性、跨版本 API 存在性仍是盲区（后者要靠离线 API 签名索引）。
