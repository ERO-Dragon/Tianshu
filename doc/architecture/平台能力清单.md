# 平台能力清单

> 北辰与游戏本体的交互面。按 **侧（客户端 / 服务端）× 读写** 组织；
> 状态：`已有` / `缺` / `不做`。新增能力先在这里登记，再开端口。

## 0. 分类

| | 读（快照/事件） | 写（效果/操作） |
|---|---|---|
| **客户端** | 玩家/世界/实体/背包/效果/准星快照 | 本地效果：界面、HUD、聊天栏、action bar、toast、title、声音 |
| **服务端** | 权威事件、服务端状态快照 | 世界变更（动作）、广播 |

三条不对称：

1. 客户端"写"是本地效果，无权威；服务端"写"是权威变更，需要服务端组件。
2. "读"分推（事件订阅）与拉（快照请求），端口要分别提供。
3. 广播虽然属于服务端操作，但需要客户端发起请求，因此是**双端能力**，不是纯服务端能力。

已定决策：

- **附近实体不做**（成本高、收益低；准星目标已覆盖对话场景）。
- **服务端动作的配置只做开关**（`enabled`），不加权限档位与频率档位；默认关闭。
- **广播是双端功能**：客户端请求 + 可选服务端组件；服务端缺失时降级为仅本地输出或明确失败。

## 5. 服务端只读（P2）

| 能力 | 状态 | 备注 |
|---|---|---|
| 权威事件 | 已有 `GameFactCollector` | 合成/拾取/钓鱼/驯服/伤害/击杀/死亡/方块/坐骑/效果/经验/交易 |

## 6. 服务端操作（P3）

### 6.1 动作（权威变更）

| 项 | 约定 |
|---|---|
| 配置 | 每个动作一个 `enabled` 开关，默认关闭（`ServerActionConfig`）；文件为 `<实例>/config/tianshu-server.toml`，存档可用 `<存档>/serverconfig/tianshu-server.toml` 覆盖 |
| 校验 | `enabled=false` 直接拒绝，不执行 |
| 权限 | 第一版：执行者需 OP（权限等级 2）；后续再扩展 |
| 回执 | 结果：`OK` / `DENIED` / `DISABLED` / `INVALID` / `FAILED(reason)`；5 秒无响应按 `FAILED` 处理 |
| 幂等 | 请求带 id，重复请求返回同一结果，不重复执行（服务端缓存 512 条） |
| 动作 | 已实现：`give_item` / `teleport` / `set_time` / `set_weather` / `spawn_entity`；无万能命令入口 |
| 可用性 | 玩家加入时服务端下发动作目录；客户端 `availableActions()` / `serverActionsAvailable()` 可据此决定向模型提供哪些工具 |

### 6.2 广播（双端）

| 项 | 约定 |
|---|---|
| 链路 | 客户端请求 → 可选服务端组件 → 广播 |
| 受众 | 第一版：全服（`broadcastSystemMessage`）；半径/队伍后续 |
| 内容 | 文本 + 发送者标识；长度上限待定 |
| 频率 | 每玩家 2 秒冷却；文本 1–256 字符 |
| 降级 | 服务端缺失：回 `FAILED`（不本地伪造），需要本地提示时由模块自己用 `presentation.chat` |
| 配置 | 同样是 `enabled` 开关 |

## 7. 元能力（已有）

事件订阅（`TickSignals` / `InputSignals` / `WorldEvent`）、注册表/字典（`NamedObjectDictionary`）、网络通道（内部）、模组列表（`InstalledMods`）、配置、语言。

## 8. 明确不做

- 附近实体；
- 原始 `Level` / `Entity` / `ItemStack` 穿过 api；
- 万能 `runCommand(String)`；
- 模拟输入（伪造按键/鼠标）；
- mixin 进 MC 内部；
- 其他玩家的背包/位置/私有数据；
- 打开链接。

## 11. 性能约定

- 读：每次只读调用方请求的切片；新增的方块/姿态/生命值/容器/玩家列表均为 O(1) 或 O(槽位/玩家数)，不做缓存、不扫描世界。`captureOpenContainer` 只在容器界面打开时读菜单；`capturePlayerList` 只读客户端已渲染的字段。
- 写：表现端口是事件级调用（聊天栏/action bar/toast/title/声音），宿主不做每帧工作；需要连续绘制时用 HUD 图层，不要每 tick 重发。
- 调用方负责节流：宿主不替模块去重或排队，避免把节流策略藏进平台。

## 12. 空闲成本（未安装/未使用时）

| 能力 | 空闲开销 |
|---|---|
| HUD 图层 | 每帧一次事件回调 + 一次 volatile 读 + 空表判断；无图层立即返回，不分配 |
| 客户端读取（`ClientGameContextPort`） | 0：纯按需，无后台采样 |
| 本地表现（`ClientPresentationPort`） | 0：仅调用时 |
| 按键 | 只注册模块声明的键；无声明时每 tick 一次空表遍历 |
| 设置页 | 页面模型在打开时构建；装配期只登记 source |
| 文件选择 / 音频设备 | 调用时才访问 |
| 诊断 | 仅事件发生时；先过模块门与 debug 门 |
| tick / input 总线 | 每 tick/按键一次 map 查找 + 空表判断 |
| 世界事件 | 无订阅者时直接返回：不构信封、不进 broker、不记生命周期（`ProtocolRuntime.publishWorldEvent` + `WorldEventPublisher.hasSubscribers`） |
| 服务端事实 | 每条发送先查通道；无客户端通道不发送；flush 空表判断 |
| HUD 着色器 | 只编译模块声明的 program |

已知的残余开销（刻意保留）：

- NeoForge 事件分发本身仍在（每帧/每 tick 一次回调），这是钩子的成本，不是能力的成本；
- 世界事件的生产者在调用 `publish` 前可能已构造 `WorldEventPayload`（很小），是否提前跳过由生产者决定；
- 专用服务端的 `GameFactCollector` 仍会收到服务端事件并逐个玩家查通道；没有客户端装天枢时它只是查完不发。
