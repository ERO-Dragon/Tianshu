# 工具层收敛计划（审查 + Numen 对照）

> 状态：**计划与实施记录**。本文把子代理审查结论、能力目录设计与 Numen（minecraft-numen）的对照
> 合成一条施工顺序，并记录每一步的实际落地。审查编号（C1/H1/H2/...）沿用审查报告。
>
> 原则：每一阶段独立可交付；先安全与正确，再删重复，再做权限与能力消费；不做大爆炸式重写。

## 2. 决策（已定）

| 议题 | 决定 | 理由 |
|---|---|---|
| A3：主对话是否带工具 | **维持 Simple 带工具**（当前行为）；A3 文档改写与"回复 + 委派"协议统一延后到天枢优化阶段 | 工具层的目的就是让助手能查/能做 |
| 写工具的触发 | **风险分级**，不做逐次确认弹窗：`READ_ONLY` 只读、`CONSERVATIVE` 生存可做、`FULL` 特权动作；服务端仍要 operator + 开关 | 不打断交互；安全靠分级 |
| L3：英文协议文本 | 保留英文（模型向协议），集中在 `ToolCatalogText`；玩家文案走 lang | 模型对英文指令更稳 |
| H4：去重方式 | `ServerToolDispatch` 在 api；adapter 只留 sender；`ToolCallClient` 收进 `tianshu-client` | 一条执行链、一份客户端状态机 |
| Lua / program | 暂不做，能力目录保留 `program` 为未来 kind | 没有真实需求前不引入第二执行语言 |
| Weaving | 不改，继续只做传输；能力表在 `tianshu-api` | 依赖方向正确 |

## 3. 阶段计划与落地

### P0 决策与文档 — 已完成

- 权限/分级/去重/L3 决策已定；
- A3 与"回复 + 委派"协议按用户要求延后；
- 26.x 配置类型核对完成。

### P1 安全与健壮 — 已完成

1. **限流**：`ToolRateLimiter`，只拦 `PLAYER`，读 10/s、写 2/s，新增 `RATE_LIMITED`；agent/模组不受限。
2. **线缆上限**：`ToolWireLimits` 统一请求/结果/错误长度；超长结果变结构化失败，不再丢包。
3. **断开**：1.20.1–1.20.4-neoforge 补 `LoggingOut`。
4. **L6**：26.3 的 `SYNCED` 是正确 scoped 名称，不改；注释已写明。
5. **游戏工具进能力表**：注册时镜像 `kind=tool`/`binding=local`，带 category/enabled/autonomy/argsSchema；
   开关同步；exposure 过滤已关闭与当前档位不允许的工具。
6. **H2**：Simple 挂钟 10s → 30s（最多 3 轮工具 + 模型往返；只约束卡住的轮次）。
7. **M3**：`ConnectionToolChannel` 唯一超时权威，`TianshuTools` 不再叠 `orTimeout`。
8. **M6**：工具结果进对话前截断到 8000 字符。
9. **审计**：`ToolAudits`（默认平台日志，可安装 sink）；只记录真正执行的服务端写工具；
   被拒绝的调用不产生事件。

有意暂缓：**战利品缓存**——限流已挡住刷取；缓存需要数据重载钩子，否则 `/reload` 后读到旧表。

### P2 去重与生命周期 — 已完成

1. `ServerToolDispatch`（api）：解析、执行、信封、幂等（`(player, requestId)` 120 秒）、异常单行化；
2. 42 份 handler 只保留登录/注册/转调，`toResult`/`failure` 删除；
3. `ToolCallClient` 收进 `tianshu-client`，13 份网络副本删除；
4. **M1**：`AXToolTurn.onReply` 返回 `CompletableFuture<Decision>`，`AXToolRoundHandler` 在工具完成时提交下一轮，
   不再在 LLM 回调线程 `.join`。

### P3 权限与写工具 — 已完成（无确认 UI）

1. `ToolAutonomy { READ_ONLY, CONSERVATIVE, FULL }`：风险等级，与 `ToolCategory` / `ToolPermission` 正交；
2. 工具用 `requiredAutonomy()` 声明；写工具默认 `CONSERVATIVE`，特权工具覆盖 `FULL`；
3. `ToolAutonomyGate` 比较档位；默认 `CONSERVATIVE`，四个写工具在 operator + 开关满足时直接可用；
4. 目录、exposure、调用三处按同一档位过滤/拒绝；服务端分发同一比较；
5. **lab 工具控制台**：工具 id + JSON + 执行 + 结果行，走正常调用路径。

未做（明确不在本阶段）：确认弹窗（用户明确不要）、对象组/allow-ask-deny 防火墙、FULL 档的设置页入口。

## 4. 与 Numen 的取舍

| Numen 做法 | 我们是否采用 |
|---|---|
| 服务端假玩家身体 | 不采用：我们是助手 + 能力层，没有自主身体 |
| Lua 程序 + 原子命令 | 部分：保留 `program` kind 与预算思路，暂不引入 VM |
| 权限防火墙 + 对象组 | 部分：风险分级已做；对象组/规则表后段 |
| skill 文件 + 渐进披露 | **采用** |
| MCP 双向 | 部分：客户端 tools/resources/prompts 已做；stdio 与 server 未做 |
| 纯 JVM 分层 | 已一致（api/client/agent） |
| bench 真模型评测 | 可选，未做 |
