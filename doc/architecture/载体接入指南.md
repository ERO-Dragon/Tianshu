# 载体接入指南

> 给想为天枢提供自有载体的模组作者。平台只认身份、能力、处理器；实体、渲染、外观归你。

## 一个载体由什么组成

| 组件 | 谁负责 | 说明 |
|---|---|---|
| 实体类型 | 你 | 两套 loader 各自注册；没有它就没有身体 |
| 渲染/模型/皮肤 | 你 | 平台不提供渲染抽象，也不覆盖别人的渲染器 |
| `AgentBodyProvider` | 你 | 把实体 id 解析成 `AgentBody`，并给出处理器 |
| `AgentBodyActions` | 你 | 按能力实现可选处理器，做不到就留空 |
| 生命周期 | 你 | spawn/despawn 由你的模组决定；平台不代管 |
| 持久化 | 你 | 平台的 `BodyPersistence` 只认识内置载体；自己的载体自己存 |
| 访问控制 | 平台 + 你 | 平台提供 `BodyAccess` 判定与命令；你的 provider 实现 `checkAccess` |

## 最小接入步骤

1. **注册实体**（两个加载器各一处），例如：
   - NeoForge：`DeferredRegister<EntityType<?>>` + `EntityAttributeCreationEvent`（生物）；
   - Fabric：`Registry.register(BuiltInRegistries.ENTITY_TYPE, …)` + `FabricDefaultAttributeRegistry`。
2. **注册 provider**，在服务端启动时：
   ```java
   AgentBodies.register(new MyBodyProvider(...));
   ```
3. **实现 provider**：
   ```java
   public Optional<AgentBody> resolve(String bodyId)          // 实体 UUID → 快照
   public List<AgentBody> all()                                // 可选，枚举自己的载体
   public Optional<AgentBodyActions> actions(String bodyId)    // 只能在 resolve 存在时非空
   public Optional<ToolException> checkAccess(ToolCaller c, String bodyId)  // 可选
   ```
4. **实现处理器**（`AgentBodyActions`，全部可选）：

   | 处理器 | 对应工具 |
   |---|---|
   | `motion()` | `body.move` / `body.look` / sequence 的 move/look |
   | `action()` | `body.mine` / `body.attack` / sequence 的 mine |
   | `items()` | `body.pickup` / `body.equip` / sequence 的 pickup/equip |
   | `query()` | `body.scan` / `body.inventory` |
   | `placement()` | `block.place` |
   | `interaction()` | `block.interact` |
   | `craft()` | `craft.recipe` |
   | `transfer()` | `container.transfer` |
   | `machine()` | `block.machine` |
   | `itemUse()` | `item.use` / sequence 的 item_use |

   处理器只收 `ActorRef` 与平台记录，不接触平台内部状态；通过 `AgentBodies.actions(bodyId)` 被路由器拿到。
5. **声明能力**（`AgentBody.capabilities()`）：工具在调用前先查能力，缺了会得到 `UNSUPPORTED_ACTOR`，
   不会走到你的处理器。

## 约定与边界

- **body id 用实体 UUID 字符串**，这样 `body.list`、工具参数与日志能对上；
- **长操作请自行申报超时**：工具默认策略由平台工具类决定，你的处理器内部循环要自己设上限，并轮询
  `BodyOperations.cancelled(bodyId)`，在取消时清理干净；
- **并发**：平台的单操作槽位按 body id 生效，你的处理器不需要再排队；一个序列会持锁贯穿多步；
- **外观**：平台不提供"替换内置载体渲染"的钩子。想要不同外观就注册自己的实体类型；
- **持久化**：平台的存档只保存内置载体的注册表条目与背包。自有载体若需要跨重启，请自己写存档；
- **ACL**：玩家调用进入你的处理器之前，平台已经用 `checkAccess` 问过你的 provider；返回拒绝即可。

## 验证你的接入

参考 `ForeignCarrierRoutingTest`（`tianshu-client` 测试）：用一个假 provider + 假处理器包，注册路由器，
调用 `body.scan` / `body.move`，确认路由走到你的处理器、未注册 id 得到 `UNAVAILABLE`。

同样的方式可以覆盖你的能力声明、`checkAccess` 与序列步骤。
