# 智能体身体验收清单（1.21.1）

> 手工验收用。每一步都写了"做什么、期望什么"，失败时先看[智能体身体](智能体身体.md)里的判定顺序。
> 只覆盖 1.21.1 的 NeoForge / Fabric；其他版本分支没有身体实现。

## 准备

1. 单人世界，开启作弊（需要权限等级 2）。
2. 打开身体写工具的开关，默认是关的：
   - NeoForge：`<世界>/serverconfig/tianshu-server.toml` 的 `[tools]` 段，`body_actions = true`；
   - Fabric：`config/Tianshu/tools.properties`，`body_actions=true`。
3. 重启游戏，让开关生效。

## 1. 身体存在与列举

| 步骤 | 期望 |
|---|---|
| 执行 `/tianshu body list` | `no agent bodies` |
| 执行 `/tianshu body spawn marker` | 返回 `spawned agent body <uuid>` |
| 执行 `/tianshu body list` | 列出刚才的 uuid |
| 执行 `/tianshu body spawn stand` | 返回第二个 uuid；世界里出现一个悬浮的盔甲架 |
| 执行 `/tianshu body spawn walker` | 返回第三个 uuid；实体存在（隐形，F3 可见），能被打/被推 |
| 对 walker 执行 `body.move`（`mode: teleport`） | 位置改变 |
| 对 walker 执行 `body.move`（`mode: walk`）到十格外 | 实体沿地面走过去；future 到达后才返回，结果里的位置是落点 |
| 对 stand / marker 执行 `mode: walk` | `FAILED`，消息说明这具身体不能走 |
| `body.move` 指向不可达位置（墙后、悬空） | `FAILED`（无路径或超时），身体停在原地附近 |

失败：命令不存在 → 命令注册没走到；`unknown body kind` → 传了 marker/stand 以外的词。

## 2. 能力边界

| 步骤 | 期望 |
|---|---|
| 让天枢调用 `body.list` | 两条记录；marker 的能力是 `LOOK`,`MOVE`，stand 多出 `ATTACK`,`INVENTORY`,`MINE` |
| 让 marker 执行 `body.mine` | `UNSUPPORTED_ACTOR`，世界不变 |
| 让 marker 执行 `body.attack` | `UNSUPPORTED_ACTOR` |
| 用一个不存在的 uuid 执行 `body.move` | `UNAVAILABLE` |

这一组验证的是"平台按能力拒绝"，不是"动作失败"。

## 3. 移动与朝向

| 步骤 | 期望 |
|---|---|
| `body.move` 指定 stand 到 5 格外的一个坐标 | 盔甲架瞬移到该坐标；结果显示落点 |
| 同一条指令把 `mode` 写成 `walk` | `FAILED`，消息说明这具身体只能传送 |
| `body.look` 指向另一个点 | 盔甲架转向该点 |

## 4. 挖掘与攻击

| 步骤 | 期望 |
|---|---|
| 把 stand 传送到一块泥土旁，`body.mine` 该方块 | 方块消失并掉落；结果里带方块 id 与坐标 |
| 对空气位置 `body.mine` | `NO_EFFECT`（`there is no block there`） |
| 把 stand 传送到一只生物旁，`body.attack` 它 | 生物受伤；结果为 `DONE` 或 `NO_EFFECT`（盔甲架无伤害时） |
| 对 6 格外的目标执行 mine/attack | `FAILED`，消息是 out of reach |

## 5. 身体背包（stand 专属）

| 步骤 | 期望 |
|---|---|
| `craft.recipe` 带 `body: <stand uuid>`，站在合成台旁 | 产物进身体背包，不是玩家背包 |
| 身体旁边没有合成台时重复上一步 | `FAILED`，消息要求 nearby crafting table |
| `container.transfer` 带 `body: <stand uuid>`，`toPlayer=true` | 物品从容器进身体背包 |
| 同一个调用改成 `toPlayer=false` | 物品从身体背包进容器 |
| `block.machine` 带 `body: <stand uuid>` 给熔炉加燃料 | 燃料取自身体背包，熔炉开始燃烧 |

这一步是"玩家指挥一具有背包的身体"，玩家自己的背包不受影响。

## 5b. 放置与使用（动作玩家）

| 步骤 | 期望 |
|---|---|
| `stand` 背包里有石头，`block.place` 带 body 放到身体旁的空位 | 石头出现、消耗一个、落点与结果回显一致 |
| 楼梯、门、告示牌各放一次，`face` 指定朝向 | 朝向与 `face` 一致 |
| 背包里没有该物品时调用 | `FAILED`，消息包含 `has no <item>` |
| `marker` 调用 `block.place` | `UNSUPPORTED_ACTOR` |
| `block.interact` 带 body 对木门 | 门打开；对按钮执行后按钮按下并弹回 |
| 领地/保护插件在场时重复放置 | 按玩家规则拒绝或允许，记录结论 |

注意：调用期间其他模组会把一次性"动作玩家"当玩家对待（Create 的 Deployer 同理），这是预期行为。

## 5c. 感知

| 步骤 | 期望 |
|---|---|
| 站在石头旁，`body.scan` 带 `blocks: minecraft:stone` | 只返回石头的坐标，不带别的方块 |
| 把 `blocks` 换成 `minecraft:air` | 空列表（空气不算命中） |
| 对着一只僵尸 `body.scan` 带 `entities: minecraft:zombie` | 返回僵尸的 UUID、类型与坐标 |
| 不带任何过滤条件调用 | `INVALID_ARGS`，提示需要方块或实体 id |
| `radius` 给 999 | 服务端钳制，结果与半径 16 一致 |
| `body.inventory` 带 stand 的 id | 列出背包里的槽位/物品/数量 |
| `body.inventory` 对 marker | `UNAVAILABLE`（没有背包），不是空列表 |
| 用一个不存在的 body id | `UNAVAILABLE` |

## 5d. 拾取

| 步骤 | 期望 |
|---|---|
| 在 stand 旁边丢几组物品，`body.pickup` 带 body | 物品进身体背包，掉落物消失，结果列出物品与数量 |
| 继续丢物品直到身体背包放不下 | 只拾取能放下的部分，其余留在地上 |
| `marker` 调用 `body.pickup` | `UNSUPPORTED_ACTOR`（没有背包） |
| 附近没有任何掉落物 | 成功但 `items` 为空 |

## 5e. 手持与工具

| 步骤 | 期望 |
|---|---|
| `body.equip` 把铁剑放进活动槽位 | 返回槽位与物品 id |
| 装备铁剑后 `body.attack` 一只生物 | 伤害明显高于空手（记录数值） |
| 连续攻击直到剑耐久耗尽 | 剑消失，不再有加成 |
| 装备镐后 `body.mine` 一块石头 | 不是瞬破：裂纹逐 tick 推进，约一两秒后破坏；镐耐久按 tick 下降 |
| 空手 `body.mine` 同一块石头 | 明显更慢（原版空手速度），仍能挖穿 |
| 对准基岩调用 `body.mine` | 立即 `FAILED`（该身体无法破坏），不会进入循环 |
| 挖掘中途把方块换成别的方块 | `FAILED`（block changed），进度作废 |
| 挖掘中途把身体挪出触及范围 | `FAILED`（out of reach），进度作废 |
| `body.equip` 传 `slot: -1` | 清空活动槽位，攻击回到空手伤害 |
| 玩家（不带 body）调用 `body.equip` | `INVALID_ARGS`（只对身体生效） |

注意：挖掘是渐进的，工具影响速度与耐久；耐久在挖掘期间按 tick 消耗。

## 5f. 走路停滞

| 步骤 | 期望 |
|---|---|
| `body.move`（`mode: walk`）指向墙角或封闭空间 | 卡住约 40 tick 后返回 `FAILED`（stalled），不会等满 30 秒 |
| 走到一半被方块挡住但仍有微小位移 | 仍是 stall 判定（40 tick 内位移小于阈值），或总超时兜底 |

## 5g. 分子能力

| 步骤 | 期望 |
|---|---|
| 周围有石头，`body.collect` 带 block 与 count: 3 | 依次走到最近的三块石头并挖掉，掉落进入背包，结果 collected=3 |
| 周围没有目标方块 | 成功返回，collected=0，detail 说明附近没有该方块 |
| 收集过程中方块被拿走 | 停止并返回已收集数量与原因，不会卡死 |
| 对一只僵尸 `body.follow`（distance 3） | 靠近到 3 格内结束，结果 DONE 并给出最终距离 |
| 跟随目标被移除 | 下一步扫描不到目标即结束，REJECTED |
| `seconds: 1` 用于远距离目标 | 预算用完返回 REJECTED，不会无限跟随 |

## 5h. 持久化

| 步骤 | 期望 |
|---|---|
| spawn 一个 stand，往背包里放几件物品，设置活动槽位 | 正常 |
| 停服再启动 | `/tianshu body list` 里同 id 的身体还在，背包内容与活动槽位都在 |
| 重启后对同一身体 `body.mine` | 能正常挖掘，说明实体与注册表对上了 |
| 停服前把身体实体 kill 掉再重启 | 该条目被跳过，日志说明找不到实体，不会凭空重建 |

## 6. 已知限制（预期内的失败）

| 现象 | 原因 |
|---|---|
| 重启后 `/tianshu body list` 为空 | 注册表与背包都是内存态，未做持久化 |
| 跨维度 `body.move` 被拒 | 只支持同维度传送 |
| 身体所在区块未加载时动作被拒 | 不做强制加载 |
| `body.scan` 在半径内找不到目标 | 可能是区块未加载：只读已加载区域，不生成新区块 |
| walker 走路时卡在角落 | 原版寻路的正常限制；停滞 40 tick 或总超时后返回 FAILED，不会无限等待 |
