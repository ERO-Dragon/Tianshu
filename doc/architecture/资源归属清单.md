# 资源归属清单

模块拆分之后，**资源文件也要跟着模块走**：一个功能模块的模型清单、提示词、词表，应该由该模块的
jar 发布，而不是被折进 `tianshu-core` 或 `tianshu-client`。本文是这份归属的**唯一清单**，也是迁移
记录。

## 1. 判定规则

| # | 规则 | 结果 |
|---|------|------|
| R1 | 只被**一个**功能模块的业务代码读取 | 资源随该模块发布（放在该模块的 `src/main/resources` 内） |
| R2 | 被**两个及以上**模块读取（拥有它的功能模块 + 客户端设置页 + 平台适配层） | 资源仍由**拥有模型的模块**发布；读取器留在 kernel（`core` / `api`），kernel 只按 classpath 路径读，**不得出现功能模块包名** |
| R3 | 平台资源系统的资源（`ResourceLocation`：语言、shader、mixin 清单、loader 清单） | 留在 `tianshu-client`（语言）或 `adapter`（shader / mixin），因为它们不是"单文件 classpath 资源" |
| R4 | 同一种资源只允许存在一份 | 迁移后旧位置不得留副本，否则哪一份生效取决于 classpath 顺序 |

R2 的取舍写在每个读取器里：`AsrModelManager` / `LlmModelManager` / `TtsModelInfo` 这三个读取器被
"拥有它的功能模块 + 设置页 + 平台配置"三方共用，因此读取器留在 kernel；数据则随 owner 走。为了让
kernel 不反向依赖功能模块的包名，迁移后的路径统一镜像 kernel 自己的包：
`/com/rheinmetal/tianshu/model/catalog/<catalog>.json`。

## 2. 模型清单（classpath 资源）

| 资源 | 迁移前 | 迁移后（随 owner 发布） | 读取器（留 kernel） | 共用方 |
|------|--------|------------------------|---------------------|--------|
| `asr_model.json` | `tianshu-core/src/main/resources/com/rheinmetal/tianshu/constant/` | **`tianshu-intake`** `…/model/catalog/asr_model.json` | `core.model.AsrModelManager` | intake 引擎启动 / 热词；`client` 听澜设置页；`adapter` `ClientConfig` |
| `llm_models.json` | 同上 | **`tianshu-weaving`** `…/model/catalog/llm_models.json` | `core.model.LlmModelManager` | weaving 采样默认值；`client` 织言设置页；`adapter` `ClientConfig` |
| `llm_embedding_models.json` | 同上 | **`tianshu-weaving`** `…/model/catalog/llm_embedding_models.json` | `core.model.LlmModelManager` | weaving RAG / embedding 解析；`client` 织言设置页 |
| `tts-model.json` | 同上 | **`tianshu-echo`** `…/model/catalog/tts-model.json` | `core.model.TtsModelInfo` | echo 下载 / 合成引擎；`client` 回响设置页 |

`tianshu-core/src/main/resources` 在本次迁移后不再持有任何模型清单（`constant/` 目录树已清空），
kernel 只保留读取逻辑。清单缺失时读取器返回空集合，因此"文件没跟着模块走"不会在编译期报错——这
正是要出这份清单的原因；`ModelCatalogOwnershipTest` 把路径与 owner 钉成断言。

## 3. 其余资源

| 资源 | 当前位置 | 归属判定 | 处理 |
|------|----------|----------|------|
| `ir-intent-keywords.json` | `tianshu-client/src/main/resources/assets/tianshu/` → **已迁** | 只被 intake 的 IR 识别链（`IntentKeywordLoader` / `CommandParser` / `IrInputPreprocessor`）读取 | 移入 **`tianshu-intake`** `…/function/intake/repair/ir_intent_keywords.json`；`IntentKeywordLoader` 首次使用时从自己身边的 classpath 读，平台侧同名资源保留为**可选覆盖** |
| `ax_event_tiers.json`、`ax_prompts/*.json`、`ax_*_texts.json`、`general_ax.zh_cn.default.json` | `tianshu-auxilium` | 只被 auxilium 读取 | 已就位，不动 |
| `assets/tianshu/lang/zh_cn.json`、`en_us.json` | `tianshu-client` | 所有模块的界面文案共用一份语言文件，由平台资源系统按语言加载（R3） | 不动；键集合由 `ModuleStatusLanguageTest` 守 |
| `assets/tianshu/shaders/**`、`tianshu.mixins.json` | `adapter:neoforge-1.21.1` | 平台渲染 / mixin 资源，只对适配层有意义 | 不动 |
| `fabric.mod.json`、`META-INF/neoforge.mods.toml` | 各模块自己的 `src/main/resources` | 模块清单即模块身份 | 已随模块，不动 |
| `tianshu-build.properties` | `adapter` 的生成资源 | 构建产物（`generateTianshuBuildProfile`） | 不动 |

## 4. 迁移后必须同步的东西

1. **加载路径**：读取器里的 classpath 常量（本次改了 4 个：`AsrModelManager`、`LlmModelManager` ×2、
   `TtsModelInfo`）；`IntentKeywordLoader` 从"只接受平台推送"改成"自读 + 可覆盖"。
2. **源码级测试里的路径**：`ModelArchiveDownloaderTest` 直接按文件路径读 `tts-model.json`，已改指
   `../tianshu-echo/…`。
3. **打包**：模型清单现在跟模块 jar 走（`tianshu_intake` / `tianshu_echo` / `tianshu_weaving`），
   所以裁剪掉某个功能模块时，它的模型清单也一起消失——这是本次迁移要达到的效果。
4. **不要留旧副本**：`assets/tianshu/ir-intent-keywords.json` 与 `constant/*.json` 已删除，不再存在
   "两个位置哪份生效"的问题。

## 5. 为什么不把读取器一起搬进功能模块

`AsrModelManager` / `LlmModelManager` / `TtsModelInfo` 的描述对象（`AsrModelInfo` / `LlmModelInfo` /
`TtsModelInfo`）与下载器（`ModelArchiveDownloader`、`ModelDownloadHttpClient`、`HuggingFaceDownloader`）
同属 kernel 的模型领域，并且被设置页与平台配置直接引用；把它们搬进功能模块会让 `client` / `adapter`
各自依赖三个模块的模型域内部，反而更难维护。本次只让**数据**跟着 owner 走，读取器留在 kernel，边界由
classpath 路径常量 + 归属测试表达。
