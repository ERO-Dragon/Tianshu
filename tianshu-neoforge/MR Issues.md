## 问题 #3：B→C 连线模型和卡片展开动画完全偏离设计意图

**严重程度：极高（核心视觉机制）**

**涉及位置：**
- `MrEngine.java` 第 213~228 行（targetCardX/Y 计算）
- `MrWhipLayout.java` 整个 `compute()` 方法
- `MrRenderer.java` 第 97~109 行（drawCard 出场逻辑）、第 185~211 行（drawCardBackground）

### 缺陷 3a：B→C 连线应该是固定角度斜线，不是直连卡片左上角

**现状：**
- B 点算出后，代码直接以卡片左上角坐标（cardX, cardY）作为 C 点
- B→C 的连线就是"关节点到卡片左上角的直线"，方向完全取决于卡片相对于 B 的位置
- 没有固定角度的概念

**设计意图（含鞭子效应的完整模型）：**
- B→C 的 40° 角度是**静息目标角度**，不是实时固定角度
- C 点不是卡片的左上角，而是**线段与卡片矩形边框的交点**
- 具体连接到哪条边（上/下）取决于 B 点后的BC斜线向上还是向下：
  - 向斜上 → C点位于下边
  - 向斜下 → C点位于上边

**鞭子效应与角度的关系：**
- **静止时**：卡片稳定在目标位置，B→C 角度精确回归到 40°
- **转头时**：A 和 B 瞬间跟着实体移动，但 C（卡片）因阻尼滞后 → B→C 角度被拉偏，不再是 40°
- **恢复中**：卡片在阻尼驱动下追上目标位置 → B→C 角度逐渐回归到 40°
- **核心逻辑**：40° 是锚定值，偏离和回归的动态过程本身就是鞭子动画的视觉表现


### 缺陷 3b：C→卡片展开方式应为"锚定单边拉伸"，不是"中心点展开"

**现状：**
- 卡片背景从中心点向四周等比展开（`x = cardX + (cardWidth - w) * 0.5f`）
- 四条边同时向两侧扩张

**设计意图：**
- C 点连接着卡片的某一条边（上/下），这条边**固定不动**
- 展开时，只有**对侧的边**向远离 C 的方向移动
- 具体方向取决于 C 连接的是哪条边：
  - C 在上边 → 上边不动，下边向下拉伸展开
  - C 在下边 → 下边不动，上边向上拉伸展开


### 缺陷 3c：卡片位置必须与连线方向一致，由屏幕分区统一决定

**现状：**
```java
targetCardX = anchorX - cardW * 0.5f;  // 水平居中于锚点
targetCardY = anchorY;                   // 顶边和锚点齐平
```
卡片位置与 B→C 连线方向**完全独立**，各算各的。卡片永远骑在实体头顶正上方。

**设计意图（连线方向 + 卡片方位 一体化）：**

斜线 B→C 的方向不是固定的向上/向下，而是根据实体在屏幕中的位置决定（和 A→B 一样受屏幕分区驱动）。**卡片必须出现在连线所指方向的那一侧**，两者必须一致。

具体来说：
- 实体在屏幕上方 1/5 → A→B 向下 → B→C 继续向斜下 ，卡片在下边
- 实体在屏幕下方 1/5 → A→B 向上 → B→C 继续向斜上 ，卡片在上边
- 实体在屏幕中间 → A→B 水平 → B→C 根据实体位置判断斜上/斜下：
  - 实体在屏幕整体上半 1/2 → B→C 向斜下 ，卡片在下边
  - 实体在屏幕整体下半 1/2 → B→C 向斜上 ，卡片在上边

**核心原则：卡片位置是连线方向的延伸结果，不是独立计算后拼凑的。**

统一计算逻辑应该是：
1. 根据实体在屏幕的归一化坐标 (normalizedX, normalizedY) 决定方向分区
2. 从该分区得出 A→B 的方向和 B→C 的目标角度（静息态 40° 基于此方向）
3. 从 B 沿该方向 + 角度延伸，延伸长度为AB长度，得到点C
4.（关键）（这个地方很难懂）根据实体在屏幕中占的横向比例，决定C点位于卡片的边中的比例
4. 卡片的位置由这个几何链条推出，而非单独设定

### 完整的应有效果链

```
阶段1 (ap 0.0~0.25)：A→B 刚性线段从 A 向外生长（现状已正确）

阶段2 (ap 0.25~0.5)：B→C 从 B 点以固定角度（如40°）向外生长
  - C = 射线延长至同AB距离一样后的终点
  - 连接到哪条边由实体在屏幕中的位置决定

阶段3 (ap 0.5~1.0)：卡片框从 C 所在的边进行单边拉伸展开
  - C 连哪边，哪边固定不动
  - 对侧边向远处拉伸，形成"从连接点长出"的效果

阶段4 (ap > 1.0)：文字内容流式出现
```

**修复影响范围：**
- `MrWhipLayout` 需要新增 B→C 射线与矩形求交算法
- `MrCardSnapshot` 需要新增字段：C 点连接的边（上/下）、展开方向
- `MrEngine` 中 targetCardX/Y 的计算逻辑需要重构
- `MrRenderer.drawCardBackground()` 的展开动画需要改为单边锚定模式
- `MrRenderer.drawTetherLine()` 的第二段连线终点需要改为 C 点（交点）而非卡片左上角

   - 取消消失动画，恢复正常显示

  锚点出屏 → 什么都不做，让鞭子阻尼自然拉扯
  实体从扫描列表消失 → 触发正常消失动画
  卡片自然滑出屏幕边界的部分 → MC 的 GUI 裁剪自动处理

### 移除后的效果

- 卡片永远是"活着"的状态，不会因为边界突然闪没
- 转头时看到线段被拉向屏幕边缘，卡片阻尼跟随，视觉上很自然
- 实体真正离开扫描范围（超出 32 格或死亡）才触发消失动画
- 代码更简单：删除 `softBoundAlpha`、`isInHardBounds`、`isInSoftBounds`、硬杀逻辑

- `MrProjector.project()` 在 NDC 超出 ±1.5 时返回 null，这里需要放宽或改为返回屏幕外的坐标，否则锚点一出屏就连 A 点都没有了，线段也画不出来
- 建议将投影的 NDC 范围放宽到 ±3.0 或更大，允许锚点在屏幕外一定范围内仍然有坐标

## 问题 #7：卡片绘制细节全面偏离设计意图

**严重程度：高（视觉呈现）**

**涉及位置：**
- `MrRenderer.java` 第 185~211 行（drawCardBackground）
- `MrRenderer.java` 第 213~251 行（drawCardContent）
- `MrEngine.java` 第 383~429 行（precomputeVisuals）
- `MrConstants.java` 颜色/尺寸常量
- `MrRenderer.java` 第 103~110 行（背景遮罩）

### 缺陷 7a：背景色固定暗色，缺少敌我区分和渐变

**现状：**
- 背景统一使用 `bgAlpha << 24`（纯黑 60% 透明度）
- 敌对和非敌对实体使用完全相同的背景色

**设计意图：**
- 非敌对实体 → 深蓝色半透明背景，带微弱渐变（上方略亮、下方略暗，营造深度感）
- 敌对实体 → 深红色半透明背景，同样带微弱渐变
- 渐变方向：从斜上到斜下略微变暗一点点

### 缺陷 7b：切角效果失效，边框为完整矩形

## 问题 #8：LOS/出屏恢复逻辑、A 点定位、消失与出现动画衔接

**严重程度：高（交互体验核心）**

**涉及位置：**
- `MrEngine.java` 第 170~195 行（LOS 宽限期逻辑）
- `MrEngine.java` 第 360~380 行（离开实体清理）
- `MrAnimationController.java`（动画状态机，缺少"反向恢复"能力）

### 缺陷 8a：消失动画中视线恢复时不能中途刹车

**现状：**
- 消失动画一旦开始，只能播放到 DEAD 状态
- 视线在消失动画期间恢复 → 什么都不做，必须等卡片彻底死透
- 死透后 → 创建全新动画控制器 → 从头播出现动画 → 视觉上有闪断

**设计意图（两阶段恢复）：**

消失动画总时长 1s，其中线段收缩 0.5s + 卡片收缩 0.5s（对半分）。

根据消失动画当前进度决定恢复方式：

**情况1：线段正在收缩（卡片已经缩完了）**
- 立即跳转到出现动画的"线段生长"阶段
- 线段从当前缩短的位置开始重新向外生长
- 无缝衔接，没有闪烁

**情况2：卡片正在收缩（还没缩完）**
- 不打断卡片收缩，让它先缩完
- 卡片缩完后 → 转入出现动画的"卡片展开"阶段

**需要的动画状态机改动：**
- `MrAnimationController` 需要新增一个"恢复中"状态
- 或者让消失动画可以被"反转"：记录消失进度，将 appearProgress 设为消失进度的一半（线段阶段），从那里继续播放出现动画

### 缺陷 8b：出屏消失动画与 LOS 宽限期需要联动

**现状：**
- LOS 宽限期（1秒）：视线丢失但实体还在范围内 → 卡片正常显示（有透视/作弊感）
- 出屏处理（问题 #4 已记录）：删掉软硬边框，卡片靠阻尼跟随出屏
- 两者是独立逻辑

**设计意图（联动）：**

当实体丢失视线（LOS = false）或实体出屏（投影在屏幕外）后：
1. 卡片继续跟随（阻尼），**但同时开始播放消失动画**
2. 不是等 1 秒宽限期过了才消失，而是**立即开始消失**
3. 如果消失动画期间实体重新出现（视线恢复 / 实体回到屏幕内）→ 按缺陷 8a 的逻辑恢复

**总结：丢视线/出屏 → 马上开始消失（边跟边缩），不是等到宽限期过了才消失。**

宽限期概念可以保留用于：多久后从跟踪列表中移除。但视觉上的消失应该立即开始。

### 缺陷 8c：LOS 丢失后 A 点应冻结在最后可见位置（防作弊）

**现状：**
- LOS 丢失但实体还在范围内 → 锚点 A 继续跟着实体的实时 3D 投影位置走
- 玩家能看到卡片跟着墙后面的实体移动 → **透视/作弊**

**设计意图：**
- 当 `isLineOfSight == false` 时，A 点**冻结**在最后一次看到实体时的屏幕坐标
- 不再跟随实体的实时位置更新
- 效果：实体躲进墙后，卡片停在实体消失的位置，然后播放消失动画
- 实体在墙后移动玩家看不到，卡片也不跟着动 → 无作弊

**实现方式：**
- 在 TrackedCard 中记录 `lastSeenAnchorX` / `lastSeenAnchorY`
- `isLineOfSight == true` 时更新这两个值并正常使用
- `isLineOfSight == false` 时使用冻结值作为 A 点，不再更新

## 问题 #10：碰撞解决应废弃旧推挤算法，改为预布局方向搜索

**严重程度：高（布局稳定性 / 连线几何一致性）**

**涉及位置：**
- `MrWhipLayout.java` 第 122~199 行（resolveCollisions）
- `MrEngine.java` 卡片目标位置计算逻辑
- `MrCardSnapshot.java` 后续可能需要记录连接方向 / C 点 / 卡片边信息

### 现状

当前碰撞解决是在所有卡片位置已经算完后，再对快照坐标做后处理推挤：

1. 先按卡片中心 Y 排序
2. 做 3 轮纵向矩形重叠推开
3. 再做 3 轮横向矩形重叠推开
4. 直接修改 `cardX/cardY`

这个方式存在几个问题：

- 卡片位置被推走后，A→B→C 的几何关系没有同步重算
- 连接线方向、C 点、卡片边框位置会脱节
- 推挤是事后修补，不是根据 MR 连线规则预先找位置
- 纵向 / 横向推挤规则和新的八方向布局设计不一致

### 设计意图：放弃旧碰撞推挤，改为“预布局方向搜索”

不再使用 `resolveCollisions()` 这种事后推开算法。

新的逻辑应该是：

1. 每张卡片在绘制前，先根据 A 点和候选方向计算 C 点
2. 根据 C 点和连接边计算卡片矩形
3. 判断该卡片矩形是否会遮挡已有卡片
4. 如果遮挡，就尝试下一个方向
5. 找到可用位置后，再正式确定该卡片的 C 点、卡片矩形和绘制方向

也就是说，卡片不是先生成再被推开，而是从一开始就寻找一个不会遮挡的位置。

### 八方向候选规则

以当前实体根据屏幕位置得到的原始方向作为第一优先方向。

静止状态下，AC 连线与水平线的夹角应保持目标角度。可以理解为类似“马走日”的折线结构：

- A→B 为一段线
- B→C 为一段线
- 静息状态下 A→B 和 B→C 等长
- AC 是这两段线形成的等效方向

候选方向按顺序尝试八个方向，例如：

1. 原始方向 `theta`
2. `90° - theta`
3. `-theta`
4. `90° + theta`
5. `-90° - theta`
6. `180° - theta`
7. `180° + theta`
8. 另一个补充对称方向

实际实现时不要求死用这组表达式，但必须满足：

- 优先尝试该实体所在屏幕区域最自然的方向
- 八个方向应覆盖上、下、左、右以及四个斜向区域
- 方向选择必须同时决定 C 点、卡片所在边、卡片展开方向
- 卡片方向和连接线方向必须来自同一套方向决策，不能各算各的

### 碰撞判断方式

每个候选方向需要进行两级判断：

**1. C 点可用性判断**

先判断候选 C 点附近是否已经被已有卡片覆盖。

**2. 卡片矩形可用性判断**

再根据该 C 点生成完整卡片矩形，并用矩形重叠判断是否与已有卡片相交。

注意：不能只判断四个角点。四角判断会漏掉“长矩形穿过另一个矩形中间，但四个角都不在对方内部”的情况。应以 AABB 矩形相交作为主要判断。

### 八方向全部失败后的兜底：沿原 AC 方向延长

如果八个静息方向全部被遮挡，不要直接随便选择重叠最小的位置。

设计意图是：

1. 回到该实体的原始 AC 方向
2. 保持 A 点不动
3. 保持 AC 方向不变
4. 逐步增加 AC 长度
5. 每次步进后重新计算 C 点和卡片矩形
6. 找到第一个不被遮挡的位置后使用

也就是：

- 不是把卡片直接平移出去
- 而是沿 A→C 的原始方向把连接关系整体拉长
- C 点、卡片边、卡片矩形都要重新由新的 AC 长度计算出来

建议步进策略：

- `step = max(8px, segmentLength * 0.5)`
- 最多尝试 6~8 次
- 如果仍然失败，再进入最终兜底

### 最终兜底

如果八方向搜索和沿原 AC 方向延长都失败，仍然不能让目标突然不画。

最终可以从所有尝试过的候选中选择“最不坏”的位置：

- 与已有卡片重叠面积最小
- 出屏惩罚较小
- 离静息位置较近

这个最终兜底只用于极端拥挤情况。

### 允许轻微重叠

为避免卡片因为极小重叠而频繁切换方向，布局判断不应把“任何重叠”都视为绝对失败。

可以允许低比例轻微重叠，例如：

- 重叠面积小于当前卡片面积的 5%-20% 时，可以视为可接受
- 近处 / 敌对 / 高优先级目标的可接受重叠阈值应更低
- 远处 / 非敌对 / 低优先级目标可以稍微更宽松

这个规则可以加入现有轮询式搜索中：

1. 先按候选方向顺序查找完全不重叠的位置
2. 如果没有完全不重叠的位置，再接受八个方向中总重叠最少的位置
3. 如果轻微重叠也没有，再进入沿原 AC 方向延长
4. 延长仍失败时，再选择“最不坏”的候选

这样可以保持轮询式搜索的低计算量，不必为了评分系统强制算完所有八个方向，同时减少方向跳变。

注意：允许轻微重叠不是让卡片互相遮挡文字，而是用于处理边角、小面积擦边、动画过渡中的短暂交叠。

### 目标布局优先级

选出最多 10 个目标后，布局顺序不能完全随机。

本轮先不考虑聚焦目标优先级，因为聚焦状态和敌友关系组合后规则会变复杂。

推荐优先级：

1. 敌对目标优先于非敌对目标
2. 同类别内，距离近的目标优先于距离远的目标
3. 如果上一帧已有稳定方向，并且该方向仍然可，应优先沿用上一帧方向，避免卡片方向来回跳变

也就是说，第一版布局顺序可以是：

```text
敌对近处 → 敌对远处 → 非敌对近处 → 非敌对远处
```

近处目标优先的原因：

- 近处目标更具战术价值
- 近处卡片因为透视缩放更大，更应该优先占据自然位置
- 远处卡片较小，更适合在剩余空间里寻找次优位置

### 与鞭子效果的关系

预布局算法只负责计算“目标 C 点”和“目标卡片矩形”。

实际显示时仍然应该保留阻尼 / 鞭子效果：

- A 点跟随实体或冻结在最后可见位置
- 目标 C 点由布局算法给出
- 当前 C 点通过动态阻尼追向目标 C 点
- 静止后回归目标方向和目标长度

因此，碰撞算法不应该直接破坏鞭子效果，而是给鞭子系统提供稳定的目标位置。

### 修改方向

- 删除或废弃 `resolveCollisions()` 的事后推挤逻辑
- 在生成卡片目标位置时引入候选方向搜索
- 为每个已放置卡片记录占用矩形
- 后续卡片只避让已经放置好的卡片
- 记录每张卡片上一帧采用的方向，用于方向稳定性
- 卡片 C 点、连接边、展开方向、卡片矩形必须由同一个方向结果统一生成

- 聚焦卡片没有碰撞优先级，和其他卡片一样参与 resolveCollisions 推挤

**设计意图：**
- 聚焦卡片在碰撞布局算法（问题 #10）中应**第一个绘制**
- 其他卡片不能和聚焦卡片抢占位置
- 聚焦卡片直接使用它的默认方向（不搜索），其他卡片避让它
- 聚焦卡片的占用矩形比实际卡片大（因为放大了 2 倍），其他卡片必须全部避开

### 缺陷 11e：聚焦/退出聚焦没有过渡动画

**现状：**
- 进入聚焦：scale 瞬间从原值跳到 1.5，位置瞬间跳到屏幕顶部
- 退出聚焦：scale 瞬间跳回，位置瞬间跳回
- 非聚焦卡片瞬间缩小到 0.75 倍、透明度瞬间降到 0.4
- 所有变化都是瞬时的，没有过渡

**设计意图：**
- 进入聚焦：卡片从当前 scale 平滑过渡到 `perspectiveScale × 2.0`
- 退出聚焦：卡片从聚焦 scale 平滑过渡回 `perspectiveScale`
- 非聚焦卡片：scale 和 alpha 平滑过渡到缩小/降低值，退出时平滑恢复
- AB/BC 线段长度跟随 scale 变化平滑过渡
- 所有过渡都应通过阻尼或独立动画曲线实现，不应瞬变

### 缺陷 11f：退出聚焦条件不完整

**现状：**
- 退出聚焦只有一个条件：聚焦 UUID 在当前帧不存在（实体消失）
- 没有其他退出方式

**设计意图：退出聚焦有三种方式：**

**方式1：实体消失**
- 聚焦 UUID 不在当前帧快照中 → 开始退出聚焦动画（反向的进入动画）
- 和当前逻辑一致

**方式2：准星离开实体 + 倒计时退出**
- 聚焦模式下，如果用户准星不再瞄准聚焦实体 → 开始倒计时
- 倒计时期间准星重新对准 → 重置倒计时
- 倒计时归零 → 退出聚焦（播放反向动画）
- 倒计时时长：**聚焦卡片内文本流式输出完毕后 + 5 秒**
  - 流式输出未完成时不开始倒计时
  - 流式输出完成后才开始 5 秒倒计时
  - 如果没有流式输出（无 LLM），则详细信息全部显示完毕后开始 5 秒倒计时

**方式3：准星对准新实体 → 直接切换**
- 聚焦模式下，准星对准另一个实体 → 立即取消当前聚焦
- 开始对新实体的凝视计时（和进入聚焦一样的 3 秒凝视要求）
- 不需要先退出再进入，直接切换

### 缺陷 11g：聚焦卡片内容未扩展，无流式文本

**现状：**
- 聚焦卡片和扫描卡片显示完全相同的内容
- 没有流式文本输出功能
- 没有 LLM 集成

**设计意图：**
聚焦卡片应显示更丰富的信息，根据是否启用 LLM 有两种模式：

**启用 LLM 时：**
- 使用 LLM 流式生成对当前实体的汇总/分析文本
- 文本逐字显示（打字机效果）
- 流式输出期间不触发退出倒计时
- 全部文本输出完毕后才开始 5 秒退出倒计时

**未启用 LLM 时：**
- 罗列实体的详细信息（比扫描卡片更多的属性、状态等）
- 所有信息逐字显示完毕后开始 5 秒退出倒计时

**需要的改动：**
- `MrCardSnapshot` 需要新增聚焦文本字段（可能是多行文字或分步内容）
- `MrEngine` 或新的文本控制器需要追踪流式输出进度
- `MrRenderer` 需要支持逐字渲染（根据当前已显示的字符数截断文本）
- 需要一个标记表示"流式输出是否完成"，用于退出倒计时的触发条件
