📋 Knowledge Graph Workspace (图谱工作台) 最终开发计划书
文档版本：V13.0 绝对终态 (彻底独立版)
功能定位：取代传统的悬浮合成表，提供一个基于 2D 虚拟画布的、可无限推演的、防内存爆炸的“合成图谱编辑器”。这是一个完全独立的 Mod，绝非 JEI 的附属插件。

一、 核心痛点与设计哲学
传统合成表的局限：只能看单层配方，遇到复杂整合包（如工业模组的多步处理）需要不断点开点出，丧失全局规划能力。
传统树形面板的灾难：如果允许无脑递归展开，整合包里的物品（如铁锭变铁粒，铁粒又变铁锭）会形成死循环；且多个面板互相嵌套，极其容易遮挡屏幕。
本系统的解法：将背包/容器界面左侧剩余区域变成一张可滑出的“局部草稿纸”（左侧半侧 2D 画布）。玩家可以把各种合成表像贴卡片一样铺在这块半透明画布上，用发光连线标明逻辑关系。不替玩家做复杂判断，只提供最客观的图谱展示与极致流畅的交互，同时不遮挡背包主体区域。
对 JEI 的态度 (生死红线)：JEI 只是可选的外挂数据源，绝非核心依赖！ 本系统 100% 基于 Minecraft 原生 RecipeManager 驱动。没装 JEI，本系统必须完美运行；装了 JEI，本系统通过兼容层获取更广泛的数据。
二、 核心数据与逻辑架构 (防崩溃基石)
2.1 数据源分层架构 (彻底解耦)
第一梯队 (绝对核心)：直接读取 Minecraft.getInstance().level.getRecipeManager()。覆盖原版工作台、熔炉、高炉、烟熏炉、切石机、锻造台等所有标准 RecipeType。这已经解决了 80% 的需求，且开发效率极高。
第二梯队 (可选增强)：仅当运行环境检测到安装了 JEI/REI 时，才实例化 JEICompatibilityLayer。专门用于抓取那些不按原版规则来的异构模组（如 Create 的顺序装配、部分神秘仪式等非标准配方）。
分发逻辑：查询配方时，先查原生 RecipeManager，查不到且 JEI 存在时，再降级询问 JEI 插件。
2.2 数据与视图的绝对隔离
铁律：画布上有 5 个展示“铁锭”的面板，必须创建 5 个绝对独立的 UI 实例 (RecipePanelNode)。防止翻页状态互相覆盖导致闪烁。
实现：底层维护全局唯一的 DAG (有向无环图) 缓存，只存配方数据。UI 面板仅读取 DAG 数据，各自维护坐标和翻页索引。
2.3 祖先检测拦截器 (防死循环红线)
铁律：每次准备生成新节点前，必须向上递归遍历当前节点的祖先链。
命中处理：如果发现目标物品（如铁锭）已经是当前节点的祖先，直接阻断新节点的创建。镜头自动平滑飞到祖先面板并闪烁高亮 1 秒。
2.4 适配器层架构 (Adapter Layer - 彻底消灭屎山代码)
铁律：引入 UniversalRecipeViewModel (统一视图模型) 和 RecipeAdapter 接口。渲染引擎只认 ViewModel，绝不碰具体模组逻辑。
ViewModel 结构：只包含 List<SlotViewData> (相对坐标、物品、类型枚举 INPUT/OUTPUT/CATALYST)。
适配器实现：
VanillaCraftingAdapter -> 吐出 3x3 坐标。
VanillaFurnaceAdapter -> 吐出线性坐标。
FallbackLinearAdapter -> 遇到任何异构但能拿到输入输出列表的配方，直接吐出“降维抽象线性流”坐标。
JEICompatAdapter (可选) -> 从 JEI 偷取插槽相对坐标，吐出 ViewModel。
三、 渲染与 2D 虚拟相机引擎
3.1 渲染管线隔离
绝对禁止：严禁使用 OpenGL 3D 世界坐标渲染。所有节点的绘制必须在 GUI 层的左侧图谱抽屉区域内完成，并通过裁剪区域限制到背包/容器左侧剩余空间。
路线 B 基线：渲染风格采用原版 AdvancementScreen / 进度面板式视觉语言。common 层只提供图谱语义、节点、边、相机与 ViewModel；NeoForge 层负责把这些语义映射到原版风格 GUI。允许在 tianshu-neoforge 中使用 Mixin / Accessor / Invoker 作为平台桥接，但 Mixin 只能用于复用或暴露原版渲染资源、方法与生命周期钩子，禁止承载 CraftingGraph 的业务状态、配方语义、持久化或 Undo 逻辑。
3.2 原版风格渲染基线
铁律：不再坚持科技风和纯程序化外观。背景、按钮、节点边框、槽位底板、滚动条与弹窗统一向原版进度面板/容器 GUI 的灰黑、浅高光、深阴影风格靠拢；可优先复用 Minecraft 自带贴图、Sprite、九宫格或原版绘制方法。若直接复用贴图会造成缩放模糊，则节点内容区、连线和高频缩放元素仍可用代码绘制原版风格矩形/边框。
性能原则：Mixin 不是为了把业务塞进原版类，而是为了让平台层尽可能吃到原版渲染路径和 ModernFix 等优化收益。Phase 0/1 先建立 AdvancementStyle 渲染适配基线；后续如发现某些原版私有绘制能力值得复用，再在 NeoForge 层补充最小 Mixin 桥。Fabric 或其他加载器只需要替换平台桥，不得要求 common 层修改。
3.3 2D 虚拟相机系统
维护 offsetX, offsetY, zoom, targetZoom。缩放锚点必须永远锁定在当前鼠标的屏幕坐标上。每 Tick 执行平滑插值。
3.4 Soft Grid (软网格折行布局)
引入常量 MAX_NODES_PER_ROW = 5。当子节点数 > 5 时，自动向下折行排列，防止画布横向爆炸。
四、 交互状态机 (UX 核心，极易踩坑)
4.1 Tab 按键：全权限通道
外层 (主界面)：短按 Tab 可以滑入/滑出合成图谱面板的观察模式；长按 Tab 进入临时编辑态，松开 Tab 后若未锁定则退出临时编辑态但不强制收回观察面板；按住 Tab 的同时按下鼠标中键可以直接切换到完全编辑模式，不需要等待长按阈值。完全编辑模式可通过短按 Tab 退出，或者在通过 Esc 打开暂停页面时自动退出，也可以通过按 E 进入背包等操作退出。观察模式透明度 40%，编辑模式透明度 70%。
内层 (背包/合成台/机器操作界面等)：默认 70% 透明度常驻。短按 Tab 可以滑入/滑出合成图谱面板，图谱抽屉仅占用背包/容器左侧剩余区域并接管该区域输入（仅当聚焦于这个面板时），按 E 随着背包等面板的关闭而退出编辑态。
空态生根：图谱为空时，按住 Tab + 左键点击物品创建 SOURCE 根节点，按住 Tab + 右键点击物品创建 USAGE 根节点；这只是空图的入口交互，不允许在数据结构上把根节点特殊化。
4.2 Shift 全局破坏性范式
按下 Shift 进入 DestructiveMode。连线中点出现红 ✂，列表出现红 X，右键直接秒删，无二次弹框。释放 Shift 红叉消失。
五、 节点内部 UI 与连线规范
5.1 节点内部同构规范
节点内部不含全局操作文本和收藏按钮。
节点二分类是图谱基础结构，不是渲染标签：RecipePanelNode 必须携带 nodeType。SOURCE 表示“这个 item 如何合成出来”，USAGE 表示“这个 item 可以参与合成什么”。节点绑定主语必须是 itemId，而不是槽位实例；例如工作台配方里的四个木板作为“木板”主语时地位相同，不能因为点击的是第几个木板槽而产生不同主语语义。
节点类型与边方向是两个维度：GraphExpansionDirection 只描述新节点相对父节点向上/向下布局和 PCB 走线方向；RecipePanelNodeType 描述节点自身查询语义、智能定锚、持久化与 Undo 恢复语义。Tab 交互下左键创建 SOURCE 节点，右键创建 USAGE 节点；根节点与子节点都遵循同一规则，不再存在“根节点默认只能是来源节点”的特例。
节点外观不通过不同颜色区分 SOURCE/USAGE，统一使用同一套卡片色彩，只在标题区绘制小图标：SOURCE 使用三股箭头汇聚图标，USAGE 使用三分叉箭头图标。
主语物品角标：节点内部所有代表绑定主语 itemId 的槽位都要绘制右下角小角标。SOURCE 节点只在匹配主语的 OUTPUT 槽绘制；USAGE 节点在匹配主语的 INPUT/CATALYST 槽绘制，且主语匹配按 itemId/tag 候选判断，不绑定某个具体槽位实例。角标使用同一青蓝色小三角/芯片点，不改变节点主色。

左侧滚动分类器：纵向列表组（类似 JEI 分类栏），上下端有箭头用于组内翻页。
配方快速选择按钮：在节点左上角、左侧垂直合成类型栏右侧放置一个小型可点击按钮，用于打开当前节点的“主语配方索引窗口”。该按钮不是全局搜索，也不创建新节点，只服务于当前 RecipePanelNode 内的快速跳页。
主语配方索引窗口：点击按钮后，在当前节点附近弹出一个小窗口，窗口拥有最大宽度/高度限制，超出内容时使用平滑纵向滚动；窗口内部以类似 JEI 的网格排列一排排物品图标，每个格子代表当前节点绑定主语 itemId 下的一条可选配方，点击格子后将当前节点 selectedRecipeIndex 切到对应配方并关闭或保持窗口高亮当前项。窗口必须裁剪在左侧图谱抽屉内，不得溢出遮挡背包主体区域。
索引图标语义：USAGE 节点的每条配方通常对应不同输出物，因此格子优先显示该配方的输出物图标；SOURCE 节点的多条配方输出都等于主语，不能重复显示同一个输出图标，格子应使用该配方输入材料的动态轮播图标来表达“这是一种合成方式”，例如每隔固定 tick 在主要输入材料之间切换显示，必要时叠加小型序号/配方类型角标辅助区分。
索引窗口锁定规则：如果当前节点的整页配方翻页因 inputAnchorsLocked 或 outputAnchorsLocked 被置灰，那么索引窗口中会改变当前 ViewModel 输入/输出布局的点击也必须置灰并拦截；允许打开窗口浏览，但不允许切到会破坏已有支路语义的配方。后续如果实现输入侧/输出侧局部切换，则索引项也按相同侧锁规则判断。
右侧焦点展示区：读取 UniversalRecipeViewModel 渲染物品。
同配方翻页：合成表下方左右两侧的极简箭头，切换同分类下的不同排列；当同一节点配方数量很多时，优先使用主语配方索引窗口进行跳转，左右箭头只作为临近配方的轻量切换。
底色状态法：根据 SlotType，已有材料“暗绿切角”，缺失“暗橙切角”。
智能定锚：打开/切换分类时，自动将材料满足率最高的那一页置顶。
5.2 连线锁定与翻页置灰机制
连线锁定只看“是否引用了当前配方页里的具体槽位”。GraphAnchorKind.NODE_CENTER 表示引用的是节点绑定主语 itemId，这个主语不会因为切换当前节点配方而变化，因此不锁定配方切换；GraphAnchorKind.SLOT_CENTER 表示引用的是当前 ViewModel 中的具体 INPUT、OUTPUT 或 CATALYST 槽位，这类引用会随配方切换失效，必须锁定对应侧。
确认规则表：
| 当前节点 | 被引用对象 | 典型连线 | 是否允许切换当前节点配方 |
|---|---|---|---|
| SOURCE(X) | 输入槽 Y | SOURCE(Y) 中点 -> SOURCE(X) 的 Y 槽 | 不允许 |
| SOURCE(X) | 输入槽 Y | SOURCE(X) 的 Y 槽 -> USAGE(Y) 中点 | 不允许 |
| SOURCE(X) | 主语/输出 X | SOURCE(X) 中点 -> USAGE(X) 中点 | 允许 |
| SOURCE(X) | 主语/输出 X 查来源 | 高亮 SOURCE(X) | 允许 |
| USAGE(K) | 主语 K | SOURCE(K) 中点 -> USAGE(K) 中点 | 允许 |
| USAGE(K) | 主语 K 查用途 | 高亮 USAGE(K) | 允许 |
| USAGE(K) | 非主语输入 Y | SOURCE(Y) 中点 -> USAGE(K) 的 Y 槽 | 不允许 |
| USAGE(K) | 非主语输入 Y | USAGE(K) 的 Y 槽 -> USAGE(Y) 中点 | 不允许 |
| USAGE(K) | 输出 Z | SOURCE(Z) 中点 -> USAGE(K) 的 Z 输出槽 | 不允许 |
| USAGE(K) | 输出 Z | USAGE(K) 的 Z 输出槽 -> USAGE(Z) 中点 | 不允许 |
实现规则：节点内仍维护 inputAnchorsLocked 与 outputAnchorsLocked，但只有 SLOT_CENTER 才能写入这两个锁。INPUT/CATALYST 槽位引用写入 inputAnchorsLocked，OUTPUT 槽位引用写入 outputAnchorsLocked；NODE_CENTER 引用不写入任何锁。
整页配方翻页：当前阶段的左右箭头和主语配方索引窗口点击都属于整页配方切换，会同时改变输入和输出 ViewModel，因此只要 inputAnchorsLocked 或 outputAnchorsLocked 任意一侧为 true 就置灰并拦截。只有节点中点引用时，两侧锁都保持 false，允许切换。
删除解锁：删除某条支路或删除子节点后，必须重新扫描该父节点剩余连线，只按剩余 SLOT_CENTER 锚点重新计算 inputAnchorsLocked/outputAnchorsLocked，不能因为仍有 NODE_CENTER 连线就锁住配方切换。
5.3 电路板连线规范
交互方向：Tab 交互下左键查询来源，创建 SOURCE 节点；右键查询用途，创建 USAGE 节点。根节点和子节点都遵循这套左/右键规则。
语义方向：数据边方向不再强制等于创建方向。查询来源时，SOURCE 节点作为“来源提供者”，连线从 SOURCE 节点整体中点指向被解释对象；查询用途时，USAGE 节点作为“用途集合接收者”，连线从被查询对象指向 USAGE 节点整体中点。
锚点类型：被查询对象如果是当前节点绑定主语，则使用节点整体中点；如果是当前页某个非主语输入/输出/催化材料，则使用具体槽位中心。节点绑定主语永远是 itemId，不是某个槽位实例。
确认规则表：
| 当前节点 | 查询对象 | 查询类型 | 新节点 | 连线 |
|---|---|---|---|---|
| SOURCE(X) | 输入槽 Y | 查来源 | SOURCE(Y) | SOURCE(Y) 中点 -> SOURCE(X) 的 Y 槽 |
| SOURCE(X) | 输入槽 Y | 查用途 | USAGE(Y) | SOURCE(X) 的 Y 槽 -> USAGE(Y) 中点 |
| SOURCE(X) | 主语/输出 X | 查用途 | USAGE(X) | SOURCE(X) 中点 -> USAGE(X) 中点 |
| SOURCE(X) | 主语/输出 X | 查来源 | 不新建 | 高亮 SOURCE(X) |
| USAGE(K) | 主语 K | 查来源 | SOURCE(K) | SOURCE(K) 中点 -> USAGE(K) 中点 |
| USAGE(K) | 主语 K | 查用途 | 不新建 | 高亮 USAGE(K) |
| USAGE(K) | 非主语输入 Y | 查来源 | SOURCE(Y) | SOURCE(Y) 中点 -> USAGE(K) 的 Y 槽 |
| USAGE(K) | 非主语输入 Y | 查用途 | USAGE(Y) | USAGE(K) 的 Y 槽 -> USAGE(Y) 中点 |
| USAGE(K) | 输出 Z | 查来源 | SOURCE(Z) | SOURCE(Z) 中点 -> USAGE(K) 的 Z 输出槽 |
| USAGE(K) | 输出 Z | 查用途 | USAGE(Z) | USAGE(K) 的 Z 输出槽 -> USAGE(Z) 中点 |
起点横向偏移：同一合成面板内按材料所在行错开焊盘 X 坐标，第一行向左偏移，第二行不偏移，第三行向右偏移；更多行按左/中/右循环，避免同列多条来源/用途线完全重叠。
样式：上下布局专用 PCB 走线，必须遵循“先沿实际目标方向垂直引出 -> 45°切角 -> 水平走线 -> 45°切角 -> 垂直接入目标锚点”的顺序，避免先水平再垂直造成线束穿插。注意：语义边方向不一定等于视觉布局方向，例如查来源时新 SOURCE 节点在下方但语义边从下方节点指回上方被解释对象，因此绘制端的垂直引出方向必须按 fromAnchor/toAnchor 的实际 Y 相对关系计算，不能单纯按 GraphExpansionDirection 取正负号。线宽定义在世界坐标系下（如 2.0f），绘制时乘以 camera.zoom，保证缩放时粗细比例协调，点击检测容差同步缩放。
5.4 异构配方的“降维抽象”绘制 (兜底神技)
在 FallbackLinearAdapter 中，无视模组特殊 GUI 形状，统一拍扁成“工业流水线图纸”：左侧输入流式布局 -> 中间机器图标(稍大+蓝底) -> 右侧输出流式布局。(注：原版工作台必须保留 3x3 网格)

六、 画布固定 UI 层规范
固定在左侧图谱抽屉的屏幕坐标层，不随画布缩放平移（恢复矩阵后绘制）：

左上角：收藏列表入口与历史列表入口竖直排列。它们不是当前树操作按钮，而是顶部下滑面板的开关。未展开收藏或历史时，drawer 内只有一个合成图区；点击收藏或历史入口后，从 drawer 顶部丝滑下滑展开一个新的列表区，合成图区被该列表区向下排开。再次点击当前入口时列表区向上收起；收藏列表与历史列表互斥，打开其中一个必须收起另一个。列表区内部支持垂直滚动，点击条目恢复对应图谱。
合成图区右上角：当前树操作按钮横向排列，包括搜索入口/搜索框、收藏当前树、创建副本/另存为、清空整棵树。搜索默认以一个小放大镜按钮存在；未展开时点击该按钮或 Ctrl+F 打开搜索框，展开后搜索框占据同一操作层。搜索结果展示区会在条目前置标识“来源/用途”，而虚空生根条目则会提供两个明确分按钮“来源 / 用途”供用户点选后创建对应根节点。它们始终属于合成图区本身，不属于顶部下滑的收藏/历史列表区；当收藏/历史列表区展开时，这组按钮会随着合成图区整体被向下排开。清空按钮显示为红色 X/删除符号，作用对象是当前画布内整棵图谱树；点击后清空所有节点、连线、打开的节点弹窗和锁定状态，并标记脏位。该按钮属于面板级全局操作，不参与单节点 Shift 破坏模式，也不进入 DeleteBranchCommand 的细粒度 Undo 语义；后续可由历史记录/崩溃恢复承担误删找回。
左下角：全局操作提示文本（如“按住 Shift 右键连线可删除…”）。
搜索层：Ctrl+F 唤出搜索框，搜索框固定在合成图区顶部的屏幕坐标层，和当前树收藏/副本/清空按钮横向排布；它不属于收藏/历史下滑列表区，因此会随合成图区被顶部下滑区向下挤开，且不随画布缩放平移。
七、 持久化、容灾与双子抽屉系统
收藏系统：永久保存图谱树，无限制。当前树收藏按钮位于合成图区右上角，收藏成功后该星星进入已收藏态，并在旁边显示“空加号星星”用于创建该收藏的副本/另存为；当前树发生展开、删除、切配方、撤销等语义变化后，已收藏态取消，副本按钮收起。
历史记录系统：每次“虚空生根”自动存档，最多保留 5 条 (FIFO)，防止孤岛迷失。收藏/历史文件统一保存在当前游戏版本目录的 config/TianshuAIAssistant/cache/crafting_graph 下；其中 favorites/ 存放永久收藏，history/ 存放历史记录，crash_recovery.json 存放崩溃恢复快照。
命令模式撤销栈：严禁序列化树快照。只记录 DeleteBranchCommand { UUID 列表 }，Ctrl+Z 时精准重建。撤销恢复时必须恢复 RecipePanelNodeType、节点绑定 itemId、RecipeGraphEdge 的语义方向与两端 GraphAnchorData；恢复完成后重新扫描剩余边重算 inputAnchorsLocked/outputAnchorsLocked，不能依赖删除前的脏锁状态。
增量崩溃恢复：引入 isDirty 脏位。isDirty 只表示内存图谱结构发生过变化，不能在每次节点移动、展开、删除、翻页时立即写盘。自动保存采用低频节流策略：每次客户端 Tick 只做轻量判断，只有 dirty=true 且距离上次自动保存至少 60 秒、且当前没有正在进行的后台写入任务时，才生成一次 SaveData 并提交写盘。序列化写盘必须放入单线程后台 IO 队列，禁止在渲染线程、输入事件线程或 GUI 绘制流程中同步 Files.write。提交前对 JSON 内容计算 hash，如果和上次成功写入内容一致则跳过本次磁盘写入，只刷新节流时间，避免 selectedRecipeIndex 未变化或重复 tick 导致无意义覆盖。序列化字段至少包含节点 UUID、parentUuid、nodeType、itemId、displayName、selectedRecipeIndex、坐标、边 from/to、itemId、GraphExpansionDirection、fromAnchor/toAnchor；锁定状态优先在加载后按边锚点重算，避免旧存档锁状态与边集合不一致。下次上线弹窗提示恢复。
八、 搜索与“虚空生根”系统
Ctrl+F 唤出搜索框：

画布内定位：模糊匹配已有节点，镜头平滑聚焦并高亮命中的节点。同一 itemId 可能同时存在 SOURCE 与 USAGE 两类节点，搜索结果必须在条目前置显示“来源/用途”标识，避免把“怎么合成”与“能做什么”混成一个结果。
输入事件：搜索框由 ScreenEvent.KeyPressed 与 CharacterTyped 接管输入；Esc 关闭搜索框，Backspace 删除字符，方向键切换结果，Enter 聚焦当前已有节点结果。搜索打开时必须临时维持图谱交互态，避免用户松开 Tab 后输入框消失。
虚空生根：画布无匹配但底层有配方时，底部显示 [+] 创建新根节点条目。该条目内部必须拆分为两个明确按钮：来源与用途；点击来源才创建 SOURCE 根节点，点击用途才创建 USAGE 根节点。没有对应配方的一侧必须置灰或不可点击，不能用整条目左键/右键隐式选择类型。新节点是完全独立的孤岛根节点并聚焦，不能默认为 SOURCE。

十、分阶段验收标准
验收纪律：必须按 Phase 顺序逐步验收。任一 Phase 的核心能力失败时，停止后续验收，先回到该 Phase 修复。验收结果分为通过、部分通过、失败三类；部分通过代表主流程可用但边界行为、UI 细节或持久化仍需修补。Phase 8 属于可选兼容层，未正式接入前只验收“不装 JEI/REI 时不影响前七阶段”。

Phase 0：启动、总控与 controller 生命周期验收
验收目标：确认合成图谱能初始化、FeatureManager 总控能控制启停、controller 不再初始化后变 null、可配置交互键生效，并确认路线 B 的平台边界成立。
验收操作：进入世界并打开背包或容器界面；观察左侧图谱抽屉小缝或面板；短按交互键；长按交互键；关闭合成图谱总控后重复操作；重新开启总控后再次重复操作；检查 common 层没有引入 Minecraft GUI、AdvancementScreen 或 Mixin 依赖。
通过标准：总控开启时，短按交互键能展开/收起抽屉，长按交互键能进入鼠标可点击状态，长按结束后抽屉不自动滑回；总控关闭时，交互键不能打开合成图谱，面板不接管鼠标；日志不应持续出现 tick skipped controller=null 或 render skipped controller=null；允许出现 ensure controller=true reason=...，代表懒加载恢复成功；路线 B 的渲染桥和未来 Mixin 仅位于 tianshu-neoforge，common 仍保持纯逻辑。
失败判定：面板完全不出现则回到生命周期和总控检查；持续出现 controller=null 则检查 shutdownClient、懒加载入口和 provider 初始化状态；出现 disabled ai=... recipePanel=... 则检查 FeatureManager 与 ClientConfig 同步。

Phase 1：虚拟画布与相机引擎验收
验收目标：验证左侧抽屉、GUI 裁剪、2D Camera 平移缩放、缩放锚点和平滑插值稳定可用，并确认 Phase 0/1 已切换到 AdvancementStyle 原版进度面板风格基线。
验收操作：打开背包；短按交互键展开抽屉；再次短按收回；确认收回后保留小缝；长按交互键进入交互态；在抽屉内中键或右键拖动画布；滚轮缩放；把鼠标放在不同位置缩放；在抽屉外点击或滚轮；观察抽屉背景、把手、按钮、节点占位、槽位和提示文本是否为原版灰黑面板、高光边框、深阴影风格。
通过标准：抽屉滑入滑出不闪烁；收起状态保留小缝；拖动和缩放平滑；缩放时鼠标指向的画布位置基本不漂移；图谱内容被限制在左侧抽屉内，不覆盖背包主体区域；抽屉外输入不被图谱错误拦截；视觉上不再是科技青蓝主风格，节点/按钮/面板统一接近原版进度面板；把手为原版灰黑竖向控件并略微内缩。
失败判定：抽屉完全不出现则回 Phase 0；抽屉有背景但无节点可继续 Phase 2/3；滚轮影响背包而不是图谱说明输入拦截范围错误；图谱画到背包主体区域说明裁剪区域错误；Phase 1 控件仍大量使用科技风切角/霓虹青蓝边框则回路线 B 渲染基线修正。

Phase 2：核心状态机与输入夺权验收
验收目标：验证新交互逻辑：短按交互键滑入/滑出抽屉，收起后留小缝；长按交互键才进入鼠标可点击状态；长按结束时抽屉不会自动滑回；中键锁定、Esc 解锁、Shift 破坏态和输入拦截范围正确。
验收操作：短按交互键展开，再短按收起；长按交互键超过阈值后在抽屉内点击、拖动、滚轮；松开长按，观察抽屉是否保持原展开/收起状态；长按交互键时长按中键约 300ms，松开交互键后测试是否仍可交互，再按 Esc 解除；创建节点和连线后按住 Shift 观察红色删除提示。
通过标准：短按只控制抽屉展开/收起；长按只控制交互态，不改变抽屉展开状态；松开长按不会导致抽屉自动滑回；中键锁定能保持交互态，Esc 能解除；Shift 期间删除提示出现，松开后消失；图谱只在抽屉区域内接管鼠标。
失败判定：短按无反应说明 KeyMapping 或 tick 状态机错误；长按后不能点击说明 held 状态或输入入口错误；松开长按自动收回说明 expanded 与 held 仍然耦合；抽屉外鼠标被拦截说明命中范围错误。

Phase 3：原生适配器、同构节点与软网格防环展开验收
验收目标：验证 RecipeManager 原生配方读取、UniversalRecipeViewModel 适配、SOURCE/USAGE 双类型节点、主语 itemId 绑定、左键查来源、右键查用途、智能锚点、PCB 连线、翻页锁定、防环和主语角标。
验收操作：用木板、木棍、工作台、火把、熔炉、铁锭、石头等物品测试；空图时左键创建 SOURCE 根节点，右键创建 USAGE 根节点；在 SOURCE 节点中点击输入材料分别查来源/用途；在 USAGE 节点中点击主语、非主语输入和输出分别查来源/用途；创建多条槽位连线后尝试切配方；删除支路后再次尝试切配方；用铁锭/铁粒等循环关系测试祖先检测。
通过标准：SOURCE 表示“这个 item 如何合成出来”，USAGE 表示“这个 item 可以参与合成什么”；根节点和子节点都遵循同一左键/右键规则；节点标题区显示来源/用途小图标但不通过主色区分；节点外观继续沿用 AdvancementStyle，不能回退为科技风主视觉；所有代表绑定主语 itemId 的槽位绘制右下角角标；主语绑定按 itemId/tag 候选判断，不绑定具体槽位实例；查来源和查用途生成的节点类型正确，连线锚点符合 5.3 表格；NODE_CENTER 连线不锁配方切换，SLOT_CENTER 连线按 INPUT/CATALYST 或 OUTPUT 写入 inputAnchorsLocked/outputAnchorsLocked；整页配方切换在任意侧锁定时置灰；删除支路后按剩余边重算锁；祖先循环被阻断并聚焦/高亮已有祖先节点。
失败判定：SOURCE/USAGE 语义混淆、根节点存在特殊默认类型、主语角标绑定到具体槽位、槽位支路存在时仍允许翻页、只剩 NODE_CENTER 连线却仍锁翻页、删除支路后锁状态不重算、循环展开无限生成节点，均判定 Phase 3 失败。

Phase 4：剪枝与命令模式 Undo 验收
验收目标：验证 Shift 删除、支路删除、DeleteBranchCommand、Ctrl+Z 撤销恢复和删除/撤销后的锁重算。
验收操作：创建至少 4-6 个节点和多条连线；删除叶子节点后 Ctrl+Z；删除一整条大支路后 Ctrl+Z；删除带多条边的中间节点后 Ctrl+Z；每次删除和撤销后检查父节点翻页锁状态。
通过标准：删除支路时相关子节点和连线一起消失；Ctrl+Z 能完整恢复整条支路；恢复后 RecipePanelNodeType、主语 itemId、selectedRecipeIndex、RecipeGraphEdge 语义方向、from/to GraphAnchorData 均正确；删除和撤销后 inputAnchorsLocked/outputAnchorsLocked 按当前剩余边重算。
失败判定：撤销只恢复节点不恢复线、SOURCE/USAGE 类型丢失、边方向或锚点丢失、删除大支路只删除一个节点、翻页锁在删除/撤销后错乱，均判定 Phase 4 失败。

Phase 5：双子抽屉、收藏、历史与崩溃恢复验收
验收目标：验证左上角收藏/历史入口竖排、顶部下滑双子面板、当前树收藏/副本/清空按钮、历史记录、文件落点、异步节流保存和崩溃恢复。
验收操作：展开图谱抽屉；点击收藏入口并观察列表从上方滑下，再次点击收起；点击历史入口并确认收藏/历史互斥；创建图谱后收藏当前树，观察星星状态和空加号星星副本按钮；修改图谱后观察收藏态取消；多次虚空生根后检查历史列表和最多 5 条 FIFO；检查 .minecraft/versions/Tianshu/config/TianshuAIAssistant/cache/crafting_graph 下 favorites、history、crash_recovery.json；重进世界测试恢复提示。
通过标准：收藏/历史入口位于左上角竖排；顶部列表展开时合成图区被向下排开；搜索和当前树操作按钮始终属于合成图区右上角横排，不进入收藏/历史列表区；收藏列表和历史列表可滚动并能恢复完整图谱；收藏成功后出现已收藏态和副本按钮，图谱语义变化后取消已收藏态；历史最多保留 5 条；保存文件落在指定 cache/crafting_graph 目录；保存采用低频节流与后台 IO，不造成明显卡顿；崩溃恢复能恢复 nodeType、itemId、语义边方向和 GraphAnchorData。
失败判定：收藏/历史布局混入当前树按钮、顶部面板不排开合成图区、恢复后节点类型或边语义丢失、文件写到错误目录、频繁写盘造成卡顿、历史无限增长或无法恢复，均判定 Phase 5 失败。

Phase 6：搜索聚焦与虚空生根验收
验收目标：验证 Ctrl+F 搜索框、已有节点模糊匹配聚焦、SOURCE/USAGE 标识、未匹配时虚空生根以及搜索输入接管。
验收操作：展开抽屉并按 Ctrl+F；输入已有节点名称；用方向键切换结果并按 Enter 聚焦；搜索图上不存在但底层有配方的物品；查看底部创建根节点条目；分别点击“来源”和“用途”按钮；按 Esc 关闭搜索框，Backspace 删除字符。
通过标准：Ctrl+F 打开搜索框；搜索框接管 KeyPressed 与 CharacterTyped；Esc 关闭，Backspace 删除，方向键切换，Enter 聚焦已有节点；搜索打开时临时维持图谱交互态，用户松开交互键后输入框不消失；已有节点结果前置“来源/用途”标识；虚空生根条目必须拆分为明确的“来源 / 用途”按钮，没有对应配方的一侧置灰或不可点；新节点是独立孤岛根节点，不默认 SOURCE。
失败判定：搜索时松开交互键输入框消失、搜索结果不区分 SOURCE/USAGE、虚空生根只能创建一种类型、整条目通过左右键隐式选择类型、搜索输入影响背包快捷键，均判定 Phase 6 失败。

Phase 7：智能定锚与原生高级优化验收
验收目标：验证 InventoryAnalyzer 库存最齐页、搜索生根/历史恢复时语义锚点稳定、切石机和锻造台等特殊 RecipeType 精准布局、SLOT_CENTER 双偏移锚点和多行线束错开。
验收操作：准备多配方物品，并在背包中放入其中一种配方的大部分材料，创建 SOURCE 节点观察是否自动选到材料最齐页；改变背包材料后重复测试；测试切石机相关石材配方；测试锻造台升级模板、装备、材料组合；选择三行输入工作台配方，给不同行材料创建多条来源/用途线观察线束。
通过标准：多配方节点优先显示库存满足率最高的页，不固定总是第 0 页；节点切配方、搜索生根、历史恢复时尽量维持语义完整锚点；切石机和锻造台配方布局合理，输入/催化/输出区分明确；不同行输入线束不会完全重叠；输入/输出有纵向偏移区分；折线按 fromAnchor/toAnchor 实际 Y 相对关系引出，不因 GraphExpansionDirection 与语义方向不同而反向绕线；大量节点和展开面板存在时应只绘制可见内容，打开图谱后的 FPS 下降必须处于可接受范围，若明显异常则优先检查渲染路径、可见性裁剪、ItemStack 缓存和动画插值。
失败判定：库存最齐页无效、特殊 RecipeType 退化成错误布局、锚点偏移丢失导致多线完全重叠、语义边方向和视觉走线混淆、恢复历史后锚点语义丢失，均判定 Phase 7 失败。

Phase 8：JEI/REI 可选兼容层验收
