# AX 暂停菜单设置页设计

## 1. 文档目的

本文记录 AX / 辅星模块在天枢暂停菜单设置框架中的玩家设置页。模块名是“辅星”，玩家面对的助手名仍是“天枢”。本文只描述 AX 自有设置、配置持久化和运行时生效边界，后续新增玩家可调功能时应继续在本文维护。

AX 不创建独立 `Screen`，只通过 `AXSettingsRegistrySource` 向统一 `TianshuSettingsScreen` 注册分类和控件。本文不定义通用 GUI 框架，也不修改 IA、IR、LLM、TTS 或 Presence 的设置职责。

## 2. 设计原则

- 页面只呈现玩家能够理解且确实会改变行为的设置，不展示配置路径、内部状态草稿或调试信息。
- UI 文本全部来自 Minecraft 语言资源，Java 代码不硬编码中英文标签。
- AX 只配置回复是否进入 TTS，不配置 TTS 模型、音色或语音库；这些属于 TTS 模块。
- 游戏画面范围内的文字、状态和回复展示属于映迹；AX 不自绘 HUD，也不持有画面停留时间、布局或动画策略。
- AX 当前记忆按世界隔离，不提供“跨会话记忆”或“跨世界记忆”开关。
- 设置项必须接入真实运行时行为，不能只保存字段或在调用点增加旁路判断。

## 3. 页面结构

### 3.1 总开关

`启用辅星` 控制 AX 整体运行。关闭后，AX 不注册对话输入 capability、不注册 IA participant、不订阅 AX 所需事件，也不调用 LLM。重新启用需要刷新模块运行时。

### 3.2 怎么呼叫天枢

`天枢的呼叫名（可留空）` 是玩家希望用来叫起天枢助手的额外称呼，不是 AX 模块名，也不是 IA participant 的展示名。

AX common 的 `AXParticipantRegistrar` 会把该值同时写入：

- `DialogueClaimCondition.wakeWord`，作为 IA 强仲裁条件；
- `DialogueVoiceTriggerGroup.wakeWords`，由 IA 汇总进共享语音触发注册表。

IR 从共享注册表构建触发词索引，执行近似修复和命中，再把结果送回 IA 仲裁。因此 NeoForge 设置页只保存该值并刷新 AX 运行时，不直接向 IR 注册，也不建立第二条仲裁链路。

该字段允许留空。留空时 AX 不注册额外 wakeWord，不向共享语音触发注册表提供额外热词，也不会因为该称呼获得 IA wakeWord 强仲裁；AX 仍可以通过其他 IA 授权链路处理被明确分配给它的对话。

当前 participant 展示名仍由 AX common 定义为“辅星”，用于模块/参与方标识；玩家可见助手名仍是“天枢”。若未来允许修改展示名，需要单独设计展示名语义，不能复用呼叫名字字段。

### 3.3 回复朗读

`朗读天枢回复` 控制 AX 的聊天回复是否送入 TTS 队列。

关闭后，AX 仍会处理被仲裁到的对话请求，但不会要求 TTS 播放回复。AX 不在本页提供“显示文字”或“文字停留时间”，因为游戏内展示由映迹统一承接。

### 3.4 对话行为

- `允许思考模式对话`：只控制玩家可见 `CHAT` 请求的 `thinking`；默认关闭，用响应时间换取可选的回答质量。AX 后台记忆维护使用 `TASK` lane 和自身固定策略，不受该玩家设置影响。
- `玩家说话时打断辅星`：开启时，ASR 报告玩家开始说话后，AX 取消当前 CHAT 请求并停止当前 TTS；关闭时，AX 不执行这两项打断动作。

## 4. 默认值

| 设置 | 默认值 |
| --- | --- |
| 启用辅星 | 是 |
| 呼叫名字 | `天枢`，可留空 |
| 朗读天枢回复 | 是 |
| 允许思考模式对话 | 否 |
| 玩家说话时打断辅星 | 是 |

## 5. 持久化与生效

AX 设置归入天枢统一的 NeoForge 客户端配置 `config/tianshu-client.toml`，由 `ClientConfig.SPEC` 的 `[ax]` 分区声明和保存。AX 不再创建独立配置文件。

当前 `[ax]` 分区包含：

```toml
[ax]
enabled = true
wakeWord = ""
replySpeechEnabled = true
chatThinkingEnabled = false
interruptOnPlayerSpeech = true
```

生效策略：

- `enabled` 或 `wakeWord` 变化后刷新模块运行时，因为它们改变 capability/participant 注册关系；`wakeWord` 为空时不注册额外呼叫词。
- `replySpeechEnabled`、`chatThinkingEnabled` 和 `interruptOnPlayerSpeech` 由既有 AX 实例读取同一个配置对象，可直接对后续行为生效。
- 保存失败时不提交设置会话，也不触发运行时刷新；页面保留未保存草稿供玩家重试。

旧 AX 独立配置文件、自由文本 TTS 音色设置和旧页面伪状态区不再读取或保留兼容逻辑。AX 发起 TTS 时只携带 AX 固定的语音风格标识，具体音色资源仍由 TTS 模块解析和管理。

## 6. 给映迹的泛化需求

AX 不负责游戏画面范围内的展示，但可以向映迹提供可展示内容源。映迹后续可按统一 HUD/状态体系消费这些内容：

- AX 回复流：开始、片段、完成、失败，携带 sessionId、turnId、requestId、文本片段、完整文本和失败原因。
- AX 处理状态：已接收、检索记忆、思考、回应、中断、失败、记忆维护开始/完成/失败。
- 展示策略归映迹所有：是否展示、位置、层级、停留时间、动效、与其他模块状态的合并规则。
- AX 侧只保证事件语义稳定，不在 NeoForge AX 包内绘制 HUD，也不保存 HUD 专用配置。

## 7. 后续扩展边界

新增设置前应先确认其所有者：

- 影响 AX prompt、记忆、仲裁参与或输出策略的玩家选项，可进入本页。
- 模型加载、采样默认值和 context 规划属于 LLM，不进入 AX 页面。
- 音色、语音样本和 TTS 模型属于 TTS，不进入 AX 页面。
- HUD 通用布局、回复文字展示或 Presence 状态展示属于映迹，不进入 AX 页面。

仅当设置存在稳定玩家语义、明确默认值、真实运行时接入点和可验证行为时，才扩展配置 schema 与页面。
