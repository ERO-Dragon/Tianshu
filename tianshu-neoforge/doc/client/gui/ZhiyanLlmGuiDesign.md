# 【织言】大语言模型 GUI 设计书

## 1. 文档定位

本文档定义【织言】大语言模型模块在天枢设置 GUI 中的初版界面结构、展示信息、交互状态和实现边界。

后续制作【织言】相关 GUI 时，以本文档为默认设计基准。若实现中发现现有设置 GUI 模板无法直接承载某些图形化控件，应优先保持本文档的信息结构和交互语义，再决定是否扩展 renderer 或新增专用模板。

【织言】页面的核心目标不是展示完整 LLM 技术参数，而是让玩家方便完成以下操作：

1. 打开或关闭大语言模型模块。
2. 查看当前设备是否适合运行本地模型。
3. 从已下载模型中选择一个模型。
4. 加载或卸载模型。
5. 下载、取消下载或删除本地模型。

## 2. 模块命名

模块在左侧分类、右侧标题和语言文件中统一命名为：

```text
【织言】大语言模型
```

不使用“LLM”“大模型中心”“模型管理器”等其他标题替代。

模块 ID 仍建议沿用运行时稳定 ID：

```text
module.llm
```

显示名和内部 ID 分离，避免为 GUI 文案调整影响协议、能力或模块生命周期。

## 3. 页面整体结构

右侧页面只保留四个主要区块：

```text
启用状态
设备能力
模型加载设置
模型下载
```

页面顺序固定为：

1. 启用状态
2. 设备能力
3. 模型加载设置
4. 模型下载

其中“模型加载设置”整合模型选择、模型信息和加载控制，不再拆成多个独立大区块。

## 4. 启用状态区

### 4.1 展示内容

启用状态区只展示一行：

```text
启用状态：开 / 关
```

不展示额外说明文案，不展示长提示，不展示性能解释。

### 4.2 行为要求

当启用状态为“关”时：

- 不运行【织言】大语言模型模块。
- 不启动本地 LLM 服务。
- 不加载模型。
- 不产生 LLM 相关显存占用。
- 不产生 LLM 相关模型内存占用。
- 不接受模型加载操作。

当启用状态为“开”时：

- 允许选择已下载模型。
- 允许加载或卸载模型。
- 允许进行模型下载管理。

### 4.3 控件映射

在现有设置 GUI 框架中，启用状态可优先使用：

```text
panel.enable(...)
```

显示文案应为“启用状态”，控件值表现为“开 / 关”。

## 5. 设备能力区

设备能力区用于让玩家快速判断当前电脑适合运行多大规模的模型。该区域不作为完整硬件监控面板，不展示过多技术字段。

### 5.1 刷新频率

设备能力区的数据应每秒刷新一次。

刷新内容包括：

- 显卡型号。
- 显存占用分布。
- 内存占用分布。
- 推荐模型规模范围。

若页面不处于打开状态，不需要为 GUI 维持高频刷新。

### 5.2 展示字段

文字字段只展示：

```text
显卡型号：<GPU 名称>
```

其余设备数据通过图表展示。

### 5.3 图表形式

优先设计目标是环带状占用图，但初版实现可以使用分段进度条。

若使用分段进度条，应至少包含：

```text
显存条
内存条
```

每个条形图必须同时满足：

1. 使用不同颜色区分占用来源。
2. 用文字写明占用情况。
3. 能表达总量、游戏占用、LLM 占用和剩余可用。

### 5.4 显存条

显存条展示整张显卡显存的占用分布。

分段含义：

| 分段 | 含义 |
|---|---|
| 游戏已占用 | Minecraft / 游戏进程当前占用的显存。 |
| LLM 已占用 | 【织言】模型加载后额外占用的显存。 |
| 可用 | 当前可用于后续加载或系统调度的显存。 |

推荐显示格式：

```text
显存：游戏 2.1GB / 织言 3.8GB / 可用 2.1GB / 总计 8GB
```

条形图颜色建议：

| 分段 | 颜色语义 |
|---|---|
| 游戏已占用 | 蓝色或绿色。 |
| LLM 已占用 | 紫色或橙色。 |
| 可用 | 深灰或浅灰。 |

### 5.5 未加载 LLM 时的显存显示

当模型未加载时，不存在 LLM 相关显存占用。

此时显存条必须显示：

```text
织言 0GB
```

或等价的空分段。

不得把游戏占用、系统占用或其他进程占用错误归入 LLM 占用。

模型未加载时的示例：

```text
显存：游戏 2.1GB / 织言 0GB / 可用 5.9GB / 总计 8GB
```

### 5.6 内存条

内存条展示系统内存或当前可观测内存占用分布。

分段含义：

| 分段 | 含义 |
|---|---|
| 游戏已占用 | Minecraft / 游戏进程当前占用的内存。 |
| LLM 已占用 | 【织言】模型加载后额外占用的内存。 |
| 可用 | 当前系统可用内存。 |

推荐显示格式：

```text
内存：游戏 9.4GB / 织言 1.2GB / 可用 21.4GB / 总计 32GB
```

### 5.7 未加载 LLM 时的内存显示

当模型未加载时，不存在 LLM 相关模型内存占用。

此时内存条必须显示：

```text
织言 0GB
```

或等价的空分段。

不得把 Minecraft 基础内存、JVM 内存、系统占用或其他模块占用错误归入 LLM 占用。

模型未加载时的示例：

```text
内存：游戏 9.4GB / 织言 0GB / 可用 22.6GB / 总计 32GB
```

### 5.8 推荐模型规模

推荐模型规模暂时按范围展示，不做绝对承诺。

推荐显示格式：

```text
推荐模型规模：3B - 7B
```

建议初版范围：

| 可用显存 | 推荐模型规模 |
|---|---|
| 小于 4GB | 1B - 3B |
| 4GB - 8GB | 3B - 7B |
| 8GB - 12GB | 7B 左右 |
| 12GB - 16GB | 7B - 14B |
| 16GB 以上 | 14B 以上 |

推荐范围只作为下载和选择模型时的提示，不作为硬性限制。

## 6. 模型加载设置区

模型加载设置区整合以下能力：

1. 模型选择。
2. 模型信息展示。
3. 模型加载与卸载。
4. 加载状态显示。

区块标题固定为：

```text
模型加载设置
```

### 6.1 模型选择

模型选择控件只展示已下载模型。

推荐显示格式：

```text
当前模型：[Qwen3 4B v]
```

未下载模型不得出现在该下拉框中。

如果没有任何已下载模型，显示：

```text
当前模型：暂无可用模型
```

此时加载按钮禁用。

### 6.2 模型信息展示

模型信息只展示玩家需要理解的基础信息。

保留字段：

```text
模型名称
模型规模
模型大小
```

示例：

```text
模型名称：Qwen3 4B
模型规模：4B
模型大小：约 2.5GB
```

不得在该区展示：

- 上下文长度。
- 本地状态。
- repoId。
- HuggingFace 文件路径。
- 本地绝对路径。
- tokenizer 信息。
- RAG 参数。
- 请求参数。

上下文长度属于请求或推理配置，不属于玩家选择模型时必须关注的信息。模型选择下拉框只列已下载模型，因此本地状态也是冗余信息。

### 6.3 加载控制

加载控制并入“模型加载设置”区，不单独建立“运行控制”区。

只保留两个按钮：

```text
[加载] [卸载]
```

不提供“重新加载”按钮。

状态显示在按钮右侧或按钮下方：

```text
状态：未加载
```

### 6.5 加载状态

加载状态至少包含：

```text
已禁用
未选择模型
未加载
加载中
已加载
卸载中
加载失败
```

### 6.6 按钮启用规则

| 当前条件 | 加载按钮 | 卸载按钮 | 状态 |
|---|---|---|---|
| 模块关闭 | 禁用 | 禁用 | 已禁用 |
| 没有已下载模型 | 禁用 | 禁用 | 未选择模型 |
| 已选择模型且未加载 | 启用 | 禁用 | 未加载 |
| 加载中 | 禁用 | 禁用 | 加载中 |
| 已加载 | 禁用 | 启用 | 已加载 |
| 卸载中 | 禁用 | 禁用 | 卸载中 |
| 加载失败 | 启用 | 禁用 | 加载失败 |

失败时可显示一行短原因，例如：

```text
原因：显存不足
```

不得展示异常堆栈或底层调试日志。

## 7. 模型下载区

模型下载区用于让玩家查找、下载、取消下载、删除本地模型。

该区借鉴 ASR/TTS 设置页的下载区结构，但信息更克制，避免变成完整技术目录。

### 7.1 展开方式

模型下载区默认可以折叠。

推荐显示：

```text
模型下载：展开 / 收起
```

展开后展示筛选项、模型列表、下载操作和下载状态。

### 7.2 筛选项

推荐筛选项：

```text
推荐范围
模型规模
下载状态
```

初版可包含：

| 筛选 | 选项 |
|---|---|
| 推荐范围 | 全部 / 推荐 |
| 模型规模 | 全部 / 小型 / 中型 / 大型 |
| 下载状态 | 全部 / 已下载 / 未下载 |

筛选项应服务于玩家快速找到适合自己设备的模型，不展示过多模型技术分类。

### 7.3 模型列表

模型列表每项只展示轻量信息：

```text
模型名称
模型规模
模型大小
推荐配置或推荐范围
```

示例：

```text
Qwen3 4B · 4B · 约 2.5GB · 推荐 6GB 以上显存
```

不展示：

- repoId。
- hfFilePath。
- modelFile。
- 本地绝对路径。
- 上下文长度。

### 7.4 下载操作

选中模型后，根据状态展示操作按钮。

| 模型状态 | 操作 |
|---|---|
| 未下载 | 下载 |
| 下载中 | 取消下载 |
| 已下载 | 删除 |
| 下载失败 | 下载 |

是否提供“重新下载”由后续实现决定。初版可先不展示，避免误操作。

### 7.5 下载状态

下载状态展示为短文本：

```text
状态：空闲
状态：下载中 43%
状态：下载完成
状态：下载失败
```

下载失败时可展示短原因，但不展示堆栈。

示例：

```text
状态：下载失败
原因：网络连接失败
```

## 9. 与现有设置 GUI 框架的映射

| 页面区块 | 优先模板 | 说明 |
|---|---|---|
| 启用状态 | `enable` | 显示开 / 关。 |
| 设备能力文字状态 | `status` | 显卡型号、推荐模型规模可先用状态行。 |
| 设备能力图形条 | renderer 扩展或专用模板 | 现有模板不一定支持分段进度条，初版可先降级为状态文本。 |
| 模型选择 | `options.select` | 只列已下载模型。 |
| 模型信息 | `status` | 只展示名称、规模、大小。 |
| 加载 / 卸载 | `actions` | 根据加载状态控制按钮 enabled。 |
| 模型下载展开 | `enable` | 借鉴 ASR/TTS 的展开开关。 |
| 下载筛选 | `options.select` | 推荐范围、模型规模、下载状态。 |
| 下载列表 | `list` | 借鉴 ASR/TTS 的模型下载列表。 |
| 下载操作 | `itemActions` 或 `actions` | 按模型状态显示下载、取消、删除。 |
| 下载状态 | `status` | 显示空闲、下载中、完成、失败。 |

## 10. 实现边界

### 10.1 GUI 不直接暴露推理 offload 参数

当前运行策略固定为全 GPU 推理，GUI 不提供 CPU / GPU layer / `ngl` 调整入口。

历史配置中的 offload 百分比字段可作为兼容和未来扩展保留，但不进入初版主界面。

### 10.2 GUI 不直接展示技术路径

玩家界面不展示 repoId、模型文件路径、本地绝对路径等技术字段。

这些信息可保留在内部诊断、日志或未来高级折叠面板中，但不得进入初版主界面。

### 10.3 未加载模型时 LLM 占用必须为零

设备能力区必须区分游戏占用和【织言】占用。

模型未加载时：

```text
织言显存占用 = 0
织言内存占用 = 0
```

加载成功后，才允许显示 LLM 相关占用。

### 10.4 下载区参考 ASR/TTS，但不复制全部复杂度

ASR/TTS 已有下载展开、筛选、列表、进度、状态的实现模式。

【织言】应借鉴该结构，但字段更少，避免把模型仓库的技术信息完整暴露给玩家。

### 10.5 状态控制优先于按钮数量

【织言】加载设置只提供“加载”和“卸载”。

不提供“重新加载”。

若需要重新加载，用户先卸载再加载，状态机更清晰，也能避免重复提交加载任务。

## 11. 初版实现建议

初版可以分两阶段实现。

### 11.1 阶段一：模板可用版

使用现有模板完成主要信息和操作：

- 启用状态。
- 显卡型号。
- 推荐模型规模。
- 显存 / 内存占用文字。
- 已下载模型下拉框。
- 模型名称 / 规模 / 大小。
- 加载 / 卸载按钮。
- 模型下载展开、筛选、列表和状态。

此阶段设备能力图形条可先用文字状态替代。

### 11.2 阶段二：图形增强版

在 renderer 层补充分段进度条或环带图。

增强目标：

- 显存分段条。
- 内存分段条。
- 每秒刷新。
- 游戏占用、织言占用、可用资源以不同颜色显示。

若实现环带图成本较高，分段进度条作为长期默认实现也是可接受方案。

## 13. 设计原则总结

【织言】大语言模型 GUI 初版遵循以下原则：

1. 命名统一：显示名固定为【织言】大语言模型。
2. 信息克制：只展示玩家真正需要知道的内容。
3. 图形优先：设备占用优先用图形条表达，并配合文字数值。
4. 状态明确：加载和卸载按钮必须严格受状态机控制。
5. 隐藏推理 offload 技术细节：当前固定全 GPU，GUI 不暴露 CPU / GPU layer 调整。
6. 下载友好：下载区借鉴 ASR/TTS，但字段更少、更面向玩家。
7. 未加载即零占用：未加载 LLM 时，设备能力区不得显示 LLM 相关占用。
