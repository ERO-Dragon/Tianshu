0. 🛡️ 零信任安全基座与静默监听协议（已完成）
{
    痛点：多人服务器对数据读取极度敏感，传统 Mod 主动发包握手易触发反作弊；开发者容易陷入单机/多人的逻辑分支陷阱导致代码臃肿。
    功能描述：整个 Mod 的底层安全宪法。采用“客户端绝对静默 + 服务端单向发令”的统一架构，实现单机与多人的零代码分支管控。

    技术实现：

    客户端物理熔断（受控白名单发言原则）：
    默认状态下，客户端绝不主动发送任何自定义网络包（不发探测包、不发握手包），表现得与原版完全无异。
    所有高级功能的权限开关在内存中默认硬编码为 false（瘫痪态）。
    【唯一例外 - 物品变更请求】：
    仅当涉及真实的物理背包变动（如功能2的换装、功能8的清理），且经过本地安全校验后，客户端才允许发出特定用途的 C2S 意图包（如 C2SRequestSwapPreset）。
    【防患未然】：
    若当前连接的服务端未安装本 Mod（未下发 S2C 权限包），客户端底层会直接拦截上述 C2S 意图包的发送，并在本地进行降级提示，绝不向无 Mod 的服务端乱发废包。
    服务端统一发令（唯一信源）：
    权限的判断逻辑100% 交由服务端执行。Mod 的服务端逻辑层统一读取 tianshu-server.toml 配置文件：
    如果是原版服务器（没装 Mod） ➡️ 无法读取配置，无动作。
    如果是装了 Mod 的服务器，但配置写了 false ➡️ 无动作。
    如果配置写了 true ➡️ 向该玩家下发 S2C 授权包（如 RadarAllowedPacket(true)）。
    单边静默解锁（零分支闭环）：
    客户端仅作为纯粹的 S2C 监听器。没收到包就是 false（瘫痪），收到包就切为 true（激活）。
    单机模式的优雅自洽：单人游戏时，本地自带的 IntegratedServer 同样会加载 tianshu-server.toml，因为该配置默认值为 true，所以本地服务端会自动向本地客户端下发许可包。全程无需任何 if (isSingleplayer) 判断，单机与联机走完全相同的代码路径。
}

1. 🌐 准星智能扫描与全息 MR 系统（制作中）
{
    痛点：遇到不认识的模组方块/生物需要切出去查Wiki；战斗中无法快速获取怪物面板信息（如攻防、距离），打断心流。
    功能描述：本系统采用“状态机”管理，分为绝对静默、全息 MR 扫描、全息 MR 深度解析三个层级，坚决贯彻“不打扰是最高修养”的原则。

    第一层：全息 MR 系统（呼之即来，挥之即去）
    默认处于静默状态，无任何 UI 污染。
    玩家通过语音指令（如“打开扫描”、“战术目镜”）瞬间唤出，在屏幕内为范围32格内的最多 10 个实体生成投影式 2D 牵引卡片。
    卡片遵循近大远小伪 3D 原则；采用绿/橙二分色法则（绿色代表无仇恨/中立，橙色代表敌对）；被物理遮挡的实体卡片直接隐没（非透视），优先展示最近的敌对单位。
    卡片内仅显示极简战术数据：实体头像图标、名称、血量条、距离数值、攻击力(剑)与防御力(盾)图标。
    可通过语音指令（如“关闭扫描”）或设定超时时间后自动挥之即去。
    第二层：深度解析（无声的默契与主动询问）
    默契触发（悬停）：当玩家准星持续悬停在某个实体或方块上超过设定时间（如 3 秒），系统判定玩家产生疑惑，自动进入解析状态。
    指令触发：玩家注视目标时直接语音提问（如“这是啥”、“分析一下这个”），。
    *实体表现*：该实体的战术卡片瞬间放大并锁定至屏幕上方显眼位置，并展开生成的深度解析文本气泡（如特殊机制、持有药水）。
    *方块表现*：在准星旁瞬间弹出一个切角矩形全息框（确立全局赛博朋克科技风），内含方块名及解析（如红石状态、NBT 特性）。
    *AI辅助*：当LLM启用时，系统会自动调用大模型，根据目标信息生成深度解析文本，替换默认解析。
    技术实现：
    状态管理：构建严格的 HUD 状态机（SILENT -> SCANNING -> FOCUSING），防止状态混乱。
    渲染管线：严禁使用 OpenGL 3D 世界坐标渲染。必须使用 MC Camera 投影矩阵将 3D 拍平为 2D，统一在 RenderGuiOverlayEvent（纯 GUI 层）绘制切角矩形与图标，确保与所有光影包 100% 兼容。
    悬停计时器：在 ClientTickEvent 中记录准星命中目标的 Tick 差值，达到阈值自动抛出解析事件。
    数据隔离：全息 MR 系统所需的轻量级数据由本地 Provider 毫秒级读取，严禁发送给大模型。仅当进入“深度解析”状态且启用了LLM时，才将 BlockState/NBT等精简后的信息打包发给 LLM。
}

2. 🗣️ 基于智能降级的语音装备中枢
{
    痛点：战斗或跑酷中切换装备手忙脚乱；整合包物品繁多，理想套装部件缺失时无法灵活应对；背包满时换装卡死。
    功能描述：实现“宏观套装一键切换”与“微观快捷栏调度”，引入独特的智能降级机制与垃圾回收机制，确保玩家在任何极端状态下都能瞬间完成换装。
    宏观切换（套装模式）：语音输入“切换战斗套”，系统根据预设瞬间完成替换。
    微观调度（单槽模式）：语音输入“拿盾牌”，系统仅在快捷栏 1-9 寻找匹配物品并与手持物交换。
    极简预设录入：穿戴好目标配置后，语音“保存当前为战斗套”，直接将当前状态拍快照。
    技术实现：

    预设存储（期望结构体）：预设不存死板的 NBT，而是存“期望标准”。例如：{slot: chest, baseId: "diamond_chestplate", expectedEnchants: ["Protection IV"]}。保存的是“理想”，穿戴时做“妥协”。
    智能降级匹配算法：
    当触发套装切换时，遍历背包寻找满足该槽位的物品，按优先级排序：1. 完全匹配（ID 与附魔一致） -> 2. 同 ID 降级（附魔缺失） -> 3. 材质降级（如钻石退化为铁）。
    空间回退算法（垃圾回收）：
    针对背包已满的情况：1. 优先寻找背包内同类装备进行跨槽位 Swap。2. 若无同类装备，直接调用【功能 10】的“垃圾物品表”，丢弃第一件垃圾腾出空间，完成换装。
    严谨的 C/S 申请机制（核心突破）：
    彻底抛弃任何“模拟原版点击/模拟按Q”的降级妥协方案。坚决不绕过服务端，不伪装发包。
    客户端仅作为“纯意图收集器”，无论宏观套装切换还是微观单槽交换，一律发送自定义的 C2SRequestSwapPreset 包（内含预设 ID 或目标物品槽位映射表）：

    若服务端安装本 Mod 且开启功能： 服务端接管，在服务端执行上述的【降级匹配】与【垃圾回收】逻辑，直接调用 player.getInventory() API 修改服务端真实背包，再同步给客户端。(服主可通过配置彻底关闭此功能防作弊)。
    若服务端未安装本 Mod（或关闭功能）： 服务端丢弃该包。客户端检测到无 S2C 授权，在本地直接拦截语音指令，自动降级提示玩家“当前服务器不支持换装操作”。
    单人档/局域网： 等同于“服务端安装了 Mod”，直接走内部高速通道执行。
    指令路由：100% 本地 Ngram 拦截执行，严禁发送大模型，确保毫秒级响应。
    AI 反馈示例：

    *(单人/模组服完美切换)*：“战斗套已就绪。”
    *(单人/模组服触发降级)*：“战斗套已切换，未找到附魔钻甲，已临时装备铁甲。”
    *(单人/模组服触发垃圾回收)*：“背包已满，已为你丢弃泥土腾出空间，战斗套切换完成。”
    *(原版服务器)*：“当前服务器不支持套装切换。”
    设计亮点解读：

    真正的白名单逻辑：把“防作弊”变成了“权限管理”。服主拥有绝对控制权（配置文件开关），玩家在原版服务器不会因为乱发包被踢，而是会被模组温柔地告知“不支持”，体验极度平滑。
    算力下沉：把最核心、最容易出 Bug 的“降级匹配”和“丢垃圾”逻辑放在了服务端执行，这意味着就算玩家本地开修改器乱发请求包，服务端也会按照正常逻辑校验，杜绝了任何刷物品的可能。

4. 🧪 主从式悬浮合成面板（制作中）
{
    痛点：整合包配方方式繁杂（工作台、熔炉、各类模组机器）；同类机器下仍有多种配方冲突；深层查阅时子面板容易迷失归属关系。
    功能描述：一个高信息密度的专业级合成查阅台。采用左侧分类导航、右侧焦点展示的主从布局，通过“空间缩进与发光连接线”解决深层级面板的归属迷航。

    技术实现：

    状态机与自由布局：游离态（移动时）低透明度防穿透；沉浸态（开背包时）高亮激活交互。支持拖拽标题栏自定义位置并本地持久化。
    左侧纵向分类器（解决多方式冲突）：
    当检测到目标物品有多种合成方式时，面板左侧出现一个窄条，纵向排列所有合成类型（如“工作台”、“熔炉”、“动力搅拌机”、“农夫烹饪锅”），附带对应机器小图标。点击即可切换右侧的主视图。
    右侧焦点视图与左右翻页（解决同方式多配方）：
    右侧区域同一时间只展示一种配方。若当前分类下仍有多种配方（如工作台有3种排列），在配方网格下方提供极简的 < 1/3 > 切角翻页按钮。
    智能定锚：每次打开面板或切换分类时，底层算法自动比对背包，将“材料满足率最高”的那一页直接置顶展示。
    底色状态法（极简两色）：
    全局坚持极简色彩规范。材料图标下层只使用两种底色：背包已有为“暗绿切角”，缺失为“暗橙切角”。无论面板嵌套多深，这两种颜色代表的意义绝对不变，形成视觉本能。
    空间缩进与发光连线（解决子面板归属感，核心 UX）：
    当玩家点击缺失材料（如“小麦”）展开子集面板时：
    绝不改变子面板底色，子面板依然保持统一的磨砂黑底。
    空间位移：子面板在主面板的右侧（或下方）纵向展开，并在水平方向上向右缩进一段距离。
    发光连接线（神来之笔）：从主面板被点击的“小麦”格子边缘，拉出一条 1px 的、带有微弱科技蓝发光的切角折线，精准连接到弹出的子面板边缘。
    *视觉效果*：就像电路板的分支一样。玩家一眼就能通过这条线，知道这个子面板是属于哪个材料的。再点“种子”，再拉一条分支线。层级再深也不乱，因为底色永远是干净的黑白绿橙，只有细线在勾勒逻辑。
    精准生命周期：点击“×”沿连接线收回子面板；语音支持“关掉小麦的配方”精准销毁节点，“收起面板”一键剪断所有连线清空。
    AI 反馈示例：

    *(多方式切换)*：“已切换到动力搅拌机的配方，这是材料凑得最齐的一种。”
    *(翻页提示)*：“工作台还有另外 2 种合成方式，点击下方箭头查看。”
    *(深层跳转)*：“已为你拉出小麦的合成分支，注意看连接线。”
}

5. 🔬 战术空间战术雷达（已完成）
{
    【核心设计哲学：绝对客观的双轨状态机】
    雷达的最高境界是“不替玩家做判断”。废除一切模糊的“严重度×置信度”猜测与动能积分预测。系统转为绝对客观的物理与状态事实汇报机制。采用“UI指向轨”与“语音警报轨”双线并行，通过严苛的“存在集”与“视线冗余剔除”，确保雷达的每一次发声都绝对准确，绝不引发信息焦虑。

    【工程红线：零 GC 快照机制】
    *绝对禁止全量重建方块数组。* 采用 Chunk Slice 增量更新 + Dirty Region：预分配固定环形缓冲区，仅当玩家坐标变化超 2 格时，在主线程拉取新进入感知区的边缘方块进行局部覆写。异步线程的视线检测（RayTrace）与距离计算全基于此只读缓冲区，实现零内存分配。
    算力归属： 本功能涉及视线穿透判定。为防止拖垮服务端 TPS，所有重度计算逻辑100% 沉降于客户端异步线程执行。系统仅读取客户端本地已缓存的区块与实体数据，计算结果直接驱动本地 UI 与声卡播报，全程不向服务端发送任何数据包。

    技术实现（异步漏斗引擎）：

    第一级：空间与敌意粗筛 O(N)
    剔除 非敌对生物、已死亡实体。提取实体绝对坐标，计算与玩家的欧几里得距离，分发至 16 格与 8 格处理管线。

    第二级：16格 UI 指向轨（二级逻辑）
    对进入 16 格的敌对实体，提取其相对方位角，驱动屏幕边缘的圆环指向标。
    **去重与防抖护栏**：同类实体仅维持一个指向标，锚定最新进入者。显示 3 秒后自动隐藏。当实体出界（>16格）时，启动 20 Tick（1秒）防抖计时器，期间若反复横跳不重置资格，坚持 1 秒后才释放该类别的指向标槽位。

    第三级：8格 存在集感知轨（三级逻辑）
    对进入 8 格的实体，维护一个 `Set<EntityType> level3PresenceSet`。
    **存在集规则**：异步线程每 tick 汇总 8 格内实体类型集合。若某类型不在 Set 中，推入播报队列并加入 Set；若已存在，直接吞掉。当 8 格内彻底查无此类型时，立刻从 Set 中摘除以重置许可。
    **【红线】**：此层拥有绝对独立性，不受下方第四级战斗状态任何干扰，无 CD 概念，纯靠集合进出状态控制。

    第四级：视线截断与行为锁定裁决（四级逻辑）
    提取 8 格内实体的 `isAttacking()` 状态（如骷髅拉弓、苦力怕嘶嘶），并结合异步 RayTrace 进行视线判定。
    **触发铁律**：必须同时满足 `有锁定动作` + `!hasLineOfSight(视线受阻)`。
    **高危总动员播报**：一旦触发，无视视线条件，强行盘点整个 8 格内所有敌对生物的绝对总量，生成精确播报：“警告，已被锁定，警戒范围内共有：X只A，Y只B”。
    **独立警戒状态机**：
    - 维护 `boolean isInAlertState` 与 `int alertCooldownTimer`。
    - 非警戒状态下触发，立刻置位 `true` 并播报。
    - 警戒状态下，无论有多少怪拉弓，**永久静默**。
    - **脱战衰减**：每 tick 扫描 8 格内是否还有任何锁定动作。若无，计时器 `+1`；若有，计时器立刻清零。当计时器达到 60 Tick（3秒），才解除 `isInAlertState = false`。

7. 🛑 关键链路熔断预警系统
{
    痛点：传统的 10% 固定耐久预警极其智障——低频挖矿时疯狂打扰玩家，高频战斗（如拔刀剑模组、末地极速刷怪）时又根本来不及反应，导致关键武器碎掉或挖坏稀有矿石。
    功能描述：引入工业级的“预测性维护”概念。不再死守固定百分比，而是根据玩家当前的“消耗斜率”动态计算剩余寿命，结合高风险动作识别，在武器失效前进行“熔断干预”，并直接给出备选方案。

    技术实现：

    预测性消耗计算：
    维护一个 30 秒的环形缓冲区，每秒记录一次主手物品的耐久度。计算衰减斜率：消耗速率 = (30秒前耐久 - 当前耐久) / 30。
    将斜率转化为预计可用秒数 (TTL)。例如：耐久还剩 50，但每秒掉 10，TTL 就是 5 秒。
    动态熔断触发器（拒绝无效打扰）：
    绝对熔断：无论什么情况，只要 TTL < 5秒，瞬间触发最高级干预。
    情境熔断：当耐久低于 20%，且检测到玩家正在进行“高风险动作”（如正在挖掘钻石/深板岩等高价值方块，或正在受击状态），直接熔断。
    静默延迟：如果耐久低于 5%，但 TTL > 60秒（比如在闲逛挖泥土），不播报，等玩家停下来或者打开背包时再说。
    极简背包扫描（Solution-Oriented 核心）：
    在触发熔断的同一帧，瞬间遍历玩家快捷栏（Hotbar 0-8）和主背包前两排。寻找同类或更高级的替代品（例如：钻石镐碎了，找铁镐或备用钻石镐；弓没箭了，找弩或弩箭）。
    AI 反馈示例（流式打字，但极短）：
    AI 不报干瘪的数字，只报“后果”和“退路”。

    场景 A（高频 PVP 刷怪，TTL 极短，有备选）：
    *(急促打断)* “立刻切换！你的剑还有不到 3 秒就碎了！按 2 换铁剑！”
    场景 B（低频挖矿，即将挖到稀有矿，无备选）：
    *(警告)* “停下！镐子快碎了，背包里没有备用，别挖这块钻石了。”
    场景 C（弓箭手弹药枯竭，有备选）：
    *(提醒)* “箭矢耗尽，按 3 切换弩继续打！”
    场景 D（闲逛挖泥土，TTL 很长，无备选）：
    *(极其平淡，不占用听觉通道)* “*(仅在打开背包时在 UI 角落弹一行小字：主手武器耐久较低，记得修补)*”
