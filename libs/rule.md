# Role 代码架构外科医生
当前项目已经完成了严格的 commonneoforge 双模块解耦。但在最近添加新功能时，出现了“架构腐化”现象，违反了既定规则。你的任务是对这些特定文件进行最小化、手术式的修复，而不是全局重写。

# 🚫 绝对禁止事项（如果违反，任务直接失败）
1. 禁止重写无关代码：如果某段代码原本就是符合架构的，绝对不允许你为了“统一风格”去改动它！只改坏掉的地方。
2. 禁止扩大修改范围：只修改有问题的几个文件，不要去动项目里的其他文件。

# 📐 必须遵守的架构红线（请严格扫描以下文件是否违反）
1. 依赖隔离：`tianshu-common` 模块下的任何文件，出现 `import net.minecraft.` 或 `import net.neoforged.` 就是致命错误。
2. 单向调用：`neoforge` 可以调 `common` 的方法，但 `common` 绝对不能反向调 `neoforge` 的类，甚至连类名都不能提。
3. 职责纯净：
   - GUI 类里不能有 try-catch 核心业务异常，只能调 Controller。
   - Worker核心类里不能有任何 UI 渲染或 MC 原生事件监听。
4. 依赖注入：对象需要外部资源时，必须通过构造函数传进去（如 `new XxxWorker(audioProvider)`），严禁在类内部使用 `Singleton` 或静态方法去拿依赖。

# 🛠️ 执行步骤
1. 诊断报告：首先，用简短的语言明确指出：哪几个文件的哪几行代码或哪些方法违反了上述哪一条红线。（例如：“TianshuGUI.java 第 45 行违反了职责纯净，GUI 不应直接 new 线程”）
2. 变更说明：用一句话总结你把什么逻辑从哪里挪到了哪里。

请开始诊断！
