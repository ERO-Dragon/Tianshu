# AX 辅星本地小模型实时对话提示词长度调查

## 背景

本调查面向 AX 辅星在本地 LLM 环境下进行“模拟真人对话”的提示词与上下文长度设计，重点考虑 GGUF 格式、Q4_K_M 量化、2B / 4B / 9B / 12B 级别模型。

这里的“真人对话”特指低延迟、轮次清晰、自然接话、少旁白、少长篇叙事的交互方式；它不同于酒馆式长角色卡、小说续写或剧情旁白系统。

## 核心结论

GGUF 和 Q4_K_M 不直接决定模型可输入的提示词长度。它们主要影响模型权重体积、推理速度和部署成本。真正限制提示词长度与上下文长度的是以下因素：

- 模型自身训练时支持的最大 context length。
- 运行时配置的上下文窗口，例如 llama.cpp / Ollama 中的 ctx-size、num_ctx 等。
- KV cache 占用的显存或内存。
- 模型规模对长提示词的遵循能力。
- 实时语音或实时对话场景对首 token 延迟的要求。

因此，AX 辅星不应简单地因为模型标称支持 8K、16K、32K context 就把系统提示词写到很长。对话系统更应优先保证短响应、低延迟、人格一致性和轮次感。

## 建议长度

### 静态提示词

静态提示词指系统规则、人格设定、说话风格、行为边界、少量关系背景与输出格式约束。

| 模型规模 | 建议静态提示词长度 | 说明 |
| --- | ---: | --- |
| 2B Q4_K_M | 200-500 tokens | 只适合轻量闲聊，规则必须非常短 |
| 4B Q4_K_M | 400-900 tokens | 可承载基础人格、口吻和少量短记忆 |
| 9B Q4_K_M | 800-1,800 tokens | 较适合稳定人格和自然对话 |
| 12B Q4_K_M | 1,000-2,500 tokens | 可承载更完整的人格、情绪和关系背景 |

### 总输入上下文

总输入上下文指静态提示词、用户当前输入、最近对话历史、摘要记忆、运行状态与工具结果的合计。

| 模型规模 | 建议总输入上下文 | 说明 |
| --- | ---: | --- |
| 2B Q4_K_M | 1K-2K tokens | 超过后容易不稳定或响应变慢 |
| 4B Q4_K_M | 2K-4K tokens | 适合短历史 + 简短记忆摘要 |
| 9B Q4_K_M | 4K-8K tokens | 比较适合常规真人感对话 |
| 12B Q4_K_M | 6K-12K tokens | 可支持较长关系上下文，但仍需控制延迟 |

### 实时语音对话

如果 AX 辅星需要接入实时语音，建议进一步收紧上下文：

| 模型规模 | 实时语音总上下文建议 |
| --- | ---: |
| 2B Q4_K_M | 512-1,500 tokens |
| 4B Q4_K_M | 1K-3K tokens |
| 9B Q4_K_M | 2K-6K tokens |
| 12B Q4_K_M | 3K-8K tokens |

语音对话对首 token 延迟更敏感。相比完整设定，实时语音更需要短句、快速接话、少解释和明确的上下文压缩策略。

## 对 AX 辅星的设计启发

AX 辅星不宜把“人格、世界观、长期记忆、技能规则、最近对话”全部堆入一个超长 prompt。更稳的结构是：

- 短系统规则：限制输出风格、轮次行为、禁止旁白化。
- 稳定人格摘要：只保留影响当前对话风格的核心设定。
- 最近对话窗口：保留最能影响当前回复的若干轮。
- 长期记忆摘要：使用压缩后的事实、偏好、关系状态。
- 技能上下文：只在技能被触发或候选时注入。
- 状态上下文：只注入当前任务真正需要的运行状态。

推荐默认配置：

| 模型规模 | 静态 prompt | 最近历史 | 摘要记忆 |
| --- | ---: | ---: | ---: |
| 2B | 约 300 tokens | 约 800 tokens | 约 200 tokens |
| 4B | 约 700 tokens | 约 2K tokens | 约 300 tokens |
| 9B | 约 1.2K tokens | 约 4K tokens | 约 500 tokens |
| 12B | 约 1.8K tokens | 约 6K tokens | 约 800 tokens |

## 风险点

### 小模型长提示词风险

2B / 4B 模型即使运行时允许较大上下文，也不代表能够稳定遵循长提示词。长设定可能导致：

- 忽略用户当前输入。
- 回复变成解释设定。
- 输出像小说旁白而非对话。
- 重复系统规则中的措辞。
- 首 token 延迟和整轮响应时间上升。

### 酒馆式角色卡迁移风险

酒馆式角色卡常包含大量人物背景、场景描写、行为描写和叙事约束。直接迁移到真人对话系统时，容易让模型输出“讲故事式文本”。AX 辅星如果追求自然实时对话，应将角色卡改写为更短的对话行为规则。

### 盲目扩大上下文风险

长上下文会增加 KV cache 占用，并提升每轮处理成本。对于实时交互，超长上下文带来的记忆收益经常低于延迟和稳定性损失。

## 建议结论

AX 辅星在本地小模型路线中，应把提示词设计从“长人设 + 全量历史”调整为“短规则 + 最近窗口 + 摘要记忆 + 按需技能注入”。

如果目标模型覆盖 2B、4B、9B、12B 四档，建议将 prompt 编排设计为可分层降级：

- 2B：极简人格和极短历史，重点保证能接话。
- 4B：基础人格、短历史、少量摘要记忆。
- 9B：完整自然对话人格、较长历史、稳定摘要记忆。
- 12B：增强人格一致性、关系状态和多轮任务能力。

整体上，真人感对话的静态提示词建议控制在 2.5K tokens 以内；常规总上下文建议优先落在 4K-8K tokens 区间。只有在 12B 以上模型、硬件余量充足、且确实需要更长记忆时，才考虑更高上下文。
